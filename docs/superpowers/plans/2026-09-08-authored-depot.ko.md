## 방향

첫 접수실을 실제로 일하던 공간처럼 구성한다. 가구를 똑같이 복제하거나 소품을 무작위로 뿌리지 않는다. 접수, 포장, 기록 보관이라는 작업 흐름에 따라 모양과 물건을 다르게 만든다. 사용 흔적은 손이 닿는 모서리·작업면에만 둔다. 목표는 제작자의 선택이 보이는 일관성과 완성도이며 제작 주체에 대한 오인을 보장하는 것은 아니다.

## 구현

- [x] 재사용 가능한 모서리 깎기 메시를 구현하고 크기·표면 방향·닫힌 형상을 검사한다. 가구·상자·직원 소품에 적용하며 기존 충돌 크기는 유지한다. Godot에서 Dimensions·Color와 새 Edge Bevel을 편집할 수 있게 한다.
- [x] 접수실의 대형 사장 장식을 작은 사내 액자로 바꾸고 접수대, 포장 작업대, 기록 보관 구역을 개별 구성한다. 작업면에 송장, 테이프, 도장, 저울을 배치하고 진열 매트를 적재 위치 표시로 바꾼다. 방 안의 시계와 안내판을 실제 벽에 붙인다. 같은 가구의 다른 구역도 역할별로 구분한다.
- [x] 운반 중 직원 몸과 손이 상자 방향을 따라가도록 조정한다. 들기·내려놓기 자세를 짧게 연결한다. 위험이 없는 상자의 상시 이름표는 줄이고 위험 예고는 보존한다. 배송 완료음은 짧은 도장·기계음으로 구별한다.
- [x] 기존 통로, 창구 릴레이, 화물 동작, 온라인을 검증하고 실제 한영 화면과 운반 자세를 확인한다. Windows 빌드와 패키지를 갱신하고 로컬 `v0.7.8`을 저장한다.

## 범위와 기준

맵 크기·시작점·배송구·쥐 활동 구역·물리·온라인 프로토콜은 유지한다. 새 배치는 저장된 맵에서 직접 편집한다. 장식은 통로를 막는 새 충돌체를 추가하지 않는다. 반복 소품을 개별화하되 멀리서 작은 소품이 화면을 채우지 않도록 표시 거리를 제한한다. 새 기능이나 추가 구역 수보다 첫 화면, 모서리에서의 이동, 상자 운반의 일관성을 우선한다.

## 검증 결과

- 전체 검사 통과: 동작 검사 27개, 2인 온라인 시나리오 8개, 4인 온라인 시나리오 1개. 온라인 검사는 이 PC의 여러 프로세스로 실행했으며 외부 네트워크 검증은 아니다.
- 모서리 메시의 크기·표면 방향·닫힌 형상과 에디터 크기·색·충돌 동기화 통과. 첫 검사는 구현 전 실패를 확인한 뒤 구현 후 통과했다.
- 운반 방향·자세 연결·재채기 예고 표시와 배송 완료음의 길이·음량 범위 통과. 사운드는 파형 검사이며 청취 평가를 대신하지 않는다.
- 한영 화면, 작업대, 운반 자세를 실제 렌더로 확인했다. 마지막 진열 매트 정리 후 통로 검사와 화면 캡처를 다시 통과했다.
- Windows 내보내기와 패키지 실행 통과. 패키지 안 런타임 스크립트 29개 및 저장 맵 지문 확인 통과. 한영 안내, 라이선스 고지와 SHA256 목록을 ZIP에 포함했다.
- 독립 코드 검토에서 추가 결함이 보고되지 않았다. 실제 친구 그룹의 재미, 장시간 플레이와 대상 PC의 성능은 미검증이다.
