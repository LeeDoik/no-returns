## 설계

접수실, 양쪽 굽은 길, 중앙 분류장, 배송구에 의도적으로 묶음을 배치한다. 서로 무관한 랜덤 함정이나 수십 개의 물리 파편 대신, 알아보기 쉬운 세 가지 반응을 재사용한다. 기존 운반 경로의 여유 공간과 걸어서 우회할 선택을 유지한다. 점수 피해나 필수 상자 종류는 없다. 같은 버전의 연결된 분류 라인을 보완한다.

- **POP / 부풀린 포장 에어캡:** 밟거나 때리면 잠시 눌렸다 터진다. 가까운 직원과 바닥의 화물을 위와 바깥쪽으로 조금 민다. 8초 뒤 다시 부푼다.
- **UP / 반송 스프링:** 발판에 진입한 직원과 내려놓은 화물을 위쪽과 발판이 향한 쪽으로 조금 발사한다. 3초 뒤 재사용할 수 있지만 가만히 올라서 있으면 반복 작동하지 않는다. 선택 가능한 인계 보조 장치로 배치한다.
- **TILT / 빈 상자 탑:** 움직이는 직원, 던진 화물, 재채기에 맞으면 쓰러진다. 가까운 탑과 에어캡이 짧은 간격으로 반응해 연쇄 사고를 만든다. 10초 뒤 다시 선다. 쓰러지는 상자는 움직임이 제한된 시각 소품이며, 끝없이 쌓이는 네트워크 물리 파편이 아니다.

구별되는 실루엣, 발사 전 압축, 제한된 파편 움직임과 현장 소리로 원인과 결과를 전달한다. 벽과 높이를 고려한다. 들고 있거나 배송·복구 중이거나 쥐가 잡은 화물은 별도로 작동시키거나 밀지 않는다. 발판에 오른 직원은 들고 있는 화물을 유지한다. 호스트만 효과를 계산하고 참가자는 상태·남은 시간·사건 번호를 받는다. 재시작과 계약 변경 때 초기화하며, 호환되지 않는 통신 버전을 거부하고 중복 상태로 소리를 다시 재생하지 않는다.

## 추가 요청: 문서에 재채기

바닥 소품 24개와 별개로 기존에 보이는 문서·서식 13곳을 Paper stack 소품으로 바꾼다. 재채기 방향으로 종이 18장이 처음 0.14초 동안 한 뭉치로 날아가고, 이후 풀려 흩날리며 고정 벽·책상·바닥에 시각적으로 부딪힌 뒤 8초에 복구된다. 다른 진입·연쇄 반응은 문서를 작동시키지 않는다. 매번 같은 노드를 재사용한다. 종이는 점수나 화물 밀림을 만들지 않는다.

상태·남은 시간·사건 번호·방향은 압축한 실수 배열로 저장한다. 전체 캠페인 메타데이터의 기존 2,048바이트 제한을 유지한다. 상태가 바뀌면 즉시 전송해 0.18초 눌림 예고가 정기 0.2초 갱신 사이에서 사라지지 않게 한다. 발동 완료 상태의 수동 전송만 확인하지 말고 실제 호스트·참가자 실행에서 예고 수신을 검증한다.

## 검증 결과

행동 검사 33개, 두 프로세스 온라인 시나리오 9개, 네 프로세스 시나리오 1개가 통과했다. 전체 검사 중 옛 쥐·레버 좌표를 사용하는 사례는 새 저장 맵 위치로 수정한 뒤 해당 사례와 나머지 온라인 검사를 재실행했다. 증거는 `artifacts/sorting-suite.log`, `artifacts/remaining-network.log`, `artifacts/paperwork-final.log`에 있다. 기존 캠페인 메타데이터 2,048바이트 제한을 유지한다. 실제 렌더링으로 접수 통로·소품 발사·문서 비산을 확인했다. Windows 내보내기와 패키지 실행, 컴파일된 스크립트 34개·저장 맵 검사, ZIP 8개 파일의 SHA256 검사가 통과했다. `artifacts/sorting-pack-audit.log`와 `build/NO_RETURNS_0.7/SHA256.json`에 패키지 식별자를 남겼다.

리뷰에서 쥐의 바닥 접촉 검사와 참가자의 눌림 예고 누락을 확인해 수정했다. 외부 플레이테스트와 Steam 연동·심사는 완료로 표시하지 않는다.
