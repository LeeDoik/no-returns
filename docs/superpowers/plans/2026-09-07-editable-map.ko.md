# 코드 없는 맵 편집 전환 계획

[English](2026-09-07-editable-map.en.md)

> 문서 체계 개정: 이 파일의 버전·수치는 작성 당시 기준입니다. 현재 규칙·미완료 상태는 [문서 홈](../../README.md)을 먼저 확인하세요.

## 승인된 목표와 구조

사용자는 에디터에서 직접 맵을 수정하도록 전환을 요청했다. 기존 절차형 맵을 한 번 저장된 `scenes/maps/shipping_shrine.tscn`으로 옮기고 이후에는 이 파일을 게임의 원본으로 사용한다. 일반 실행·빌드가 맵을 다시 생성하거나 덮어쓰지 않는다. 배경/조명/장식은 실제 노드로 보인다. 배송구 외형과 판정, 벨트와 레버, 쥐 둥지·활동 범위·순찰점, 직원·화물 시작점을 함께 편집한다.

## 구현 순서

1. 이동·회전한 배송구/벨트, 이동한 둥지/시작점, 저장·재로드 후 배치 유지 검사부터 추가한다.
2. 맵 런타임과 한·영 표지판 스크립트, 구역 포함 판정 헬퍼를 작성한다. 기존 생성기는 일회성 변환에만 쓴다.
3. 현재 맵을 기능별 노드로 묶어 씬에 저장하고 메인 씬에서 참조한다. 직원·화물·벨트·쥐가 실제 씬 위치를 읽게 바꾼다.
4. 서로 다른 맵 파일을 가진 방장/손님은 입장 전에 거절한다. 기존 로컬·온라인 검사와 편집 배치 검사를 실행한다.
5. 편집용 실행 바로가기, 벽 복제용 예제, 전체 한·영 초보 안내를 제공한다. 에디터와 게임 렌더, Windows 내보내기와 팩을 확인하고 로컬 Git에 기록한다.

## 한계와 보존

기존 project.godot의 사용자 에디터 저장과 art 작업은 건드리지 않는다. 기본 크기·배치·판정·게임 규칙은 보존한다. 쥐는 자유로운 길찾기 AI로 바꾸지 않으므로 경유점을 통로에 배치해야 한다. 멀티플레이는 같은 맵으로 다시 빌드한 파일을 모두 사용한다. 플레이 중 편집 동기화·사용자 맵 다운로드·Steam Workshop은 범위가 아니다. F5로 전체 게임을 시험하고 배포 EXE에는 재빌드가 필요하다.


## 검증 결과 · 2026년 9월 8일

동작 검사 22개, 실제 두 프로세스 시나리오 7개, 네 프로세스 시나리오가 통과했다. 새 검사에는 저장·재로드, 이동/회전 배송구와 벨트, 실제 배송 보상, 시작점 연결, 블록 외형/충돌 동시 변경, 다른 맵 입장 거절이 포함된다. 전체 검사 로그는 `artifacts/editable-full-tests.log`, 추가 통합 검사는 `artifacts/editable-final-test.log`에 남긴다.

실제 렌더러의 배송 신전 캡처를 확인했다. Windows 내보내기와 패키지 실행 검사가 통과했고, 팩 안의 컴파일된 런타임 스크립트 27개·저장 맵·맵 지문을 확인했다. 안정된 0.7 실행 파일/ZIP 경로를 0.7.3으로 갱신했다. 데스크톱 화면 캡처 도구가 선택한 Godot 창 대신 다른 화면을 반환하여 에디터에서 마우스로 편집하는 과정의 시각 검증은 완료하지 못했다. 저장 씬 편집·재로드와 게임 반영은 엔진 검사로 확인했다.

[한국어 편집 안내](../../development/map-editing.ko.md)와 영어 대응본, EDIT_MAP.cmd, BUILD.cmd, 충돌 포함 SolidBlock 예제를 제공한다. 사용자 project.godot 수정과 별도 아트 파일은 이번 커밋에 포함하지 않는다.
