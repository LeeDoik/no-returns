# 첫 플레이 기반 — 구현 계획

[English](2026-09-07-first-prototype.en.md)

> **과거 기록 · 2026-09-12 폐기/대체.** 현재 게임은 [PSX 우주 배송 기획](../../current/01-overview.ko.md)을 따른다. 아래 구현·실행·아트·수치는 과거 자료이며 현재 상태가 아니다. 삭제된 파일은 경로 기록으로만 남긴다.


> 문서 체계 개정: 이 파일의 버전·수치는 작성 당시 기준입니다. 현재 규칙·미완료 상태는 [문서 홈](../../README.md)을 먼저 확인하세요.

버전 0.1 · 2026-09-07 · 범위: 첫 개발용 프로토타입.

**목표:** Windows에서 3인칭 임시 창고를 실행하고 두 실행 창을 연결해, 공유 화물 하나를 들고 내려놓고 던지고 받고 배송한다.

**구조:** 호스트 한 명이 플레이어와 화물의 물리를 계산한다. 손님은 이동·상호작용 요청을 보내고 호스트는 요청자, 소유권, 거리를 확인한다. 손님 화면은 전달받은 상태로 표시한다. 화물 소유권과 중복 없는 배송 규칙은 별도의 테스트 가능한 모델로 둔다. 개발 단계의 통신은 세션 경계에 분리한 ENet을 사용한다.

**기술:** Godot 4.7.2 일반판, GDScript, Compatibility 렌더러, ENet. 포터블 실행 환경은 `.tools/godot/`에 둔다. 외부 아트나 유료 서비스는 사용하지 않는다.

**공통 제약:** 한국어와 영어 문서는 전체 대응본으로 유지한다. 글로벌 게임 문구는 영어이며, 이 프로토타입에는 한국어 UI 선택도 제공한다. 호스트 포함 정확히 2인이며 혼자 연습은 별도 모드다. Steam 연결이 됐다고 표시하지 않는다. 일반 화물 하나, 정답 배송구 A, 오답 배송구 B, 짧은 복구와 재시작을 구현한다. 영구 탈락이나 인벤토리는 없다. 호스트가 나가면 손님에게 이유를 보여주고 메뉴로 돌아간다. 손님이 나가면 화물을 놓고 근무를 멈춘다. 유한하지 않은 이동 값과 잘못된 소유권을 거부한다. Steam App ID를 임의로 만들거나 포함하지 않는다. 현재 저장소는 커밋 전의 프로젝트 초안이므로 기존 파일을 보존하고 주어진 작업 폴더에서 진행한다.

에이전트 작업 시 독립적인 화물 규칙 작업에는 subagent-driven-development를 사용할 수 있다. 통합 담당자는 나머지 의존 작업을 직접 진행한다. 보고서도 두 언어로 작성하며, 저장소 기준 커밋 없이 커밋을 만들거나 새로운 사용자 작업을 생성하지 않는다.

## 1. 화물 규칙과 행동 테스트

`RefCounted`를 상속하는 `scripts/cargo_rules.gd`와 `SceneTree`를 상속하는 `tests/test_cargo_rules.gd`를 만든다.

계약:

```gdscript
var holder_id: int = 0
var delivered: bool = false
var score: int = 0
const PICKUP_DISTANCE: float = 2.4
func try_pickup(peer_id: int, player_position: Vector3, cargo_position: Vector3) -> bool
func try_release(peer_id: int) -> bool
func try_dispatch(dock_id: int) -> bool
func remove_player(peer_id: int) -> void
func reset_crate() -> void
func reset_shift() -> void
```

양수인 플레이어 ID는 아무도 들지 않고 배송되지 않은 화물을 2.4미터 이내에서 집을 수 있다. 유한하지 않은 좌표는 거부한다. 현재 소유자만 놓을 수 있다. 들고 있지 않고 아직 배송되지 않은 화물을 배송구 1로 보낸 경우에만 점수를 한 번 올린다. 소유자가 접속을 끊으면 화물을 놓는다. 화물 초기화는 소유자·배송 여부만 지우고 점수는 보존한다. 근무 초기화는 점수도 지운다. 초기화된 화물은 새 화물이므로 다시 한 번 점수를 얻을 수 있다. 접속자 등록과 접촉 판정은 월드에서 담당한다.

먼저 의미 있는 검증문을 작성하고 모듈이 없어서 의도대로 실패하는지 확인한 뒤 구현하고 다시 실행한다. 동시에 집기, 거리와 잘못된 벡터, 다른 사람의 내려놓기, 들고 있는 상태·오답·중복 배송, 접속 종료, 초기화 경계를 검증한다. 명령: `.tools/godot/Godot_v4.7.2-stable_win64_console.exe --headless --path . --script tests/test_cargo_rules.gd`. 구현 후 종료 코드 0과 PASS 요약을 기대한다.

## 2. 플레이 가능한 3인칭 장면

`project.godot`, `scenes/main.tscn`, `scripts/main.gd`, `scripts/depot.gd`, `scripts/worker.gd`, `scripts/interface.gd`를 만든다.

기본 도형으로 바닥, 벽, 중앙 칸막이, 입고·복구 지점과 A/B 표지가 있는 배송구를 만든다. 작업자는 CharacterBody3D로 카메라 기준 이동, 충돌, 점프와 벽을 피하는 회전 카메라를 제공한다. 놓인 화물의 RigidBody3D는 호스트가 계산하며, 들고 있으면 고정해 손 위치에 둔다. 상호작용은 여유 있는 근접 판정으로 집기·받기 또는 내려놓기이며 던지기는 조준 방향으로 일정한 상승 궤적을 사용하고 착지 표지를 보여준다. 전송 입력을 제한하고 오래된 이동 입력은 만료한다. 떨어지거나 잘못 배송한 화물은 입고 지점으로 돌려보낸다. 배송 5개·3분의 짧은 연습 근무는 프로토타입용 수치이며 최종 10~15분 근무와 다르다. 성공·시간 초과 뒤 재시작을 제공하고 혼자 연습에도 같은 규칙을 적용한다.

UI에는 혼자 연습, 방 만들기, 참가, 주소 입력, 언어 전환, 조작 안내, 상태, 점수·시간, 오류 안내, 일시정지·나가기 메뉴가 있다. Escape의 일반 메뉴 동작으로 마우스 잠금을 해제한다. 로컬 메뉴는 입력을 멈추며 호스트 시뮬레이션은 계속한다. 접속 종료나 연결 실패 뒤에도 버튼을 사용할 수 있어야 한다. 영어 원문과 한국어 대응문은 `scripts/copy.gd`에 둔다.

## 3. 두 실행 창의 통신과 통합 검증

`scripts/session.gd`와 `tests/test_network.gd`를 만든다. 기본 ENet 통신은 UDP 27842 포트와 손님 한 자리다. 연결 시간 제한은 10초다. 모든 네트워크 RPC의 노드 경로를 고정한다. 호스트는 전달받은 플레이어 ID를 믿지 않고 실제 송신자 ID로 행동을 승인한다. 이동 계산, 점수, 목표, 시간, 화물 소유권과 물리는 호스트가 관리한다. 손님은 위치·점수·화물 소유권을 보내지 않는다. 신뢰성 있는 행동 요청과 순서가 보장되는 비신뢰 상태 전송을 분리한다. 근무 중 참가는 거부하며 대기실에만 참가할 수 있다. 두 작업자가 모이면 호스트가 시작한다. 혼자 연습은 소켓이 필요 없다.

자동 통합 검증은 별도 포트를 쓰는 실제 Godot 프로세스 두 개로 수행한다. 연결, 호스트에서 관찰되는 손님의 이동, 양쪽에서 확인되는 손님의 집기·놓기, 양쪽의 배송 1회, 손님 종료 후 정리를 확인한다. 소유자가 아닌 사람의 행동을 거부하는 경우도 포함한다. 모든 테스트에는 시간 제한과 실패 시 0이 아닌 종료 코드를 둔다. 이는 로컬 ENet 동작만 검증한다. 다른 PC, NAT, Steam 오버레이·초대, 출시 품질은 아직 검증하지 않는다.

## 4. 실행·화면 확인·전달

ASCII Windows 실행 파일 `PLAY.cmd`, `PLAY_TWO.cmd`, `EDIT.cmd`를 만들고 실행 파일 위치를 기준으로 경로를 찾는다. `PLAY_TWO.cmd`는 사용자가 실행할 때 대화형 창 두 개를 연다. 실행 환경 다운로드와 공식 SHA512 검증을 가이드에 기록한다. 내려받은 에디터 압축 파일, 실행 환경, 캐시, 화면 이미지와 테스트 기록은 소스 관리에서 제외한다. 에디터를 이용한 실행 파일을 독립된 Steam 배포본이라고 부르지 않는다.

정확한 실행·편집·테스트 순서, 조작, 기대 화면, 검증 근거, 제한과 다음 실험을 담은 `docs/prototype/01-first-playable.en.md`와 `.ko.md` 전체 대응본을 만든다. 두 README에 실행 진입점과 실제 Steam 상태를 반영한다.

검증: `--headless --editor --quit`으로 전체 스크립트를 불러온다. 화물 규칙 및 두 프로세스 통합 테스트를 실행한다. Compatibility 렌더러로 실제 장면을 실행해 메뉴와 창고 화면을 저장하고 눈으로 확인한다. 새 문서의 링크와 언어 대응을 검사한다. 완료 전에 스크립트 오류와 검토 지적을 해결한다. Windows 독립 배포용 템플릿, 다른 하드웨어, 컨트롤러, 지연 보정과 상용 출시 검증은 이번 점검 범위 밖이다.
