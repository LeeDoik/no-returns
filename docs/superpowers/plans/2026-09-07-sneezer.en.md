2026-09-07 · User approved the telegraphed Sneezer interaction and asked to start. Version 0.1 was reported working by the user; that does not establish remote Steam connectivity.

**Goal:** A Sneezer and a Standard crate coexist, can both be delivered, and create recoverable cooperative accidents through an obvious directional sneeze.

**Architecture:** Extract per-cargo ownership, recovery, carry/throw physics and presentation into `scripts/cargo.gd`. The host advances each cargo, selects blast targets and applies pushes; guest snapshots carry both cargo states and monotonic sneeze event IDs. `scripts/sneeze_rules.gd` owns a small testable clock and cone filter. No client decides hit results.

**Tech stack:** Existing Godot 4.7.2 / GDScript / ENet, existing primitive scene. No new engine, service, purchased asset or Steam dependency.

## Constraints and decisions

- Exactly two cargo slots: ID 1 Standard at `(0, 0.55, 1.1)` and ID 2 Sneezer at `(-2, 0.55, 4)`. Both go to A. One cargo per worker; E chooses the nearest available reachable cargo. Preserve 2.4m pickup distance, validated carry sweeps, safe release, five shared deliveries, three minutes and 1.2-second recovery.
- Calm for a host-selected 6–9 seconds, then a 1.5-second windup, a single sneeze and a 0.35-second visible burst before the next calm interval. Initial calm is 6 seconds. Random timing is chosen only by the host; test seeds are reproducible. Timing values are prototype tuning, not final balance.
- Forward range 4.5m, cone half-angle 50 degrees, vertical separation at most 1.6m. Solid depot geometry blocks effects. The source and its carrier are excluded. Each eligible target is affected once per sneeze.
- Other workers receive a bounded push (7m/s horizontally, at least 3.8m/s upward), briefly lean and drop cargo. Other crates in the cone are released if held and receive a velocity change (8m/s forward, 4m/s up). Control remains available and push decays; no death, ragdoll or permanent stun.
- Held Sneezer follows the carrier's authoritative aim; a dropped/thrown Sneezer keeps its last facing. Only the visual nose turns; the proven axis-aligned collision box remains unchanged. No physics changes from swelling.
- Windup has swelling, face change, countdown text and directional floor warning. Burst has a short puff and ACHOO text. Small synthesized cues and a menu mute option are allowed; all danger is readable silently. No final art/audio asset production.
- Cargo recovery, shift completion, timeout and lobby return cancel pending sneeze effects. Restart resets clocks and pushes. Event numbers increase within an authority's model and include an authority/shift epoch, so reused guest nodes accept a new host's lower counter while repeat snapshots cannot replay a burst. Guests display replicated clock state and event effects; they never run independent hit simulation.
- Korean UI remains default. All human-readable documents are complete Korean/English pairs, with matching values and status. Steam, Internet validation, Clinger, Hopper, four players, gamepads and final assets remain outside this change.

## Task 1 — clock and targeting rules

Create `scripts/sneeze_rules.gd` (`RefCounted`) and `tests/test_sneeze_rules.gd`. A bounded independent implementer may use subagent-driven-development; the root worker integrates the coupled scene changes. Review uses requesting-code-review. No new user task or git commit is needed in this unborn workspace.

Required interface:

```gdscript
const WINDUP_SECONDS := 1.5
const BURST_SECONDS := 0.35

```
