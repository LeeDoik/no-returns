# 접착 상자 프로토타입 0.3 구현 계획

[English](2026-09-07-clinger.en.md)

사용자가 0.2가 잘 작동한다고 확인하고 다음 진행을 요청했다. 기존 기획의 다음 화물인 접착 상자를 구현한다. 독립 접착 제어기는 subagent-driven-development로 구현하고 주 담당자가 통합한다. 완료 전 requesting-code-review로 검토한다.

**목표:** 세 종류의 화물이 함께 존재하며 접착 상자가 직원 한 명 또는 접착 상자가 아닌 화물 하나에 붙고 재채기로 떨어진다.

**구조:** `clinger.gd`는 호스트가 진행하는 접착 제어기로 상태 표시와 복제를 포함한다. Cargo는 물리·소유권·배송을 유지하고 main은 화물 이동 뒤, 상태 전송 전에 접착을 갱신한다. 화물 전송에 간결한 배열을 사용해 세 화물도 기존 1280바이트 상한 안에 유지한다. 통신 방식은 바꾸지 않는다.

**기술:** 기존 Godot 4.7.2, GDScript, ENet과 기본 도형. 기본 한국어 UI, 영어 원문과 전체 대응 문서. Steam 연동·최종 에셋·점프 상자·4인 확장은 제외한다.

## 결정

- ID 3 접착 상자는 `(2, 0.55, 4)`에서 시작하며 목적지는 A다. 일반·재채기 상자는 ID 1·2를 유지한다. 목표는 180초 안에 배송 5개다.
- 자유 상태의 접착 상자가 화물 중심이나 직원 가슴에서 0.95m 안에 있고 단단한 지형이 가리지 않으면 붙는다. 가장 가까운 유효 대상을 고른다. 자신·숨김/복구/비활성 화물·다른 접착 상자는 제외한다. 연쇄 연결은 없다.
- 5초간 붙는다. 직원은 평소 속도의 70%로 움직이지만 조작할 수 있고 일반 운반 자리 하나도 유지한다. 붙은 접착 상자를 직접 집을 수는 없으며 대상 화물을 들면 둘을 함께 운반한다.
- 붙은 순간의 월드 좌표상 상대 위치를 유지한다. 따라갈 때 접착 상자의 충돌 상자로 단단한 지형을 검사하고 막히거나 2m 넘게 벌어지면 떨어진다. 벽이나 직원 복귀 위치를 가로질러 끌고 가지 않는다.
- 시간 만료·재채기 적중·대상 소실·반송·근무 종료·재시작으로 떨어진다. 2초간 다시 붙지 않으며 그동안 일반 E 집기는 가능하다. 시작·복구 직후에는 1초의 여유를 둔다.
- 대상 화물이 정상 배송되면 접착 상자도 한 번만 점수를 주고 복구한다. 오답·분실 복구라면 점수를 주지 않고 떨어진다. 독립 상태의 일반 배송도 가능하다.
- 연두색 상자에 돌출 접착판, 눈에 보이는 연결 표시, 현지화한 접착/대기 시간을 표시한다. 소리는 선택 사항이며 무음에서도 이해할 수 있어야 한다.
- 호스트가 접착·분리를 결정한다. 손님은 대상 종류·ID·시간, 화물 위치와 직원 속도 상태를 받는다. 복제된 표시는 대상을 찾거나 밀기 판정을 하지 않는다.

## 작업

- [x] 구현 전에 실제 장면의 실패 검사를 작성한다. `scripts/clinger.gd` 인터페이스는 `setup(cargo)`, `step(delta, workers, cargos)`, `detach()`, `reset()`, `snapshot()`, `apply_snapshot(data)`, `target_kind`, `target_id`, `remaining`, `cooldown`이다. 독립 담당자는 이 모듈과 `tests/test_clinger.gd`를 맡고 주 담당자가 수명주기를 통합한다.
- [x] 세 번째 화물, 붙은 화물의 집기/진행 제한, 수명주기 취소, 직원 속도 계수, 재채기 분리, 간결한 전송 형식과 현지화 신호를 cargo/main/worker/copy에 통합한다. 필요하면 세 번째 화물을 격리해 기존 검사를 유지한다.
- [x] 실제 두 프로세스 접착·분리 검사를 추가한다. 같은 대상·남은 시간·이동·재채기 분리, 기존 접속 종료·재참가와 패킷 상한을 검사한다.
- [x] 전체 동작 검사와 에디터 가져오기를 실행한다. 실제 렌더러 캡처를 확인한다. 변경을 검토하고 관련 문제를 수정한다. 기존 샌드박스 인증서·사용자 폴더 오류는 스크립트 오류와 구분한다.
- [x] 0.3 실행 안내의 전체 대응본을 만들고 두 README·Steam 현재 상태를 갱신하되 출시 요건은 완료로 바꾸지 않는다. 검증 결과와 남은 사람/원격 검사를 기록한다.

완료 근거: [0.3 실행 안내](../../prototype/03-clinger.ko.md). 스크립트 8개·프로세스 쌍 3개가 통과했으며 에디터 가져오기와 실제 화면 검사를 마쳤다. 사람이 함께 하는 플레이테스트와 원격·Steam 검증은 남아 있다.
