# 재채기 화물 — 프로토타입 0.2 구현 계획

2026-09-07 · 사용자가 예고 후 밀어내는 재채기 화물의 구현을 승인하고 시작을 요청했다. 0.1 버전은 사용자가 잘 실행된다고 확인했으며, 이것이 원격 Steam 연결 검증을 뜻하지는 않는다.

**목표:** 재채기 상자와 일반 상자를 함께 놓고 둘 다 배송할 수 있게 하며, 알아보기 쉬운 방향성 재채기로 수습 가능한 협동 사고를 만든다.

**구조:** 화물별 소유권, 복구, 운반·던지기 물리와 표시를 `scripts/cargo.gd`로 분리한다. 호스트가 화물을 진행시키고 재채기 대상을 판정해 밀어낸다. 손님에게는 두 화물 상태와 계속 증가하는 재채기 이벤트 번호를 보낸다. `scripts/sneeze_rules.gd`는 따로 검사할 수 있는 주기와 부채꼴 범위 규칙을 담당한다. 손님은 적중 결과를 결정하지 않는다.

**기술:** 기존 Godot 4.7.2 / GDScript / ENet과 기본 도형 장면. 엔진·서비스·유료 에셋·Steam 의존성은 추가하지 않는다.

## 제약과 결정

- 화물은 정확히 두 자리다. ID 1 일반 상자는 `(0, 0.55, 1.1)`, ID 2 재채기 상자는 `(-2, 0.55, 4)`에서 시작한다. 둘 다 목적지는 A다. 직원 한 명은 화물 하나만 들며 E는 집을 수 있고 닿는 화물 중 가장 가까운 것을 고른다. 집기 거리 2.4m, 충돌을 검사하는 운반, 안전한 내려놓기, 공동 배송 5개·3분·복구 1.2초를 유지한다.
- 호스트가 정한 6~9초 동안 쉬고, 1.5초 예고 뒤 한 번 재채기하며 0.35초간 분출을 보여준 다음 다시 쉰다. 최초 대기는 6초다. 무작위 간격은 호스트만 정하며 테스트 시드로 재현할 수 있다. 수치는 최종 밸런스가 아닌 프로토타입 조정값이다.
- 전방 거리 4.5m, 부채꼴 반각 50도, 높이 차 최대 1.6m. 창고의 단단한 지형이 효과를 막는다. 재채기 상자 자신과 이를 든 사람은 제외한다. 각 대상은 재채기 한 번에 한 번만 영향을 받는다.
- 다른 직원은 제한된 힘으로 밀려나고(수평 7m/s, 위쪽 최소 3.8m/s), 잠시 몸이 기울며 들고 있던 화물을 놓는다. 범위 안의 다른 상자는 들려 있다면 해제하고 전방 8m/s·위쪽 4m/s의 속도 변화를 준다. 조작은 계속 가능하고 밀리는 힘은 줄어든다. 죽음·래그돌·영구 경직은 없다.
- 들고 있는 재채기 상자는 호스트가 확인한 운반자의 조준 방향을 따른다. 놓거나 던지면 마지막 방향을 유지한다. 눈에 보이는 코만 회전하고 검증한 축 정렬 충돌 상자는 유지한다. 부풀어도 충돌 크기는 바뀌지 않는다.
- 예고에는 부풀기, 표정 변화, 남은 시간과 바닥 방향 경고를 사용한다. 분출에는 짧은 바람과 에취 글자를 사용한다. 간단한 합성 신호음과 메뉴의 음소거를 제공할 수 있으며 모든 위험은 소리를 끄고도 읽혀야 한다. 최종 아트·오디오 에셋 제작은 하지 않는다.
- 화물 복구, 근무 성공·시간 종료, 대기실 복귀 때 대기 중인 재채기를 취소한다. 재시작하면 주기와 밀리는 힘을 초기화한다. 이벤트 번호는 호스트의 모델 안에서 증가하며 호스트·근무별 식별자를 함께 사용한다. 재사용하는 손님 노드는 새 호스트의 작은 번호도 받아들이되, 같은 상태를 다시 받아 분출을 반복 재생하지 않는다. 손님은 전송받은 주기·이벤트를 표시하며 별도의 적중 시뮬레이션은 하지 않는다.
- 기본 UI는 한국어다. 사람이 읽는 문서는 모두 수치와 상태가 같은 한·영 전체 대응본을 만든다. Steam, 인터넷 검증, 접착·점프 상자, 4인, 게임패드와 최종 에셋은 이번 범위 밖이다.

## 작업 1 — 주기와 범위 규칙

`scripts/sneeze_rules.gd`(`RefCounted`)와 `tests/test_sneeze_rules.gd`를 만든다. 독립 구현 담당자에게 subagent-driven-development로 맡길 수 있으며, 주 담당자는 서로 의존하는 장면 변경을 통합한다. 검토는 requesting-code-review를 사용한다. 아직 기준 커밋이 없는 작업 폴더이므로 새 사용자 작업이나 git 커밋은 만들지 않는다.

필수 인터페이스:

```gdscript
const WINDUP_SECONDS := 1.5
const BURST_SECONDS := 0.35
const RANGE := 4.5
const HALF_ANGLE_DEGREES := 50.0
const HEIGHT := 1.6
var phase := "calm"
var remaining := 6.0
var event_id := 0
func _init(seed_value: int = 1) -> void
func reset() -> void # 최초 대기 6초; event_id 보존
func advance(delta: float) -> bool # 예고 -> 분출 때 한 번 true; 여러 이벤트 따라잡기 없음
static func contains(origin: Vector3, forward: Vector3, target: Vector3) -> bool
```

- [x] 모듈 작성 전에 실패하는 테스트를 실행한다. 주기의 정확한 전환, 예고 중 밀기 없음, 이벤트 한 번, 무작위 대기 범위, 초기화 취소, 유한하지 않은 시간값 거부와 앞·뒤·옆·높이·거리 필터를 확인한다. 음수·잘못된 시간값은 상태를 바꾸지 않는다. 긴 프레임이 예고를 지우지 않도록 호출 한 번에 한 단계까지만 전환한다.
- [x] 모델을 구현하고 같은 테스트가 종료 코드 0으로 통과하게 한다. 위임한 경우 대응 보고서에 근거를 남긴다.

## 작업 2 — 두 화물, 호스트의 밀기 판정과 신호

`scripts/main.gd`, `depot.gd`, `worker.gd`, `interface.gd`, `copy.gd`, `project.godot`를 수정한다. `scripts/cargo.gd`와 `scripts/sneeze_cues.gd`를 만든다.

`main.cargos`는 ID와 Cargo 객체를 연결한다. `main.score`는 각 화물 규칙의 점수를 합한다. 화물은 `rules`, `body`, `home`, `kind`, `recovery_left`, `sneeze`, `facing`, `step(delta, workers)`, `reset_shift()`, `reset_crate()`, `release(worker, throwing)`, `predict_contact(origin, velocity)`, `snapshot()`, `apply_snapshot(data)`를 제공한다. 호스트의 행동 검증은 실제 송신자 ID를 사용하며 접속자 여부와 이미 든 화물이 있는지 확인한다.

- [x] 단일 화물 테스트를 ID 1 기준으로 옮기되 검증 내용을 약화하지 않는다. git 기준이 없으므로 변경 전 소스를 무시된 artifacts 폴더에 보관해 검토에 사용한다.
- [x] 실제 장면의 실패 검사를 추가한다. 두 사람이 서로 다른 화물을 동시에 들기, 한 사람 한 자리, 가까운 화물 선택, 예고 중 적중 없음, 실제 분출이 직원과 일반 상자를 밀기, 운반자 면역, 지형 차폐, 충격 중복 없음, 복구·재시작 취소를 구현해 통과시킨다.
- [x] 직원의 밀리는 속도를 일반 이동과 분리해 입력 보정이 충격을 즉시 없애지 못하게 한다. 새 근무와 복구 때 초기화한다. 짧은 몸 기울임도 손님에게 복제한다.
- [x] 고정 화물 ID, 소유권, 복구, 방향, 주기, 이벤트 번호와 분출 위치를 전송한다. 배송은 중복 없이 공동 점수에 반영한다. 표시와 소리는 이벤트를 소비할 뿐 게임플레이 충격을 적용하지 않는다.
- [x] 현지화한 화물 이름, 예고·분출 상태, 한 번 클릭하는 신호음 음소거를 추가한다. 표시는 충돌체와 판정 권한에서 분리한다.
