# 물리 검토 수정 결과

[English](physics-fix-report.en.md)

> 문서 체계 개정: 이 파일의 버전·수치는 작성 당시 기준입니다. 현재 규칙·미완료 상태는 [문서 홈](../README.md)을 먼저 확인하세요.

버전 0.1 · 2026-09-07 · 첫 프로토타입 범위에서 완료.

`scripts/main.gd`와 `scripts/depot.gd`에서 P2 지적 두 건을 수정했다.

- 투척 표시는 화물의 현재 해제 위치에서 실제 0.8m 상자 모양을 물리 틱마다 이동시켜 충돌을 예측한다. 중력은 프로젝트 설정과 화물의 중력 배율을 사용한다. 선형·각 공기 감쇠는 REPLACE 모드의 0으로 명시했고 충돌체 회전은 고정했다. 원은 **첫 충돌**을 가리키며 접촉면에서 0.08m 띄우고 면의 법선에 맞춰 방향을 바꾼다. 시뮬레이션 3초 안에 충돌을 찾지 못하면 숨긴다. 반발과 지면 마찰은 물리 시뮬레이션으로 처리하며, 원은 최종 정지 위치를 예측하지 않는다.
- 운반 중에는 호스트의 매 틱마다 상자 전체를 손 방향으로 스윕하고, 0.005m의 쿼리 여유를 두고 지형 앞에서 멈춘다. 방향을 돌려도 충돌 상자는 회전하지 않는다. 내려놓기·던지기는 손으로 다시 순간이동하지 않고 검증된 위치에서 시작한다. 플레이어 원점과 화물 사이가 2.4m보다 멀어지면 화물을 먼 거리까지 끌어오지 않고 기존 위치에서 놓는다. 집기와 같은 거리 기준을 사용하므로 플레이어 뒤나 옆에서 정상 범위 안의 화물을 집었을 때도 운반을 유지한다.

`tests/test_physics.gd`는 실제 창고 장면을 불러와 실제 강체를 시뮬레이션한다. 제품 코드 수정 전에는 칸막이 운반 관통, 내려놓은 뒤 반대편 위치, 먼 거리 운반 유지, 바닥·벽의 표시 정확도 등 다섯 검사가 실패했다. 수정 전 표시 오차는 바닥 3.5278m, 뒤쪽 벽 0.2494m였다. 최종 검사는 운반의 매 프레임마다 전체 충돌체 겹침도 확인하고, 내려놓기 직전에 방향을 바꿔 해제 시 순간이동을 검사하며, 투척 방향·장애물 다섯 경우를 확인한다.

| 실제 첫 충돌 조건 | 측정 표시 오차 | 허용 최대값 |
| --- | ---: | ---: |
| 바닥, 직선 투척 | 0.1734m | 0.20m |
| 바닥, 비스듬한 투척 | 0.1734m | 0.20m |
| 뒤쪽 벽 | 0.0340m | 0.20m |
| 측면 벽 | 0.0260m | 0.20m |
| 가까운 칸막이 | 0.0600m | 0.20m |

비교 기준은 실제 강체의 첫 `body_entered` 신호에서 얻은 중심 좌표를 접촉면으로 옮기고 원의 표시 높이 0.08m를 더한 위치다. 0.20m 허용 오차에는 이산적인 충돌 보고 틱이 포함된다. 이 결과는 현재 정적·축 정렬 창고 지형과 프로젝트의 60Hz GodotPhysics3D 설정에 해당한다. 움직이는 장애물, 별도 중력 영역, 다른 물리 엔진, 네트워크 보간·지연에서의 정확도를 증명하지 않는다. 첫 프로토타입에서는 자유 비행 중 회전과 공기 저항을 의도적으로 단순화했다.

후속 검토에서는 거리 검사 회귀를 발견했다. 손과 화물 사이 거리를 비교하면 플레이어 기준으로는 유효한 집기가 취소될 수 있었다. 실제 장면 검사에 플레이어 뒤와 옆으로 각각 2.3m 떨어진 화물을 추가했다. 높이 차이는 0.36m, 총 거리는 약 2.328m다. 수정 전에는 두 경우 모두 첫 운반 틱에서 소유권 유지 검사가 실패했다. 최종 집기 검사 위치는 칸막이와 떨어뜨려, 장애물이 없을 때 손에 도달하는지도 확인한다. 운반 거리 검사를 플레이어 원점 기준으로 바꾼 뒤에는 두 경우와 기존 칸막이·먼 거리 놓기 검사를 모두 통과했다.

프로젝트 루트의 PowerShell에서 실행한다.

```powershell
& .tools/godot/Godot_v4.7.2-stable_win64_console.exe --headless --path . --log-file physics-green.log --script tests/test_physics.gd -- --role=physics
```

결과는 `PHYSICS PASS: 0 failure(s)`, 종료 코드 0이다. 화물 규칙 검사와 헤드리스 편집기 가져오기도 스크립트 오류 없이 종료 코드 0을 반환했다. 실행 환경의 알려진 루트 인증서 저장소 오류와, 편집기 가져오기에서는 `user://` 프로파일러 폴더 오류가 계속 출력됐다. 별도 통신 검사는 [프로토타입 안내](01-first-playable.ko.md)에 기록한다.
