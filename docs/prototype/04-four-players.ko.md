# 반품 불가 — 2~4인 실행 안내

[English](04-four-players.en.md)

> 문서 체계 개정: 이 파일의 버전·수치는 작성 당시 기준입니다. 현재 규칙·미완료 상태는 [문서 홈](../README.md)을 먼저 확인하세요.

프로토타입 0.4 · 2026-09-07 · Windows · Godot 4.7.2

방 하나에 **직원 2~4명**이 참가할 수 있습니다. 혼자 연습, 일반·재채기·접착 상자, 공동 배송 5개와 제한 시간 3분은 유지합니다. 같은 상호작용을 동료가 더 많은 상황에서 확인하는 단계이며 최종 4인 밸런스를 확정한 것은 아닙니다.

## 실행하기

1. 이전 게임 창을 닫고 이미 열린 방이 있다면 메뉴로 나갑니다.
2. [PLAY_FOUR.cmd](../../PLAY_FOUR.cmd)를 더블클릭합니다. 방장 하나와 손님 셋의 창을 각각 640 × 400 크기로 엽니다. 화면에 맞게 창을 옮기거나 크기를 바꿉니다.
3. 방장 창에 **4 / 4 직원**이 표시되면 **근무 시작**을 누릅니다. 직원 두 명이나 세 명이 모여도 시작할 수 있으며 방장 혼자서는 시작할 수 없습니다.
4. 창을 바꿔 선택하며 직원을 조작합니다. 별도 프로세스를 여는 개발용 실행기이며 키보드 하나로 동시에 조작하는 로컬 멀티플레이 방식은 아닙니다. 글자가 작으면 해당 창을 최대화하세요.

[PLAY_TWO.cmd](../../PLAY_TWO.cmd)는 기존처럼 창 두 개를 엽니다. [PLAY.cmd](../../PLAY.cmd)는 메뉴와 혼자 연습을 엽니다. 직접 연결할 때는 한 사람이 **방 만들기 / 2~4인**을 누르고 나머지는 방장 주소를 입력합니다. 같은 PC의 주소는 `127.0.0.1`입니다. 모두 같은 버전을 사용해야 하며 일반 플레이 포트는 UDP **27842**입니다.

WASD는 이동, 마우스는 둘러보기·조준, Space는 점프, E는 집기·놓기, 왼쪽 클릭은 던지기, Esc는 메뉴입니다. 메뉴를 열어도 시간은 흐릅니다. 언어·신호음 버튼도 유지합니다. 화물 규칙은 [접착 상자 안내](03-clinger.ko.md)를 참고하되 그 문서의 2인 제한은 과거 내용입니다. 실행 환경 복원은 [첫 안내](01-first-playable.ko.md#6-수정하기와-실행-환경-복원)에 있습니다.

## 달라진 점

| 항목 | 현재 동작 |
| --- | --- |
| 인원 | 방장과 손님 최대 세 명 |
| 구분 | 고정 번호 01~04와 노랑·민트·연보라·분홍 작업복 |
| 시작 위치 | 직원 자리마다 다른 위치 |
| 손님 퇴장 | 진행 중인 근무를 멈추고 모두 대기로 복귀. 든 화물은 놓고 접착은 취소 |
| 재시작 | 방장이 남은 2~4명으로 다시 시작. 목표와 화물 초기화 |
| 재참가 | 빈 자리를 사용하고 남아 있는 직원의 번호는 유지 |
| 방장 퇴장 | 세션 종료. 손님에게 이유를 표시하고 메뉴로 복귀 |
| 참가 제한 | 근무 중 참가·방장 이전 없음. 서버가 받는 손님은 최대 세 명 |

한 사람은 재채기 상자, 다른 사람은 일반 상자를 들고 세 번째 사람에게 접착 상자가 붙게 해보세요. 네 번째 사람은 떨어지는 화물을 받거나 회수할 수 있습니다. 사람이 늘어 역할 분담에 도움이 되는지, 공간만 붐비는지 확인합니다. 이번 버전에는 화물 추가나 인원별 목표 조정을 넣지 않았습니다.

## 서버 구조와 검증 범위

방장의 게임 프로세스가 최종 판정을 내리는 서버도 맡습니다. 이동·물리·소유권·접착·재채기 적중·점수를 계산하고, 손님은 입력을 보내며 받은 결과를 표시합니다. 현재 엔진은 초당 60번 물리를 계산하고 초당 20번 상태를 전송합니다. 화물에 이어 직원 위치도 간결한 배열로 전송해 기존 상태 크기 상한 1280바이트를 유지합니다. 별도 임대 서버나 Steam 통신은 없습니다.

전체 검사 명령은 다음과 같습니다.

```powershell
python tools/run_tests.py
```

개별 스크립트 9개, 두 프로세스 검사 3개와 네 프로세스 검사 1개를 실행합니다. 4인 로그는 `artifacts/four-network-{host,guest1,guest2,guest3}.log`에 있으며 별도로 `python tools/run_four_test.py`를 실행할 수도 있습니다. 테스트 포트 27943~27947은 일반 플레이와 구분됩니다.

직원 자리 검사는 구현 전 먼저 실패한 뒤, 2·3·4인 시작 조건, 고유 자리·시작 위치, 빈 자리 재사용, 장면의 다섯 번째 직원 거부와 상태 크기를 확인해 통과했습니다. 기존 회귀 검사는 화물·물리·근무 흐름·재채기·접착·2인 재접속을 계속 확인합니다.

실제 네 프로세스 검사는 모든 참가자의 같은 명단·자리, 서로 다른 두 화물의 소유권, 접착, 두 직원을 맞히는 재채기와 화물 해제, 공동 배송, 운반자 퇴장, 3인 재시작과 방장 퇴장을 확인합니다. 최초 기록된 직렬화 상태 최대 크기는 **1036바이트**였습니다. 상태 본문의 상한이며 통신 포장 데이터는 제외한 수치입니다. 코드 검토에서 P1/P2 결함은 발견하지 못했습니다. 빈 자리 재사용은 로컬 검사로 확인했으며 실제로 그 자리에 재접속하는 과정은 4인 통신 검사에 포함하지 않았습니다. 만원 방의 추가 연결 거부는 ENet 정원으로 설정했지만 별도 다섯 번째 프로세스 검사는 없습니다.

에디터 가져오기와 실제 렌더러의 한국어·영어 메뉴, 대기실, 직원 네 명의 화면도 확인합니다. 샌드박스에서 기존 인증서 저장소와 `user://` 캐시·프로파일러 폴더 오류가 출력될 수 있으며 스크립트 오류와 구분합니다. 로컬 화면 자료: [직원 네 명](../../artifacts/four-workers.png), [대기실](../../artifacts/four-lobby.png), [한국어 메뉴](../../artifacts/four-menu-ko.png), [영어 메뉴](../../artifacts/four-menu-en.png). git에서 제외되는 검사 자료이며 그래픽 모드의 `tests/capture_four.gd`로 다시 만들 수 있습니다.

로컬 프로세스 검사가 통과했다고 다른 PC의 LAN, 인터넷·NAT, 지연, 장시간 성능이나 사람의 재미가 검증된 것은 아닙니다. Steam 로비·초대·App ID 준비와 배포는 [출시 체크리스트](../steam/05-release-checklist.ko.md)에 남겨뒀습니다. 이번 단계의 범위는 [0.4 계획](../superpowers/plans/2026-09-07-four-players.ko.md)에 있습니다.

최종 검증: `python tools/run_tests.py`와 에디터 가져오기 모두 종료 코드 0을 반환했으며 최종 로그에서 스크립트·MTU 오류는 발견하지 못했다.
