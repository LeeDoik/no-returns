# 반품 불가 — 재채기 화물 실행 안내

[English](02-sneezer.en.md)

> **과거 기록 · 2026-09-12 폐기/대체.** 현재 게임은 [PSX 우주 배송 기획](../current/01-overview.ko.md)을 따른다. 아래 구현·실행·아트·수치는 과거 자료이며 현재 상태가 아니다. 삭제된 파일은 경로 기록으로만 남긴다.


> 문서 체계 개정: 이 파일의 버전·수치는 작성 당시 기준입니다. 현재 규칙·미완료 상태는 [문서 홈](../README.md)을 먼저 확인하세요.

**과거 0.2의 기록입니다. 현재 프로젝트는 [접착 상자가 추가된 0.3](03-clinger.ko.md)으로 실행됩니다.** 실행기는 최신 코드를 사용하며 아래 두 화물 수·패킷 측정값·예정 작업은 0.2 당시 내용입니다.

프로토타입 0.2 · 2026-09-07 · Windows · Godot 4.7.2

**일반 상자와 함께 재채기 상자를 플레이할 수 있습니다.** 이번 버전에서는 말썽꾸러기 택배를 조준하는 행동이 알아보기 쉽고 수습할 수 있는 협동 사고로 이어지는지 확인합니다. 혼자 연습하거나 개발용 2인 연결을 사용할 수 있습니다. 방송에서의 재미는 실제 플레이테스트로 확인해야 합니다.

## 1. 바로 실행하기

1. 이전 버전의 게임 창을 닫고 프로젝트 폴더의 PLAY.cmd (`../../PLAY.cmd`; retired file)를 더블클릭합니다.
2. **혼자 연습하기 / PRACTICE ALONE**를 누릅니다. 언어 버튼으로 한국어와 영어를 바꿀 수 있으며 기본은 한국어입니다.
3. 입고 구역 왼쪽에서 분홍 코가 달린 연보라색 상자를 찾습니다. 가까이 가서 **E**로 듭니다. 상자가 둘 다 가까우면 집을 수 있고 닿는 상자 중 가장 가까운 것을 고릅니다. 한 사람은 상자 하나만 듭니다.
4. 마우스로 돌아봅니다. 들고 있을 때 코는 좌우 조준 방향을 따릅니다. **E**로 놓거나 **왼쪽 클릭**으로 던지면 마지막 방향을 유지합니다.
5. 상자가 부풀면 **남은 시간과 바닥의 노란 부채꼴**을 봅니다. 1.5초 뒤 앞쪽으로 재채기합니다. 범위 안의 다른 직원은 밀려나며 들고 있던 상자를 놓고, 다른 상자도 밀려납니다. 재채기 상자 자신과 이를 든 사람은 자신의 재채기에 영향을 받지 않습니다.
6. 둘 중 어느 상자든 민트색 **A 배송구**로 보냅니다. 3분 안에 공동으로 5개를 배송하면 됩니다. 상자는 약 1.2초 뒤 각자의 입고 위치에 돌아옵니다. B는 점수 없이 반송합니다.

실행기는 이 폴더에 준비한 포터블 Godot을 사용하며 Steam 로그인이 필요하지 않습니다. 편집 가능한 프로젝트를 실행하는 방식이며 독립된 Steam 배포본은 아닙니다. EDIT.cmd (`../../EDIT.cmd`; retired file)로 에디터를 열고 F5로 실행할 수 있습니다. 실행 환경이 없다면 [첫 안내의 6번 복원 절차](01-first-playable.ko.md#6-수정하기와-실행-환경-복원)를 따릅니다.

## 2. 조작과 신호

| 입력·신호 | 의미 |
| --- | --- |
| WASD / 마우스 / Space | 이동 / 둘러보기 / 점프 |
| E | 닿는 빈 상자 중 가장 가까운 것을 집거나 받기. 이미 들고 있으면 내려놓기 |
| 왼쪽 클릭 | 든 상자를 일정한 전방·위쪽 힘으로 던지기 |
| Esc | 메뉴 열기·닫기와 마우스 잠금 해제. 근무 시간과 재채기는 계속 진행 |
| 신호음 켜짐 / 꺼짐 | 시작·근무 메뉴에서 합성한 예고음과 재채기 소리 전환 |
| 부풀기·눈 찡그림·남은 시간·바닥 부채꼴 | 곧 해당 방향으로 재채기. 범위 밖이나 창고의 단단한 지형 뒤로 피하기 |
| 바람과 에취! | 재채기 발생. 떨어진 화물을 수습하기 |

위아래 마우스 움직임은 카메라만 조절하고 던지기·재채기는 좌우 방향을 사용합니다. 화물을 들면 0.1의 첫 접촉 예상 표지가 나옵니다. 처음 충돌할 위치를 예상할 뿐, 최종 정지 위치나 이후 재채기의 결과를 뜻하지는 않습니다. 움직이는 대상과 통신 지연에 따라 실제 접촉 위치는 달라질 수 있습니다. 상자의 부풀기는 외형만 바꾸며 충돌체 크기는 유지합니다.

소리를 꺼도 위험을 알리는 화면 표시는 유지됩니다. 신호음과 언어 설정은 현재 실행 중에만 유지됩니다. 최종 오디오 에셋이나 음성 채팅은 추가하지 않았으며 짧은 기능 확인용 소리는 코드로 합성합니다.

## 3. 함께 해볼 사고 실험

PLAY_TWO.cmd (`../../PLAY_TWO.cmd`; retired file)를 실행하고 방장 창에 **2 / 2 직원**이 표시되면 그 창에서 **근무 시작**을 누릅니다. 같은 PC에 게임 창 두 개를 여는 방식이므로 창을 바꿔 선택하며 각 직원을 조작합니다. 키보드 하나로 두 사람이 동시에 조작하는 방식은 아닙니다.

다음 세 가지를 짧게 해봅니다.

1. 한 명은 재채기 상자를 들고, 다른 사람은 일반 상자를 듭니다. 코를 동료 쪽으로 조준해 예고·밀려남·화물 낙하·수습을 확인합니다.
2. 예고가 끝나기 전에 코를 다른 방향으로 돌리거나 단단한 칸막이 뒤로 피합니다. 사고를 의도적으로 막을 수 있고 그 이유가 눈에 보이는지 확인합니다.
3. 재채기 상자를 일반 상자 쪽으로 향하게 내려놓고 기다립니다. 재채기로 화물을 옮기는 행동이 배송에 도움이 되는지, 오히려 일을 늘리는지 봅니다.

매번 예고를 알아챘는지, 방향을 이해했는지, 사고가 웃겼는지, 수습이 너무 오래 걸리지 않았는지를 적습니다. 혼자서는 상자 밀기를 볼 수 있지만 협동의 재미는 동료가 있어야 판단할 수 있습니다. 아래 수치는 이 실험을 거친 뒤 조정합니다.

## 4. 현재 수치와 연결 범위

| 규칙 | 프로토타입 수치 |
| --- | --- |
| 화물 / 직원 | 일반·재채기 상자 / 1인 연습 또는 연결된 직원 2명 |
| 근무 | 3분 안에 A로 공동 배송 5개 |
| 쉬는 시간 | 최초 6초, 이후 무작위로 6~9초 |
| 예고 / 분출 | 1.5초 / 0.35초 |
| 재채기 범위 | 수평 거리 4.5m, 부채꼴 전체 각도 100도, 높이 차 최대 1.6m |
| 직원 밀기 | 수평 7m/s를 더하며 최대 12m/s. 위쪽 속도 최소 3.8m/s, 몸 기울임 0.5초 |
| 밀린 뒤 회복 | 수평 밀기 속도는 14m/s²로 감소. 일반 이동은 계속 가능 |
| 다른 화물 밀기 | 전방 8m/s·위쪽 4m/s를 더하며 전체 속도 최대 16m/s |
| 집기 / 화물 복구 | 2.4m / 1.2초 |

호스트가 주기를 정하고 소유권·적중·물리·점수를 계산합니다. 손님은 초당 20번 전송받는 확정 상태를 표시합니다. 호스트·근무별 식별자와 이벤트 번호를 함께 사용해 같은 상태를 여러 번 받아도 재채기가 반복 재생되지 않으며 다른 호스트에게 재접속해도 작동합니다. 복구 중 숨긴 화물은 돌아올 때까지 충돌에서 제외합니다. 방에서 나가기, 근무 종료와 재시작은 대기 중인 효과를 취소합니다.

일반 연결은 **ENet / UDP 27842**를 사용합니다. 자동 검증은 이 PC의 두 프로세스에서 수행했습니다. 다른 PC의 LAN, 인터넷·NAT, 지연·패킷 손실 조건은 아직 검증하지 않았습니다. Steam 로비·친구 초대·App ID·Steam 배포본은 미구현입니다. 두 사람은 같은 프로토타입 버전을 사용해야 합니다. 손님이 나가면 방장은 대기 상태로, 방장이 나가면 손님은 메뉴로 돌아갑니다. 방장 이전이나 근무 중 참가는 지원하지 않습니다.

## 5. 검증 결과와 남은 범위

프로젝트 폴더에서 다음 명령으로 검사합니다.

```powershell
python tools/run_tests.py
.\.tools\godot\Godot_v4.7.2-stable_win64_console.exe --headless --path . --log-file final-import.log --editor --quit
```

최종 전체 실행에서 개별 스크립트 5개와 방장·손님 프로세스 쌍 2개가 모두 통과했으며 검사기는 종료 코드 0을 반환했습니다. 에디터 가져오기도 스크립트 오류 없이 종료 코드 0으로 끝났습니다. 연결 테스트는 플레이와 별개인 UDP **27943**, **27944**를 사용합니다. 로그는 `artifacts/`에 있습니다.

- 기존 화물 규칙·운반/던지기 물리·근무 흐름 검사를 유지했습니다. 정적 투척 표지 5개 조건은 허용 오차 0.20m 안에 들었습니다.
- 재채기 주기·범위 규칙은 예고 시간, 갱신당 한 단계 전환, 분출 한 번, 무작위 간격 범위, 취소와 잘못된 입력을 검사합니다.
- 실제 장면에서는 두 사람의 동시 운반, 거리 경계에서 이동 중 집기, 재채기 화물의 공동 점수 반영, 직원·상자의 낙하와 밀림, 운반자 면역, 벽 차폐, 복구와 재시작을 검사합니다.
- 다른 호스트에서 연출이 누락되는 문제와 복구 중 보이지 않는 상자에 걸리는 문제를 테스트로 먼저 재현한 뒤 수정해 통과시켰습니다. 반복 상태 수신에는 신호를 한 번만 표시하고, 호스트·손님 모두 복구 뒤 충돌을 되살립니다.
- 실제 프로세스 두 쌍에서 기존 배송·접속 종료·재참가와 손님이 든 재채기 상자의 예고, 양쪽의 같은 적중·이벤트, 실제 밀린 이동, 중복 재생 방지를 확인했습니다. 관측된 직렬화 상태의 최대 크기는 **1,180바이트**로 **테스트 상한 1,280바이트**보다 작았습니다. 최종 실행에서 앞서 발생한 ENet MTU 경고는 사라졌습니다. 이 수치는 검사한 2인 상태에 대한 측정입니다.
- 코드 검토에서 발견한 P2 문제 2개를 수정했으며 후속 검토에서 검토 범위 내의 남은 P1/P2는 발견하지 못했습니다.
- 실제 Compatibility 렌더러로 한국어·영어 메뉴, 예고, 분출, 음소거 근무 메뉴를 저장하고 글자와 배치를 확인했습니다. 이는 화면 검사이며 청취 테스트나 사람의 재미 평가는 아닙니다.

샌드박스에서는 기존 루트 인증서 저장소와 `user://` 캐시·프로파일러 폴더 관련 오류가 출력됐습니다. GDScript 오류와는 별개이며 검사와 화면 저장을 막지 않았습니다. 소리 합성과 음소거 경로는 실행했지만 다른 기기의 음질과 적정 음량은 사용자가 들어보며 확인해야 합니다.

실제 장면 캡처: 예고 (`../../artifacts/sneezer-windup.png`; retired file), 분출 (`../../artifacts/sneezer-burst.png`; retired file), 한국어 메뉴 (`../../artifacts/sneezer-menu-ko.png`; retired file), 영어 메뉴 (`../../artifacts/sneezer-menu-en.png`; retired file), 음소거 메뉴 (`../../artifacts/sneezer-pause-muted.png`; retired file). 이 로컬 검사 파일은 git에서 제외됩니다. 캡처용 장면 설정은 `tests/capture_sneezer.gd`이며 그래픽 렌더러로 실행해야 합니다.
