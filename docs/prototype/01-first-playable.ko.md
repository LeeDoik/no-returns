# 반품 불가 — 첫 프로토타입 실행 안내

[English](01-first-playable.en.md)

> **과거 기록 · 2026-09-12 폐기/대체.** 현재 게임은 [PSX 우주 배송 기획](../current/01-overview.ko.md)을 따른다. 아래 구현·실행·아트·수치는 과거 자료이며 현재 상태가 아니다. 삭제된 파일은 경로 기록으로만 남긴다.


> 문서 체계 개정: 이 파일의 버전·수치는 작성 당시 기준입니다. 현재 규칙·미완료 상태는 [문서 홈](../README.md)을 먼저 확인하세요.

버전 0.1 · 2026-09-07 · Windows · Godot 4.7.2

**과거 0.1의 기록입니다. 현재 프로젝트는 [재채기 화물이 추가된 프로토타입 0.2](02-sneezer.ko.md)로 실행됩니다.** 아래 실행기·기본 조작·환경 복원 절차는 계속 참고할 수 있습니다. 상자 하나·소리 미구현 등의 제한과 다음 실험은 0.1 당시 내용입니다. 현재 검사기에는 재채기 검사와 UDP 27944를 쓰는 프로세스 쌍도 추가됐습니다.

이번 버전은 **3인칭 조작과 공유 화물의 기본 배송을 확인하는 첫 개발용 프로토타입**입니다. 혼자 연습하거나 같은 PC에서 두 창을 연결할 수 있습니다. 실제로 살아 움직이는 특수 화물과 Steam 친구 초대는 다음 단계입니다. 최종 게임의 2~4인·10~15분 기획과 달리, 이번 실험은 1인 연습 또는 2인 연결, 배송 5개, 제한 시간 3분으로 작게 만들었습니다.

## 1. 지금 실행하기

1. 프로젝트 폴더에서 PLAY.cmd (`../../PLAY.cmd`; retired file)를 더블클릭합니다.
2. `NO RETURNS` 화면에서 **혼자 연습하기**를 누릅니다.
3. 노란색 작업자와 입고 구역의 상자가 보이면 준비 완료입니다. 가까이에서 **E**를 눌러 상자를 듭니다.
4. 민트색 **A 배송구**로 가져가 **E**로 놓거나 왼쪽 클릭으로 던집니다. 상자가 배송구에 들어가면 점수가 올라갑니다.
5. 상자는 입고 구역에 다시 나옵니다. 3분 안에 5개를 배송하면 근무 완료 화면이 표시됩니다. **다시 근무하기**로 재시작합니다.

현재 폴더에는 실행에 필요한 Godot 포터블 환경을 준비했습니다. 별도 엔진 설치나 Steam 로그인이 필요하지 않습니다. `PLAY.cmd`는 포터블 Godot으로 프로젝트를 실행합니다. 독립된 Windows 배포본이나 Steam 출시 빌드는 아직 아닙니다.

## 2. 조작

| 입력 | 동작 |
| --- | --- |
| WASD | 카메라 방향을 기준으로 이동 |
| 마우스 | 시점 회전 |
| Space | 점프 |
| E | 가까운 화물 집기·공중에서 받기 / 들고 있으면 내려놓기 |
| 왼쪽 클릭 | 들고 있는 화물 던지기 |
| Esc | 메뉴 열기·닫기, 마우스 잠금 해제 |
| 메뉴의 English / 한국어 | UI 언어 전환. 기본은 한국어 |

현재 던지기는 일정한 힘과 위쪽 각도를 사용합니다. 마우스의 좌우 방향으로 던지며 위아래 시점은 카메라만 움직입니다. 화물을 들면 예상 첫 접촉 위치에 표지가 나옵니다. 착지 후 구르거나 튀는 최종 정지 위치까지 보장하는 표지는 아닙니다.

메뉴를 열거나 다른 창으로 이동하면 자신의 입력이 멈춥니다. 근무 시간은 계속 흐릅니다. 돌아오면 **근무로 돌아가기**를 누르세요. 배경 창과 전경 창을 오가며 조작할 때도 같습니다.

## 3. 같은 PC에서 두 창 연결하기

1. 이미 실행 중인 방이 있다면 메뉴로 나갑니다. 기본 포트의 방은 하나만 열 수 있습니다.
2. PLAY_TWO.cmd (`../../PLAY_TWO.cmd`; retired file)를 실행합니다. 방장 창과 참가 창이 열립니다.
3. 방장 창에 **직원 집합 완료**와 **2 / 2 직원**이 표시되는지 확인합니다.
4. 방장 창의 **근무 시작**을 누릅니다.
5. 각 창을 번갈아 선택해 이동·집기·던지기를 확인합니다. 손님은 민트색 작업자입니다. 키보드 한 개로 두 사람을 동시에 조작하는 모드는 아닙니다.

직접 연결하려면 첫 번째 `PLAY.cmd` 창에서 **방 만들기 / 2인**, 두 번째 창에서 주소 `127.0.0.1`을 유지하고 **창고 참가하기**를 누르면 됩니다.

호스트가 최종 위치·화물 소유권·점수를 결정합니다. 손님이 나가면 들고 있던 화물을 놓고 대기 상태로 돌아갑니다. 새 동료가 참가하면 새 근무를 시작할 수 있습니다. 방장이 나가면 손님에게 종료 이유를 표시하고 메뉴로 돌아갑니다. 근무 도중 참가는 지원하지 않습니다.

## 4. 다른 PC와 Steam의 현재 범위

개발 통신은 **ENet / UDP 27842 / 최대 2인**입니다. 같은 LAN에서 시험하려면 두 PC에 같은 프로젝트와 실행 환경을 준비하고, 참가자가 방장 PC의 LAN 주소를 입력합니다. Windows 방화벽이나 네트워크 정책이 연결을 막을 수 있습니다. 다른 PC에서의 성공은 아직 확인하지 않았습니다.

같은 PC의 두 프로세스 연결을 검증했으며, 인터넷의 다른 네트워크·NAT·Steam 로비·친구 초대·오버레이·실제 Steam App ID 연동은 미검증 또는 미구현입니다. 지금의 주소 입력은 개발용이며 글로벌 출시용 참가 화면으로 확정한 것이 아닙니다. [온라인·빌드 계획](../steam/04-online-and-build-plan.ko.md)의 Steam 단계는 계속 미완료입니다.

## 5. 잘 안 될 때

| 증상 | 확인할 내용 |
| --- | --- |
| Godot runtime missing | 아래 실행 환경 복원 절차 사용 |
| 방을 만들지 못함 | 같은 포트를 사용 중인 이전 방을 메뉴로 종료 |
| 연결하지 못함 | 방이 먼저 열렸는지, 주소가 맞는지 확인. 같은 PC는 127.0.0.1 |
| 연결 중에서 기다림 | 최대 10초 뒤 실패 안내. 기다리는 중에도 메뉴로 나갈 수 있음 |
| 마우스가 잠김 | Esc로 해제 |
| 캐릭터가 움직이지 않음 | 근무 시작 여부와 일시정지 메뉴 확인. 메뉴에서 근무로 돌아가기 |
| 상자가 사라짐 | 배송·반송 후 약 1.2초 뒤 입고 구역 확인 |
| B에 넣었는데 점수가 안 오름 | 목적지는 A. B는 화물을 반송하며 점수가 오르지 않음 |

## 6. 수정하기와 실행 환경 복원

EDIT.cmd (`../../EDIT.cmd`; retired file)를 실행하면 Godot 에디터에서 프로젝트가 열립니다. **F6은 선택한 장면**, **F5는 프로젝트 실행**입니다. 게임의 기본 장면은 `scenes/main.tscn`이며 창고와 UI는 GDScript로 생성합니다. 따라서 편집 화면에 모든 도형이 미리 보이지 않아도 정상입니다.

소스만 새로 받았거나 `.tools` 폴더가 없다면 프로젝트 폴더에서 PowerShell로 다음을 실행합니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/setup_godot.ps1
```

이 명령은 공식 Godot **4.7.2 일반판 Windows x64**만 프로젝트 내부에 내려받습니다. 시스템 전체 설치나 영구 실행 정책 변경은 하지 않습니다. 버전 고정 주소와 공식 SHA512 값으로 압축 파일을 검사한 후 풉니다. 준비 완료 메시지 뒤 `PLAY.cmd`를 실행합니다. 다운로드 크기는 약 86MB이며 풀린 실행 파일은 약 181MB입니다.

확인된 엔진 버전은 `4.7.2.stable.official.ed1daf0bf`입니다. `_sc_` 파일로 에디터 설정·캐시를 포터블 폴더에 보관합니다. 사용자 데이터의 실제 위치와 플랫폼별 동작은 [Godot 경로 안내](https://docs.godotengine.org/en/stable/tutorials/io/data_paths.html)를 참고합니다.

공식 출처: [Windows 다운로드](https://godotengine.org/download/windows/), [버전별 실행 파일과 체크섬](https://github.com/godotengine/godot-builds/releases/tag/4.7.2-stable), [Godot 라이선스](https://github.com/godotengine/godot/blob/4.7.2-stable/LICENSE.txt), [제3자 고지 원문](https://github.com/godotengine/godot/blob/4.7.2-stable/COPYRIGHT.txt). 공개 재배포 전에 실제 배포물의 엔진·외부 구성요소 고지를 준비하고 이용자가 읽을 수 있게 제공해야 합니다. 이번 폴더는 로컬 개발 실행용이며 공개 배포 묶음을 만들지 않았습니다.

## 7. 자동 검증

프로젝트 폴더에서 실행합니다. Python은 테스트 실행용이며 일반 플레이에는 필요하지 않습니다.

```powershell
python tools/run_tests.py
```

화물 규칙, 물리 회귀, 근무 흐름과 실제 두 프로세스 연결 테스트가 모두 성공하면 종료 코드 0을 반환합니다. 실패하거나 제한 시간을 넘으면 0이 아닌 코드로 끝납니다. 상세 로그는 `artifacts/`에 남습니다. 두 프로세스 테스트는 일반 플레이와 다른 UDP **27943** 포트를 사용합니다.

확인한 항목:

- 화물 규칙 6개 그룹, 45개 검증: 동시 집기, 잘못된 좌표·거리·ID, 소유자만 놓기, 중복·오답·보유 중 배송 거부, 초기화와 접속 종료.
- 실제 Godot 두 프로세스: 참가, 호스트가 계산한 손님 이동, 양쪽의 집기·던지기 확인, 타인의 던지기 거부, 배송 점수 공유.
- 손님이 화물을 들고 나갈 때 화물 해제·대기실 복귀, 재참가, 방장 종료와 손님에게 표시되는 이유.
- 실제 창고에서 오답 배송·분실 화물의 복구, 배송 5개 성공, 시간 종료와 두 결과의 재시작, 잘못된 이동 입력 거부.
- 칸막이 앞 운반·내려놓기 충돌과 다섯 투척 조건의 첫 접촉 표지 오차. 현재 정적 창고의 허용 오차는 0.20m.
- 실제 Compatibility 렌더러의 메뉴·창고 화면을 저장해 한국어 표시와 배치를 확인.

물리 회귀 검증과 검토 결과는 [물리 수정 보고서](physics-fix-report.ko.md), 화물 규칙의 최초 실패·성공 근거는 [규칙 테스트 보고서](cargo-rules-report.ko.md)에 기록합니다. 외부 PC, 인터넷 지연, 장시간 플레이, 상용 최소 사양을 검증한 결과로 확대 해석하지 않습니다.

## 8. 현재 제한과 다음 실험

일반 상자 한 종류만 있습니다. 재채기·접착 화물, 4인, Steam 연동, 소리, 게임패드, 설정 저장, 감도 조절, 본격적인 지연 보정, 최종 아트, 독립 실행 배포본은 아직 없습니다. 영어 원문과 한국어 UI·문서는 함께 관리합니다. 상점의 최종 게임 설명과 이 작은 실험의 구현 범위를 구분하세요.

다음 작업은 **재채기 화물 한 종류를 추가해 동료를 도우려다 사고가 나는지 확인하는 것**입니다. 먼저 이번 버전에서 이동·카메라·집기·던지기가 이해하기 쉬운지 확인하고, 효과가 예고되는 재채기로 다른 화물을 밀어내는 상호작용을 붙입니다. 현재 기획의 본격적인 방송 재미를 판단하는 단계는 그 이후입니다.
