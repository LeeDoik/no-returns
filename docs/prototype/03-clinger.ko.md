# 반품 불가 — 접착 상자 실행 안내

[English](03-clinger.en.md)

**과거 0.3의 기록입니다. 현재 프로젝트는 [2~4인을 지원하는 0.4](04-four-players.ko.md)입니다.** 아래 2인 제한과 패킷 측정값은 0.3 당시 내용입니다.

프로토타입 0.3 · 2026-09-07 · Windows · Godot 4.7.2

**일반·재채기 상자에 접착 상자를 추가했습니다.** 직원이나 다른 상자에 붙고, 재채기로 떼어낼 수 있습니다. 말썽 많은 택배를 협동 도구로 활용한다는 기존 기획을 확인하는 단계입니다. 사용자가 0.2의 정상 작동을 확인했으며 외부 멀티플레이나 재미를 평가한 결과는 아닙니다.

## 바로 실행하기

이전 게임 창을 닫고 [PLAY.cmd](../../PLAY.cmd)를 더블클릭한 뒤 **혼자 연습하기**를 누릅니다. 필요하면 언어 버튼을 사용합니다. 입고 구역 오른쪽의 **CLINGER / A** 표시에서 접착판이 돌출된 연두색 상자를 찾습니다.

처음 1초의 유예가 지난 뒤 가까이 걸어가 닿아보세요. 5초간 붙으며 평소 이동 속도가 70%로 줄지만 이동과 점프는 계속 가능합니다. 연결 표시와 남은 시간이 붙은 상태를 알려줍니다. 시간이 지나 떨어지기를 기다리거나, 동료가 재채기 상자를 붙은 상자에 조준해 일찍 떼어낼 수 있습니다. 떨어지는 접착 상자도 재채기에 밀려납니다.

E로 빈 상자를 집거나 든 상자를 놓고 왼쪽 클릭으로 던집니다. 들고 있는 접착 상자는 다른 대상에 붙지 않습니다. 붙은 접착 상자를 직접 집을 수는 없습니다. 떨어진 뒤 다시 붙지 않는 2초 동안은 일반적으로 집을 수 있습니다. WASD는 이동, 마우스는 둘러보기·조준, Space는 점프, Esc는 메뉴입니다. 메뉴를 열어도 시간과 화물 행동은 계속됩니다. 한국어·영어 전환과 합성 신호음 음소거는 유지하며 설정은 재실행 시 저장되지 않습니다.

세 종류 모두 **A**로 보냅니다. 목표는 여전히 3분 안에 배송 5개이며 B는 점수 없이 반송합니다. 접착 상자가 다른 상자에 붙은 상태에서 대상 상자를 정상 출고하면 둘을 각각 한 번씩 세고 각자의 입고 위치로 돌려보냅니다. 따라서 대상 상자를 들면 한 개의 운반 자리로 택배 두 개를 옮길 수 있습니다.

## 짧게 해볼 두 가지 실험

[PLAY_TWO.cmd](../../PLAY_TWO.cmd)를 실행하고 방장 창에 직원 두 명이 모이면 **근무 시작**을 누릅니다. 같은 PC에서는 창을 바꿔 선택하며 각각 조작합니다. 그 PC에 키보드 두 개를 연결한다고 서로 다른 플레이어를 동시에 조작하는 방식은 아닙니다.

1. **동료 구출하기.** 동료에게 접착 상자가 붙게 합니다. 재채기 상자를 들고 코를 붙은 상자에 조준하며 예고를 봅니다. 재채기는 접착을 풀지만 동료도 밀 수 있습니다. 구출 시도가 유용했는지, 웃겼는지, 짜증만 났는지 확인합니다.
2. **두 상자 묶어 배송하기.** 접착 상자를 일반 상자 옆으로 운반해 닿을 만큼 가까이 놓고 물러납니다. 일반 상자가 가장 가까운 대상이 되면 붙습니다. 일반 상자를 들어 5초의 접착 시간이 끝나기 전에 둘을 A로 보냅니다. 각각 한 번씩 점수가 올라야 합니다. 시간이 끝나면 접착 상자가 떨어지므로 다시 회수할 수 있습니다.

혼자서도 자신에게 붙이거나 상자끼리 묶을 수 있습니다. 이 상호작용을 확장할 가치가 있는지는 실제 동료와 확인해야 합니다. 그 판단이 설 때까지 기본 도형 아트를 유지합니다.

## 규칙과 복구

| 규칙 | 현재 수치·동작 |
| --- | --- |
| 활성 종류 | 일반·재채기·접착 상자, 각각 하나 |
| 접착 | 직원 가슴 또는 다른 화물 중심 0.95m 안의 유효 대상 중 가장 가까운 대상. 지형이 가리지 않아야 함 |
| 지속 시간 | 5초 |
| 직원 이동 | 붙어 있는 동안 평소 속도의 70%. 조작 가능 |
| 다시 붙기까지 | 떨어진 뒤 2초, 생성·복구 뒤 1초 |
| 대상 제한 | 직원 하나 또는 접착 상자가 아닌 화물 하나. 연쇄 접착 없음 |
| 따라가기 | 닿은 순간의 상대 위치를 유지. 단단한 벽에 막히거나 대상이 2m 넘게 이동하면 분리 |
| 재채기 | 기존 1.5초 예고 유지. 붙은 접착 상자에 적중하면 떼어내고 밀기 |
| 반송 | 배송·복구 후 1.2초 |

대상 소실, 오답·분실 대상의 복구, 근무 종료, 나가기와 재시작에도 접착을 풉니다. 오답·분실 복구에는 묶음 배송 점수를 주지 않습니다. 바닥 접촉 오차를 허용하려고 이동 충돌 검사에 면별 1mm의 여유를 두되 실질적인 벽 통과는 막습니다. 부풀기와 접착판은 외형이며 기본 충돌 상자 크기는 유지합니다.

호스트가 접착·분리·이동·점수를 결정하고 손님은 전송된 상태를 표시합니다. 화물이 세 개여도 기존 패킷 상한을 유지하도록 전송 형식을 고정된 배열로 정리했으므로 두 사람은 같은 버전을 사용해야 합니다. 현재는 **ENet / UDP 27842의 2인 연결**이며 이 PC의 별도 프로세스에서 검증했습니다. 다른 PC의 LAN, 인터넷·NAT, 패킷 손실·지연, Steam 로비·친구 초대와 4인은 미검증 또는 미구현입니다. [실행 환경 복원](01-first-playable.ko.md#6-수정하기와-실행-환경-복원)과 [Steam 준비](../steam/05-release-checklist.ko.md)는 별도 안내를 참고합니다.

## 검증 결과

프로젝트 폴더에서 실행합니다.

```powershell
python tools/run_tests.py
.\.tools\godot\Godot_v4.7.2-stable_win64_console.exe --headless --path . --log-file final-import.log --editor --quit
```

최종 검사에는 개별 스크립트 8개와 실제 방장·손님 프로세스 쌍 3개가 있으며 제한 시간 안에 실행합니다. 기존 소유권·물리·근무·재채기, 간결한 상태 직렬화, 접착 제어기, 실제 접착 상자의 수명주기, 두 프로세스 접착·구출을 검사합니다. 테스트 포트는 27943·27944·27945이며 로그는 `artifacts/`에 있습니다.

접착 제어기 검사는 모듈이 없는 상태에서 먼저 실패한 뒤 구현 후 통과했습니다. 추가 바닥 접촉 검사에서 곧바로 떨어지는 문제를 발견했고 면별 1mm의 충돌 검사 여유를 적용한 뒤 통과했습니다. 실제 main 장면에서는 붙은 상자의 집기 거부, 들고 있는 묶음의 이동, 두 개의 중복 없는 배송, 복구 뒤 감속 해제, 재시작·메뉴 복귀 취소를 확인합니다. 기존 일반 상자 선택 검사는 새 접착 상자를 검사 위치에서 멀리 두어, 가까이 생긴 새 상자 대신 원래 검사하던 상자를 계속 대상으로 삼습니다.

두 프로세스 접착 검사에서는 같은 대상·남은 시간, 따라가는 이동, 감속, 재채기 분리, 정상 속도 복귀와 접속 종료를 확인했습니다. 접착 연결 검사에서 관측한 가장 큰 상태는 **992바이트**로 **상한 1280바이트** 안에 들었고 세 종류 상태 왕복 검사는 **976바이트**였습니다. 검사한 상태의 측정이며 모든 네트워크 환경을 보장하는 수치는 아닙니다. 코드 검토에서는 확정할 수 있는 신규 P1/P2 결함을 발견하지 못했습니다. 검토에서 언급한 수명주기 검사 공백은 실제 main 장면 통합 검사로 보완했습니다.

동작 검사와 에디터 가져오기는 스크립트 오류 없이 종료 코드 0으로 끝났습니다. 기존 샌드박스 인증서와 `user://` 폴더·캐시 오류는 계속 출력되어 게임플레이 실패와 별도로 기록했습니다. 실제 한국어·영어 메뉴와 접착·구출 화면도 확인했습니다. 소리 청취, 장시간 플레이, 사람의 재미 판단과 원격 연결은 추가 확인이 필요합니다.
