# 코드 없이 맵 편집하기

[English](map-editing.en.md)

대상: Godot 4.7.2, NO RETURNS 0.7.6 · 2026년 9월 8일.

## 첫 편집: 중앙 낮은 벽 옮기기

1. 게임 창을 닫고 프로젝트 폴더의 [EDIT_MAP.cmd](../../EDIT_MAP.cmd)를 두 번 클릭합니다. Godot에서 `shipping_shrine.tscn`이 열립니다. 위쪽 **3D**를 선택합니다.
2. 왼쪽 **씬(Scene)** 목록에서 `ShippingShrine → Geometry → LowDivider`를 선택합니다. 선택한 것이 중앙 낮은 벽입니다.
3. 오른쪽 **인스펙터(Inspector) → Node3D → Transform → Position**을 펼칩니다. X를 `1`에서 `3`으로 바꾸고 Enter를 누릅니다. 벽이 오른쪽으로 2m 이동합니다. Y는 높이, Z는 앞뒤입니다. 3D 화면의 축 화살표를 끌어도 됩니다.
4. LowDivider 아래 **Solid1**을 선택합니다. 위쪽 **Dimensions**의 X/Y/Z는 벽의 가로/높이/두께입니다. 값을 바꾸면 보이는 벽과 충돌 범위가 함께 바뀝니다. 바닥에 맞추려면 Position Y를 높이의 절반으로 둡니다. 벽·바닥 크기는 Scale보다 Dimensions로 조절하세요.
5. **Ctrl+S**로 저장하고 **F5**로 전체 게임을 실행합니다. 메뉴에서 혼자 캠페인을 시작해 벽 위치와 충돌을 확인합니다. **F6**는 맵 씬만 실행하므로 직원과 게임 메뉴가 나오지 않습니다.
6. 편집으로 돌아와 **Ctrl+Z**로 변경을 취소하거나 값을 다시 바꾸고 저장합니다. 저장한 씬을 이후 게임이 그대로 사용하며 실행할 때 자동 생성으로 덮어쓰지 않습니다.

처음에는 벽 하나만 움직여 보세요. 프로젝트의 `scenes/maps/shipping_shrine.tscn`이 맵 원본입니다. 코드를 열 필요가 없습니다. `main.tscn`의 인스턴스보다 이 원본 씬을 직접 편집하세요.

## 벽을 추가하거나 색 바꾸기

왼쪽 아래 **파일시스템(FileSystem)**에서 `scenes/pieces/solid_block.tscn`을 찾습니다. 이 파일을 왼쪽 씬 목록의 `Geometry` 위로 끌어 놓아 벽을 추가합니다. 새 SolidBlock의 Position, Dimensions, Color를 오른쪽에서 바꿉니다. 기본 크기는 2×2×0.5m입니다. 배치한 벽을 선택하고 **Ctrl+D**로 복제할 수도 있습니다. 이 블록에는 충돌이 포함되어 있습니다.

단순 장식 메시를 가져오면 자동으로 충돌이 생기지는 않습니다. 처음에는 이 블록을 벽·장애물·발판으로 재사용하세요. 복제한 블록의 크기와 색은 다른 블록과 독립적으로 바뀝니다. 선반처럼 여러 조각으로 된 물체는 부모를 선택해 이동하고, 크기는 내부 구성도 확인하며 조절합니다.

## 배송 범위·쥐 행동·맵 확장

- 배송 범위: `DispatchA/B → DeliveryZone → CollisionShape3D → Shape → Size`에서 조절합니다. 투명한 편집 도형이 판정 범위입니다. 배송 판정은 상자의 중심이 이 범위에 들어오면 발생합니다. 혀 외형만 키워도 판정은 커지지 않습니다.
- 쥐: `PackratTerritory/StartPoint`가 첫 위치, `ReturnPoint`가 훔친 화물을 내려놓는 위치입니다. 반환점을 벽이나 둥지 장식 안에 두지 마세요. `PatrolPoints/Point1…4`는 목록 순서대로 순찰하는 경유점입니다. `ActivityZone/CollisionShape3D/Shape/Size`는 이동·탐색 구역입니다. 쥐는 계약 2부터 나타납니다. 현재 AI는 복잡한 벽을 돌아가는 길찾기가 없으므로 경유점 사이를 열린 통로로 연결하세요.
- 시작점: 직원 Y는 기본 `0.05`, 화물 Y는 기본 `0.55`입니다. 바닥 높이를 바꾸면 함께 조정하고 직원끼리·상자끼리 겹치지 않게 둡니다.
- 맵 확대: 먼저 Floor의 Dimensions를 키우고 OuterWalls를 옮깁니다. 이어서 `PlayableBounds/CollisionShape3D/Shape/Size`와 위치를 바꿔 새 영역을 포함합니다. 이 범위 밖으로 나간 화물은 복귀합니다. 기본 바닥은 48×60m이며 경계 판정에는 여유 폭이 있습니다. 조명·시작점·순찰점도 새 배치에 맞춰 조절하세요.
- 벨트: 기본 2.2×6m입니다. 통째로 이동·회전하는 것을 우선 사용하세요. 길이를 바꾸려면 바닥·띠 장식·TransportZone을 함께 맞춰야 하며 띠 애니메이션 길이는 코드에 남아 있습니다.

## 표지판과 조명

표지판 Label3D를 선택하고 Inspector 위쪽 **English / Korean** 두 칸을 함께 수정합니다. **Text**는 자동 표시 값이므로 이 칸만 바꾸면 다시 덮어써집니다. 에디터에는 한국어, 게임에는 설정한 언어가 표시됩니다. 새 상용 문구의 원문은 영어로 유지합니다.

천장 조명을 선택해 Position Y를 높이거나 Light의 Energy를 줄이면 눈부심을 줄일 수 있습니다. 기본 조명 높이는 6.5m입니다. 바닥만 크게 늘리면 조명이 부족한 구역이 생길 수 있습니다. 얼굴·사장상에 붙은 작은 움직임은 저장한 위치를 기준으로 게임 안에서만 작동합니다.

## 저장한 맵을 친구와 실행하기

**Ctrl+S → F5**는 소스 프로젝트의 최신 맵을 시험합니다. 이미 만들어진 EXE는 자동으로 바뀌지 않습니다. 게임 창을 닫고 [BUILD.cmd](../../BUILD.cmd)를 두 번 클릭하세요. 검사가 통과하면 새 EXE와 ZIP의 경로를 표시합니다. 이 PC에 준비된 Python·Godot·내보내기 템플릿을 사용합니다. 다른 PC의 준비 방법은 [빌드 인계](../steam/07-build-handoff.ko.md)를 참고하세요.

친구에게 `build/NO_RETURNS_0.7_Windows.zip`을 새로 전달하고 모두 같은 ZIP을 풀어 실행합니다. 소스 실행과 내보낸 빌드를 섞지 마세요. 네트워크 프로토콜 9은 저장된 맵과 종속 리소스의 지문을 확인하며 다르면 입장을 거절합니다. 맵 자동 다운로드나 플레이 중 편집 공유는 지원하지 않습니다.

## 문제가 생기면

- 게임에서 위치가 그대로: 다른 씬을 편집했거나 저장 전일 수 있습니다. `shipping_shrine.tscn`을 저장하고 실행 중인 게임을 재시작하세요. EXE라면 BUILD.cmd도 실행합니다.
- 직원이 안 보임: F6 대신 F5를 누르고 메뉴에서 캠페인을 시작합니다.
- 벽을 통과함: 충돌 없는 장식인지 확인하고 SolidBlock을 사용합니다. 블록 내부 메시만 키우지 말고 Dimensions를 수정합니다.
- 쥐가 멈춤: 순찰·반환점까지의 통로를 확인합니다. 벽을 우회하는 복잡한 길은 아직 자동으로 찾지 못합니다.
- 노란 경고나 실행 오류: `Gameplay`, 배송구·벨트·시작점 등 필수 항목의 이름을 바꾸거나 지우지 마세요. 루트에는 누락된 필수 항목에 대한 경고가 있습니다. 바로 한 편집은 Ctrl+Z로 복구하고 저장합니다.

큰 변경 전에 씬 파일을 프로젝트 밖에 복사해 백업하거나 Git 기록을 남깁니다. [로컬 버전 관리와 복구](version-control.ko.md). 맵 외 파일을 포함한 전체 초기화는 하지 마세요.

## 구현·검증 기록

실행 시 생성하던 맵을 저장된 PackedScene으로 전환했습니다. 시각 배치와 판정이 같은 씬을 읽습니다. 이전 생성 코드는 일회성 변환·기존 검사 지원용이며 일반 게임 실행에는 쓰지 않습니다. 옮기고 회전한 배송구·벨트, 저장/재로드, 직원·화물 시작점 연결, 실제 배송 보상, 블록 외형/충돌 크기 일치와 인스턴스 독립성, 서로 다른 맵의 온라인 입장 거절을 자동 검사합니다.

[Godot PackedScene 공식 문서](https://docs.godotengine.org/en/4.3/classes/class_packedscene.html)는 씬의 저장·인스턴스화와 소유 노드 저장 방식을 설명합니다. [전환 계획](../superpowers/plans/2026-09-07-editable-map.ko.md).


## 0.7.4 확장 맵과 새 장치

바닥은 **48×60m**로 기존보다 면적이 **2.5배** 커졌습니다. 배송구는 북쪽 끝의 X±15, Z-43에 있습니다. 기존 입고장과 쥐 구역을 지나 중앙의 인수인계 쉼터에서 상자를 모으거나 동료에게 넘긴 뒤 경로를 고릅니다.

| 경로 | 작동과 선택 |
| --- | --- |
| 왼쪽 안전한 야근길 | 항상 열린 우회로. 장치 타이밍을 신경 쓰지 않고 운반합니다. |
| 중앙 무급 문지기 | 앞/뒤 노란 발판에 서거나 자유 상자를 내려놓으면 문이 열립니다. 발판을 떠나도 6초 유지하여 혼자 통과할 수 있습니다. 문 안에 직원/상자가 있으면 닫히지 않습니다. |
| 오른쪽 특급 바람 배송 | 5초 대기 → 1.5초 노란 예고 → 2.5초 청록 송풍. 화살표 방향으로 바닥의 직원과 자유 화물을 밀어냅니다. 상자를 먼저 보내고 동료가 받을 수도 있습니다. 들고 있거나 쥐/접착에 잡힌 화물은 따로 밀리지 않습니다. |

새 조작 키는 없습니다. 발판은 올라서면 작동합니다. 바람은 좌우로 벗어나거나 송풍이 끝날 때까지 기다릴 수 있고 점프 중 직원에게는 바닥 송풍 이동이 적용되지 않습니다. 기존 오른쪽 컨베이어의 F 역전과 쥐의 R 경적은 그대로입니다. 새 계약에서 문과 송풍 시계가 초기화되며 로비·결과 화면에서는 진행하지 않습니다. 계약 시간은 240초를 유지합니다. 넓어진 거리에서 실제 난이도와 재미를 확인한 뒤 조정할 예정입니다.

직접 편집하려면 `Gameplay/RouteChallenges`를 선택합니다. Inspector의 Gate Hold Seconds, Wind Idle/Warning/Burst Seconds, Worker/Cargo Wind Speed를 바꿀 수 있습니다. 그 아래 **Gate 부모**를 이동하면 문·발판·끼임 방지 영역·표지가 함께 옮겨집니다. **AirMail 부모**를 이동하거나 Y축으로 돌리면 송풍 범위·방향·간판이 함께 바뀝니다. 발판 위치만 바꾸려면 Gate/PlateFront 또는 PlateBack을 선택합니다. WindZone/CollisionShape3D의 Shape/Size로 송풍 범위를 조정합니다.

`Gate/Status`, `AirMail/Status`는 작동 상태 표시라 게임이 문구를 갱신합니다. 나머지 안내판은 English/Korean을 수정합니다. 새 문이나 송풍 장치를 복제해 개수를 늘리는 동작은 아직 지원하지 않습니다. 현재 한 쌍을 배치·설정하는 편집 구조입니다. Gate 안쪽의 Door/CollisionShape3D, Clearance, PlateFront/Back 이름은 유지하세요.

편집한 EXE는 BUILD.cmd로 다시 만듭니다. **프로토콜 9**를 사용하므로 모두 같은 0.7.4 ZIP으로 실행해야 합니다. [확장 기획·검증](../superpowers/plans/2026-09-08-shrine-expansion.ko.md).


## 0.7.5 굽은 골목과 연결길

맵 크기는 48×60m로 유지하고 세 평행 통로를 바꿨습니다. 왼쪽은 사선 입구 → 분실물 벽 바깥 → 북쪽 벽 안쪽으로 돌아가는 S자 골목입니다. 오른쪽은 가림벽 안으로 들어와 송풍로에서 가로로 이동한 뒤, 북쪽 코너에서 다시 안쪽으로 꺾습니다. 문 앞 Z-26과 문 뒤 Z-30에는 좌우 연결길이 있어 중간에 경로를 바꿀 수 있습니다. 중앙 발판 문은 그대로입니다.

송풍 장치는 (15,0,-24), Y축 90도로 이동했습니다. 바람은 중앙 연결길 쪽인 -X 방향으로 불며, 바깥 우회로로 나가려면 송풍을 기다리거나 피해서 이동합니다. 화살표와 색 선을 따라 코너를 확인하세요. 입고·배송구·쥐 영역·장치 시간·계약 시간은 유지합니다.

새 벽은 `Geometry/WindingAlleys`에서 구역별 부모를 옮깁니다. 내부 SolidBlock의 Dimensions/Color로 크기·색을 조절합니다. `DesignRoutes`의 LeftLoop, RightLoop, FrontCrossLink, RearCrossLink는 설계·검사용 경유점이며 게임이 이동을 강제하지 않습니다. 실제 벽을 옮겼다면 참고 경유점도 맞춰 주세요. 경유점만 움직여도 벽이 자동으로 바뀌지는 않습니다.

## 0.7.5 실내 소품 편집

접수·포장·휴게·보관 소품 29개 묶음, 선반 상자 96개, 벽 포스터 18개와 천장 배관·깃발을 채웠습니다. `Geometry/InteriorDressing`에서 가구 묶음을 선택해 옮깁니다. 선반 속 재고는 `Geometry/Shelves`의 각 선반을 따라갑니다. 천장 배관은 `Decoration/InteriorOverhead`, 포스터는 `Decoration/WallPosters`입니다. 표지의 English/Korean을 함께 수정하세요.

바닥 가구와 쌓인 상자는 고정 충돌 소품입니다. 장식 자판기·도장은 새 E 상호작용을 제공하지 않습니다. 실제 배송 화물과 구분해 사용합니다. 큰 가구를 옮긴 뒤에는 코너·발판·송풍 구역을 막지 않는지 F5로 확인하세요.

## 0.7.6 새 실내 구역 편집

`Geometry/EnclosedRooms` 아래 `IntakeRoom`, `LostArchive`, `DoormanRoom`, `AirMailRoom`, `DispatchA/B`를 선택합니다. 방 아래의 벽·지붕도 Dimensions와 Position으로 수정할 수 있습니다. 가구는 기존 `Geometry/InteriorDressing`에 있습니다. 방 부모를 옮겨도 기존 가구·배송 판정·발판·송풍 장치는 따라가지 않으므로 관련 그룹도 함께 옮기세요.

접수실 서쪽 `HatchSill`과 `HatchHeader` 사이가 화물 창구입니다. 개구부는 가로 3m·높이 1.15m, 바닥에서 1.8~2.95m입니다. 바닥의 던지기/받기 표시는 실제 기본 던지기 궤적에 맞췄습니다. 창 높이나 크기를 바꾸면 다시 던져 확인하세요. 문지기 지붕은 높이 8.2m로 올라간 문 위 공간을 확보합니다. 기본 부분 지붕은 5.7m 높이에 있습니다. 아래 조명은 각 지붕 이름의 Light 노드입니다.
