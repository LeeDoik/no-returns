# NO RETURNS — Steam 출시 로드맵

[English](01-release-roadmap.md)

> 문서 체계 개정: 이 파일의 버전·수치는 작성 당시 기준입니다. 현재 규칙·미완료 상태는 [문서 홈](../README.md)을 먼저 확인하세요.

**작성일:** 2026년 9월 7일  
**계정 상태:** 사용자 답변 기준 미등록  
**목표:** Windows PC / Steam / 3D 3인칭 / 온라인 협동  
**진행 상태:** 출시 준비 단계이며 출시일은 발표하지 않았습니다.

## 1. 계정 등록: 사용자가 처음 할 일

[Steam Direct](https://partner.steamgames.com/steamdirect)를 열고 게임을 관리할 Steam 계정으로 로그인합니다.

출판 주체의 법적 신원, 명의가 일치하는 은행 계좌 정보, 세금 설문에서 요청하는 정보를 준비합니다. 실제 권리자가 약관에 동의하고 신원 확인을 완료해야 합니다. 개인으로도 등록할 수 있으며 법적 명의와 예금주가 일치해야 합니다. 민감한 정보는 Steamworks와 공식 검증 화면에 직접 입력합니다. 저장소에는 완료 여부만 기록하고 신분증이나 금융 식별정보는 넣지 않습니다. [공식 등록 안내](https://partner.steamgames.com/doc/gettingstarted/onboarding)

| 사용자가 준비할 정보 | 입력할 곳 | 프로젝트 진행에 필요한 공유 내용 |
| --- | --- | --- |
| 개인 또는 회사 중 출판 주체 | 공식 등록 절차 | 주체 유형과 검증 완료 여부 |
| 법적 이름, 주소, 신원 확인 | 공식 등록·검증 화면 | 완료 여부만 |
| 은행 정보 | 공식 정산 설정 | 완료 여부만 |
| 세금 설문 | 공식 세금 입력 절차 | 승인 또는 검증 대기 상태 |
| 게임 등록비 결제 | 공식 결제 화면 | 결제일, 영수증은 별도 보관 |
| 공개 개발사·배급사 이름 | 상점 정보 | 정확한 공개 표기 |
| 지원 이메일 | 사용자 소유 메일과 상점 설정 | 공개할 지원 주소 |
| App ID와 관련 디포·패키지 ID | Steamworks 앱 관리 화면 | 생성 후 실제 ID. 비밀 정보가 아님 |

공개 스튜디오 이름과 계약상의 법적 명의는 용도가 다릅니다. 양식을 채우려고 존재하지 않는 회사를 만들지 않습니다.

## 2. 공식 문서에서 확인한 비용과 기간

| 항목 | 현재 규칙 또는 일정상 의미 |
| --- | --- |
| Steam Direct 등록 | 게임당 USD 100 또는 현지 통화 상당액. 적용되는 소비세가 추가될 수 있음 |
| 등록비 회수 | 환불은 아님. 해당 제품의 조정 총매출(Adjusted Gross Revenue)이 USD 1,000에 도달하면 이후 정산에서 회수 가능 |
| 결제 수단 | Steam 지갑 잔액으로 이 비용을 결제할 수 없음 |
| 첫 출시 대기 | 게임 등록비 결제 후 30일을 계획에 반영 |
| Coming Soon 공개 | 출시 예정 페이지를 최소 2주간 공개해야 함 |
| 상점·빌드 심사 | 각각 보통 영업일 3~5일. 수정 여유를 포함해 제출마다 최소 영업일 7일 확보 |

출처: [등록비](https://partner.steamgames.com/doc/gettingstarted/appfee), [개발자 등록](https://partner.steamgames.com/doc/gettingstarted/onboarding), [심사 절차](https://partner.steamgames.com/doc/store/review_process).

대기 기간들은 서로 겹치거나 개발과 함께 진행될 수 있습니다. 게임 제작에 걸리는 예상 기간이 아니라 출시 조건입니다. 실제 출시는 해당 대기 기간, 상점 승인, 빌드 승인, 가격 준비, 자체 품질 검증이 모두 끝난 뒤 가능합니다. 결제일과 페이지 공개일이 정해지기 전에는 가장 빠른 출시 날짜를 계산할 수 없습니다.

## 3. 단계별 진행 순서

| 단계 | 할 일 | 다음 단계로 넘어갈 증거 |
| --- | --- | --- |
| A — 제품 정의 | 화물 상호작용과 첫 근무 검토, 시간 상한 합의 | 최소 실험용 기획 검토 완료 |
| B — 등록 | 사용자 등록·결제·검증·앱 설정 | 접근 가능한 앱 관리 화면과 실제 App ID |
| C — 온라인 실험 | 별도 네트워크의 2인이 이동·집기·특수 효과·배송 | 성공한 세션 기록, 화물 소유 오류 해결 |
| D — 반복 플레이 검증 | 4인으로 한 판을 완료하고 새로운 그룹과 반복 테스트 | 의도적인 협동과 다시 하고 싶다는 반응 |
| E — Coming Soon | 이름, 실제 화면, 캡슐 이미지, 문구, 설문, 정보 준비 후 심사·공개 | 공개 주소와 최초 공개 시각 |
| F — 외부 테스트 | 참가 권한 관리, 사용성·통신 피드백 수집 | 테스트 보고서, 수정 사항, 검증된 접속 흐름 |
| G — 출시 후보 | 확정 콘텐츠, 설정, 영어 문구, 고지, 에셋, 가격, 빌드 업로드 | 빌드 ID, 테스트 결과, 실제와 일치하는 상점 설명 |
| H — Steam 심사 | 상점 먼저 제출, 거의 완성된 빌드 심사 | 양쪽 승인과 해당 대기 기간 충족 |
| I — 출시 | 최종 핵심 동작 검사, 출시 실행, 공개 확인, 지원 준비 | 상점 구매 가능 여부와 실제 사용자 관점의 설치 성공 |

A와 B는 병행할 수 있습니다. 등록은 접속 테스트 전에 도움이 되며 외부 대기 기간을 시작하지만, 결제는 사용자가 진행합니다. Coming Soon에는 게임을 대표하는 빌드가 필요하며 실제 스크린샷을 콘셉트 이미지로 대체하지 않습니다.

초기 판매 형태는 일회성 구매를 제안합니다. 가격, 할인, 유료 버전의 콘텐츠 양, 출시일은 테스트를 바탕으로 사용자가 결정합니다. 작은 게임을 검증하는 동안 지속적인 서비스 운영을 약속하지 않습니다.

## 4. 개발 시간 관리 제안

첫 온라인 실험은 **집중 개발 시간 40시간 시점에 중간 판단**을 하는 방식으로 제안합니다. 사용할 시간의 상한 제안이며, 완성 예상 시간이나 출시 약속은 아닙니다.

| 조사·작업 | 제안 시간 |
| --- | ---: |
| Steam/Godot 호환성과 두 PC 접속 실험 | 12 |
| 3인칭 이동, 들기, 던지기, 기본 카메라 | 8 |
| 재채기·접착 상자와 제한된 상호작용 | 10 |
| 작업장, 할당량, 타이머, 회수, 재시작 | 4 |
| 외부 테스트, 관찰한 문제 수정, 중간 보고 | 6 |
| **합계** | **40** |

개발 경험이나 도구 호환성 때문에 이 범위가 현실적이지 않으면 접속 실험 후 다시 산정합니다. 중간 시점에 계속 개발할지, 기획을 줄일지, 실험을 멈출지 판단합니다. 이 시점을 출시 약속으로 바꾸지 않습니다.

초기 유료 제작 범위는 작업장 하나, 몇 가지 직접 구성한 배치, 특수 화물 3종과 기본 화물, 반복 가능한 근무 정도로 제한하는 방향입니다. 검토할 상한이며 대외적인 콘텐츠 약속은 아닙니다. 기존 규칙의 반복 재미가 확인된 뒤 콘텐츠를 늘립니다.

## 5. 현금 지출 계획

- **확인된 플랫폼 지출:** 등록비와 결제 화면에 표시되는 세금.
- **통신 방향:** 플레이어가 방장이 되는 Steam 세션으로 자체 상시 게임 서버 운영을 피합니다. 연동과 서비스 조건 확인 전에는 유지비를 0원으로 계산하지 않습니다.
- **아트·오디오·폰트 구매:** 나중에 진행합니다. 상업적으로 쓰기 전에 라이선스를 기록합니다.
- **현지화:** 게임 문구는 영어 원문부터 만듭니다. 추가 게임 언어에는 번역과 검증 작업이 필요합니다.
- **홍보:** 게임 영상, 상점, 소규모 스트리머 테스트부터 시작합니다. 유료 광고 예산은 가정하지 않습니다.
- **기타 변동 비용:** 테스트 기기와 접근 수단, 사용자 지원, 전문 서비스, 추후 추가 서비스. 전체 비용을 확정하지 않았습니다.

## 6. 알리기와 테스트 계획

소규모 비공개 그룹으로 시작합니다. 이후 Steam Playtest의 별도 연결 앱으로 외부 테스트를 관리할 수 있으며 자체 설정과 심사가 필요합니다. 공개 데모는 별도 결정 사항입니다. 둘 다 본편 판매에 무조건 필요한 조건은 아닙니다. [Steam Playtest](https://partner.steamgames.com/doc/features/playtest)

공개 상점이 생기면 상황의 시작, 실수, 수습이 잘 보이는 짧은 플레이 영상을 촬영합니다. 협동 파티 게임을 다루는 스트리머에게 연락하기 전에 초대문과 지원 정보를 준비합니다. 상점 방문과 찜 수로 전달 방식의 차이를 살피되 판매량을 보장하는 지표로 삼지 않습니다.

Steam Next Fest 같은 행사는 대표성 있는 데모를 만들 수 있을 때 검토합니다. 그 시점의 참가 조건과 마감일을 확인하며, 이 로드맵은 참가 자리나 날짜를 가정하지 않습니다.

## 7. 공개·출시 실행

Steam 심사 승인이 자동 출시로 이어지지는 않습니다. 권한이 있는 Steamworks 사용자가 출시를 실행해야 합니다. 직전에 사용할 빌드, 가격, 지원 플랫폼, 공개 상점 내용을 기록합니다. [출시 절차](https://partner.steamgames.com/doc/store/releasing)

현재 로컬에 준비한 것은 기획, 로드맵, 문구, 제작 안내, 기술 검증 계획, 체크리스트입니다. 계정 검증, 결제, 아트, 실제 게임, 상점 제출, 출시 실행은 앞으로 완료할 작업입니다.
