## 3. 제품·권리·콘텐츠 — 사용자와 개발

- [ ] 최종 이름이 목표 시장의 다른 게임 브랜드와 충돌하는지 검토. 그전까지 NO RETURNS는 가제.
- [ ] 배포 코드, 아트, 폰트, 소리, 음악, 홍보 자료의 충분한 상업적 사용 권리 기록.

- [ ] Steam 콘텐츠 설문에 최종 콘텐츠를 정확히 반영. 해당 폭력·성인 요소와 AI 도움으로 만든 이용자 소비 콘텐츠 포함.
- [ ] 목표 시장의 등급·판매 가능 여부 확인. 글로벌 목표만으로 모든 지역에 판매할 수 있다고 가정하지 않음.
- [ ] 추가로 적용되는 현지 출판·등급 요건이 있으면 해당 지역 판매를 켜기 전에 해결.
- [ ] Steam 식별정보, 진단, 충돌 보고, 지원 문의, 분석 정보의 실제 처리 방식을 기록하고 필요한 안내와 일치시킴.
- [ ] 최종 데이터 흐름과 출판 형태에 필요하다면 이용약관(EULA)·개인정보 안내를 준비. 무관한 양식을 완성된 법적 문서로 간주하지 않음.

Godot를 배포할 때는 엔진과 해당 외부 구성요소의 라이선스 고지가 필요합니다. 실제 사용하는 버전에 맞는 내용을 포함합니다. [Godot 라이선스 준수](https://docs.godotengine.org/en/stable/about/complying_with_licenses.html)

Steam 설문은 일반 콘텐츠, 성인 콘텐츠, 생성형 AI를 다룹니다. AI 항목은 아트, 소리, 이야기, 현지화 등 게임에 실려 이용자가 소비하는 콘텐츠에 초점을 둡니다. 개발 도구의 효율 향상만을 묻는 것과는 구분됩니다. 실제 배포 내용에 따라 답합니다. [콘텐츠 설문](https://partner.steamgames.com/doc/gettingstarted/contentsurvey)

예를 들어 Steam은 독일의 등급 요건과 인도네시아 등급 절차를 안내합니다. 설문을 마치고 실제 앱의 지역 상태를 확인해야 합니다. 설문만으로 모든 지역의 판매가 보장되지는 않습니다. [독일](https://partner.steamgames.com/doc/gettingstarted/contentsurvey/germany), [인도네시아](https://partner.steamgames.com/doc/gettingstarted/contentsurvey/indonesia)

## 7. 출시 당일 운영

출시 전 마지막 정상 빌드와 짧은 알려진 문제 목록을 남깁니다. 출시 후에는 설치, 시작 실패, 초대, 접속 문제부터 확인합니다. 중대한 신고는 실제 출시 빌드에서 재현하고 수정이나 임시 해결책을 기록합니다.

긴급 수정은 비공개 브랜치에서 검사한 뒤 배포합니다. 새 빌드가 실행이나 핵심 멀티플레이를 깨뜨리면 기록된 정상 빌드로 되돌린 상태에서 수정합니다. 실제 변경을 간결한 패치 노트로 알립니다. 이번 준비에서 자동 배포나 메시지 발송 시스템을 설정하지 않았습니다.
