# 7. MDA 분석 — Core Fun과 Core Loop

[English](07-mda.en.md)

분석일: 2026-09-09 · 게임 0.9.4 · 현재 명세 및 코드 정적 검토. 게임 코드 변경 없음. 아래 재미와 플레이 행동은 구현에서 도출한 가설이며 이번 작업에서 사람 플레이로 검증하지 않았다.

## 분석 기준

2026-09-09 보충: 본 문서와 Word 작성본은 현재 구현을 분석한 자료다. 사용자가 요청한 이동·랜덤 맵·더 넓은 규모의 기획은 [확장 방향 탐색](08-expansion-directions.ko.md)에서 별도로 다룬다. 기존 구간 개선 제안과 경제 진단이 향후 비전의 상한이나 반드시 먼저 실행할 순서는 아니다.

MDA는 Mechanics(규칙·행동), Dynamics(규칙과 플레이어 선택이 만나 생기는 플레이 양상), Aesthetics(플레이어가 느끼는 경험)를 연결한다. Aesthetics는 그래픽 품질만을 뜻하지 않는다. Core Fun과 Core Loop는 이 프로젝트를 분석하기 위한 구분이며 MDA의 추가 구성요소가 아니다. 출처: Hunicke, LeBlanc, Zubek, [MDA 원문](https://www.cs.northwestern.edu/~hunicke/MDA.pdf).

## Core Fun — 무엇 때문에 다시 하고 싶은가

**가장 유력한 핵심 재미: 말을 듣지 않는 살아 있는 화물을 옮기다가 계획이 틀어지고, 동료와 즉석에서 수습해 배송을 성공시키는 재미.** 사고는 매 배송마다 필수 단계가 아니라 반복 흐름을 흔드는 조건부 사건이다.

| 우선순위 | 경험(A) | 예상되는 플레이 양상(D) | 구현 근거(M) |
|---|---|---|---|
| 핵심 1 | Fellowship — 함께 해냈다는 유대감 | 던지는 사람과 받는 사람의 타이밍 조율, 운반·장치 조작·쥐 대응 역할의 즉석 교대 | 들기·던지기·받기, 표시, 공동 목표·잔액, 릴레이 보너스, 경적 |
| 핵심 2 | Challenge — 위험을 읽고 다루는 성취감 | 안전하게 운반할지 던질지 판단하고 화물 예고에 대응하며 시간 안에 목표 달성 | 운반 감속, 재채기·접착·점프 화물, 제한 시간, A/B 목적지 판정 |
| 핵심 3 | Discovery — 더 나은 해결법을 찾는 재미 | 발판을 누를 사람 또는 상자를 선택하고 벨트·송풍과 경로를 조합 | 직원/화물 발판 감지, 문 유지 시간, 벨트 반전, 송풍 장치 |
| 보조 | Sensation·Fantasy — 손맛과 기묘한 배송 직원 체험 | 던지기·반응 연출을 보고 사고의 원인과 결과를 함께 즐김 | 직원 동작, 특수 화물 예고, 흩날리는 문서·무너지는 장식 상자 |

웃긴 사고와 수습담은 이 경험들이 결합하면서 생길 수 있는 결과다. 이를 독립적인 MDA 기본 분류로 취급하거나, 별도의 스토리 캠페인이 확인됐다는 뜻으로 Narrative를 핵심에 넣지는 않는다. Expression과 Submission 역시 현재 구현에서 중심 재미라고 판단할 근거가 약하다.

근거: [운반·릴레이](../../scripts/cargo.gd), [배송 판정](../../scripts/cargo_rules.gd), [직원](../../scripts/worker.gd), [공동 보상](../../scripts/contracts.gd), [환경](../../scripts/route_challenges.gd), [벨트](../../scripts/conveyor.gd), [쥐](../../scripts/packrat.gd), [표시](../../scripts/pings.gd), [반응 소품](../../scripts/reactive_props.gd). 특수 화물 수치와 근거는 [현재 명세](02-spec.ko.md)를 따른다.

## Core Loop — 어떤 선택과 행동을 반복하는가

### 화물 하나의 반복

**화물 특성·A/B 목적지 확인 → 경로·운반 방법·역할 선택 → 들고 이동하거나 던지고 받기·장치 활용 → 맞는 배송 구역에 화물 놓기 → 점수·피드백 확인 → 다음 화물 선택.**

운반 중 사고나 방해가 발생하면 **상황 파악 → 회수·경로 변경·동료 도움 → 운반 재개**로 돌아온다. 이 수습 분기가 배송 작업을 협동 상황으로 바꾸는 핵심 가설이다. 모든 사고가 웃기다는 뜻은 아니며 조작 오류나 납득하기 어려운 충돌은 좌절이 될 수 있다.

| 반복 요소 | 현재 구현에서의 역할 |
|---|---|
| 목표 | 화물마다 정해진 A/B 배송지와 계약 목표량 |
| 선택 | 어느 화물을 먼저, 어느 경로로, 혼자 운반하거나 릴레이할지 |
| 행동 | 이동·집기·놓기·던지기·받기·표시·장치 조작·경적 |
| 저항 | 느린 운반, 화물 행동, 환경 타이밍, 계약 2부터의 포장쥐, 남은 시간 |
| 피드백·보상 | 배송 점수, 릴레이 알림, 계약 중 누적 획득액 |
| 반복 유도 | 다음 화물과 목적지, 남은 목표량·시간, 직전 실패에서 배운 개선 |

배송은 목적지 일치·비운반·미배송 상태여야 인정된다. 릴레이는 다른 직원이 던진 화물을 던지기 후 3초 이내, 시작 위치에서 3m 이상 떨어진 곳에서 바닥 인접 검사에 걸리지 않는 상태로 받아야 성립한다. 단순한 근거리 전달 모두가 릴레이는 아니다. 근거: [cargo.gd의 pickup/release](../../scripts/cargo.gd), [cargo_rules.gd의 try_dispatch](../../scripts/cargo_rules.gd).

### 계약 안의 반복

**배송 반복 → 남은 시간·목표량 확인 → 우선순위와 역할 조정 → 배송 반복 → 목표 달성 또는 시간 종료.**

캠페인 기본 시간은 240초이고 시간 장비 단계당 20초가 추가된다. 목표량은 1/2/3/4명 기준 5/6/8/10개에 계약 단계(0/1/2)×2를 더한다. 솔로에서도 운반·경로 숙련 루프는 남지만 다른 플레이어와의 유대감과 릴레이는 경험할 수 없다.

### 캠페인 진행의 반복

**계약 성공 → 공동 크레딧 정산 → 방장이 장비 구매 → 전원 준비 → 다음 계약 → 3번째 계약 성공으로 완주.**

배송당 10크레딧, 릴레이 배송은 5 추가이며 성공할 때 획득액과 성공 보너스 20을 공동 잔액에 반영한다. 실패에는 같은 지급을 하지 않으며 성공 루트의 장비 구매·다음 계약으로 자동 진행하지 않는다. 신발·시간·경적 구매는 다음 계약의 수행 조건을 바꾼다. 이 장비 성장은 현재 캠페인 안의 진행이며 영구 성장이라고 보지 않는다. 근거: [contracts.gd](../../scripts/contracts.gd), [진행 제어](../../scripts/main.gd).

연습은 별도 흐름이다. 기본 180초 배송 후 성공 시 전원 동의로 60초 추가 목표에 도전할 수 있으며 캠페인 장비 루프와 구분한다. 근거: [round_rules.gd](../../scripts/round_rules.gd), [main.gd](../../scripts/main.gd).

## 핵심 가설의 약점과 확인할 점

| 현재 근거·제약 | 재미에 대한 해석 | 사람 플레이에서 확인할 질문 |
|---|---|---|
| 솔로 가능, 발판을 직원 또는 화물로 작동 | 함께 접속하는 것만으로 협동이 생기지는 않음 | 플레이어가 스스로 도움과 릴레이를 요청하는가? |
| 릴레이 배송 추가 보상은 구현됨 | 실패·회수 비용을 감수할 유인이 될 가능성 | 안전 운반 대비 실제로 선택할 가치가 있는가? |
| 운반 중 화물은 고정 방식이며 힘 기반 잡기는 철회됨 | 무게를 함께 지탱하는 물리 협동을 핵심 재미로 약속할 수 없음 | 운반·던지기·회수 결과를 이해하고 통제하는가? |
| 반응 소품의 상자 잔해는 직원/배송 화물을 직접 밀지 않음 | 시각적 사고 연출이 반드시 새로운 선택을 만들지는 않음 | 장치 때문에 경로·타이밍·역할을 바꾸는가? |
| 맵 재미에 사용자 품질 지적, 실제 4인 검증 미완료 | 발견·협동의 잠재력은 있으나 성립 여부 미확인 | 같은 운반의 반복을 넘어 다른 방법을 시험하고 재플레이를 원하는가? |

이는 확정 버그나 승인된 기능 추가 목록이 아니다. 기존 [MAP-01·PHY-01·QA-01·UX-01](04-backlog.ko.md)의 관찰 관점이다. 검증에서는 도움 요청·역할 교대·경로 변경·실패 원인 설명·자발적 재시도 사례를 기록한다. 통과 수치와 실제 결과는 아직 없으며 [검증 기준](05-validation.ko.md)의 사람 플레이 항목을 완료로 바꾸지 않는다.

## 양식 작성에서 확인한 보상 루프의 약점

2026-09-09에 사용자 제공 Word 양식의 7개 답변란을 채우고 반복 구조·보완 우선순위를 덧붙였다. [한국어 작성본](../deliverables/core_loop_No_Returns.filled.ko.docx), [영어 대응본](../deliverables/core_loop_No_Returns.filled.en.docx). 원본은 보존했다.

[contracts.gd](../../scripts/contracts.gd)의 현재 규칙에서 전체 최대 장비 비용은 신발 20×2 + 시간 25×2 + 경적 20 = 110이다. 4인 첫 계약은 릴레이 없이 목표 10개만 달성해도 10×10 + 성공 보너스 20 = 120을 받는다. 구매 횟수 제한이 없어 첫 계약 뒤 전 장비 최대 강화가 가능하다. 따라서 다음 계약의 구매 선택과 릴레이 추가 수입의 장비 사용처가 일찍 소진될 수 있다. 이는 코드와 산술로 확인한 구조이며 실제 재미 저하는 아직 가설이다. 기록·운반 효율·협동 자체의 가치를 부정하지 않는다.

보완 우선순위는 ① 보상→다음 구매 선택의 지속성 ② 운반 방식 간 선택 가치 ③ 사고 수습→학습·보람 ④ 다음 계약의 변화다. 가격·해금 조정과 맵 구간 비교는 제안이며 승인된 구현 변경은 아니다. [ECO-01과 기존 백로그](04-backlog.ko.md)를 따른다.

작성본의 7개 답변란, 원본 해시, 페이지 설정과 비편집 패키지 7개 보존, 한영 내용과 수치를 확인했다. 페이지 렌더러는 `LibreOffice soffice.exe was not found on PATH`로 실패하여 실제 페이지 배치·글꼴·잘림은 미검증이다. 게임 코드 변경과 게임 테스트 재실행은 없다.

## MDA 조사 검증 범위

현재 문서와 관련 코드의 규칙·보상·진행 조건을 대조했다. 문서 링크·한영 대응·숫자·체크 상태를 검토하고 `python tools/check_docs.py`를 실행한다. 게임 실행, 렌더링, 실제 협동 플레이, 체감 재미 및 기존 게임 테스트 재실행은 이번 조사 범위에 포함하지 않았다.
