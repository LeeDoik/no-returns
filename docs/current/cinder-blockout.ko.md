현재 환경 검토 대상은 [건물 5개에 승인한 노후 질감을 확장한 별도 Unity 씬](cinder-map-appearance.ko.md)이다. 원본 블록아웃·회색·창고 외형 씬을 보존한다. 기존 경로 41개와 운반 자세 2,352개 검사를 통과했으며, 확장 결과의 사용자 검토와 수령 설비·야외 마감은 남아 있다.

## 2026-10-01 — 회색 구조 검토 씬

[첫 에셋 제작·검토](cinder-asset-prep.ko.md): 별도 `CinderStructureReview`에 구조 5종/변형 11개의 프리팹으로 창고 외형을 조립했다. 원본 씬은 변경하지 않았다. 기존 창고 Renderer 10개는 검토 씬에서 비활성화하고 Collider 10개를 유지하며 새 Collider는 없다. 남측 입구 3m 앞에서 화물을 들고 입구 안쪽 6m와 후진을 검토한다. Blender/FBX와 Unity 임포트·통로/점프/화물 자세·Mac Editor Play E/Q 검사를 통과했다. 사용자가 창고 크기를 괜찮다고 확인해 현재 14.4×20.4m를 유지한다. 이 회색 단계의 자동 검사는 최종 품질 승인이 아니다. 승인한 시안의 별도 외형 씬 적용은 위 최신 기록을 따른다. 운반·접합면 품질과 실제 적용 외형의 사용자 평가, 독립 빌드·온라인/AI/배송은 미검증이다. 아래 기존 블록아웃 생성 메뉴는 이 검토 씬의 제작 메뉴가 아니다.

## 2026-10-01 — 제작 전 준비 기록

[창고 첫 8종 제작 준비서](cinder-asset-prep.ko.md)에 바닥·벽·문틀·천장·코너/끝 마감 선행 5종과 작업등·표지판·빈 선반 후행 3종의 규격·피벗·예산 후보를 정리했다. 저장된 창고 남측 입구 중심 (-18.6,0,-8.4)m와 기존 개구부 3.2×3.3m·천장 하단 4m를 코드와 대조했다. 입구 안쪽 6m는 검토 구간 제안이며 새 복도나 경로 변경이 아니다. 당시 작업은 문서 준비만 수행했다. 현재 구조 제작·검토 상태는 위 항목과 연결된 제작 안내를 따른다.

## 실행과 범위

[Play_Cinder_Blockout.cmd](../../Play_Cinder_Blockout.cmd)를 실행한다. 실행 파일은 `builds/CinderBlockout/NoReturns-CinderBlockout.exe`다. 기존 리스너 게임과 우주선 시험 장면을 보존한다. 이번 장면은 한 명이 공간과 화물 운반 폭을 확인하는 실험이다. 계약·배송 판정·영수증·경제·온라인·적 추적은 연결하지 않았다. 빨간 캡슐 3개는 리스너 배치 표식이다.

WASD 이동, 마우스 시야, E 상자 들기, Q 내려놓기, Shift 빈손 달리기, Space 빈손 점프, F1 한국어/영어, Esc 커서 해제, 클릭으로 시야 조작을 재개한다. 운반 중 달리기·점프는 기존 내부 시험처럼 제한한다. 한영 선택은 이 실행 세션에만 유지한다.

## 배치와 실제 수치

우주선은 [내부 시험 05](ship-interior-trial.ko.md)의 모델·충돌·조명을 재사용한다. 남서쪽에 배치하고 출입부를 동쪽 출발 동선으로 돌렸다. 외장을 새로 만들지 않았다. 우주선 규격을 건물 크기에 맞추려고 축소하거나 확대하지 않았다. 지붕 통로는 높이와 경로를 확인하는 단순 판이며 지지대·최종 건축 디테일은 생략했다.

## Unity 편집과 재현

장면: [CinderDepotBlockout.unity](../../NoReturns/Assets/_NoReturns/Scenes/CinderDepotBlockout.unity). `Cinder Depot editable primitive blockout` 아래 건물·장애물·바닥 표시를 이동하거나 크기를 바꾼다. `Reused Ship Interior Trial 05`는 기존 선내 구조 묶음이다. 기본 도형과 BoxCollider를 사용하므로 Unity에서 바로 편집할 수 있다.

생성·검사·빌드는 Unity의 `NO RETURNS > Trials > Create/Validate/Build Cinder Depot Blockout` 메뉴로 실행한다. **Create와 Build는 생성 스크립트로 장면을 다시 만들므로 직접 편집한 장면을 덮어쓴다.** 직접 수정한 안은 다른 이름으로 저장하거나 [생성 코드](../../NoReturns/Assets/_NoReturns/Editor/CinderBlockoutBuild.cs)에 반영한다. 단독 Validate는 현재 장면을 검사한다. 출력 루트는 기존 `CarryWorkspace.txt`가 있으면 해당 경로를 사용한다.

수치 근거: 위 생성 코드와 [이동 코드](../../NoReturns/Assets/_NoReturns/Runtime/CinderBlockoutWalk.cs). 기존 우주선 재질의 작업 시작 전 변경 8개는 이번 변경에 포함하지 않는다.

## 2026-09-26 — 새 아트 제작부터 씬 완성까지

사용자 정정: 지금 필요한 아트 리소스는 새로 제작해야 한다. 기존 시험 모델과 과거 목록의 재사용 후보를 현재 Cinder 씬의 완성 리소스로 취급하지 않는다. 목표는 이 씬에 맞는 아트를 제작하고 적용해 한 장면을 완성하는 것이다. 아래 첫 구역과 제작 묶음은 작업 순서 제안이며 신규 외형 승인·제작 완료가 아니다.

1. **제작 기준:** 현재 블록아웃에서 벽·문·통로·천장 치수와 화물 여유를 확인한다. 기존 3.2m 문 폭·3.3m 문 높이·4m 천장 하단은 구조 시험값이며 새 출시 규격으로 확정하지 않는다. [기존 PSX 환경 시안](../art/space-concepts/environment-kit-01.png)의 상아색 패널·적갈색 띠·어두운 프레임·따뜻한 작업등을 스타일 참고로 삼는다.
2. **첫 제작 묶음 제안:** 창고 입구와 연결 통로를 위한 벽, 코너, 문틀, 바닥, 천장·보, 작업등, 화물 선반, 표지판. 치수·연결면·피벗을 포함한 제작용 시안을 준비하고 기존 [구조 우선 순서](art-structure-first.ko.md)에 따라 확인한다.
3. **모델 제작·작은 구역 적용:** 치수가 중요한 구조는 Blender에서 제작하고 공용 재질과 저해상도 텍스처를 맞춘다. Tripo가 필요한 개별 외형은 구조·시안 확인 후 제작한다. Unity에서 한 구역의 조립·빛·1인칭 화면·운반 공간을 확인한다.
4. **씬 전체 확장:** 같은 부품군을 건물 5개에 적용하고 수령소·억제 시설·야외 지면·암석·우주선 마감 등 필요한 리소스를 순서대로 제작한다. 기존 경로와 충돌 기준을 보존하고 장면별 장식 밀도를 조정한다.

완료 기준은 환경 외형의 통일, 노출된 임시 구조의 의도적 정리, 1인칭 방향·목표 식별, 운반·출입 유지와 사용자의 실제 화면 검토다. 적 AI·온라인·배송 판정의 완료 상태는 별도로 검증한다. 이번 작업은 기록·시안 확인과 제작 순서 정리만 수행했으며 새 이미지·모델·재질 생성, 비용 사용, 코드·씬 변경과 플레이 검증은 없다.
