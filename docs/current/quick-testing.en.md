## Quick feature checks

Run from the project root. Reuse the existing build by default; do not build automatically.

```sh
python3 tools/cinder_quick_test.py beacon
python3 tools/cinder_quick_test.py rescue
python3 tools/cinder_quick_test.py baton
python3 tools/cinder_quick_test.py all
```

If the current Unity sources/assets/settings differ from the binary or the record is missing, **reject before launching clients**. When native validation is needed, explicitly rebuild once.

```sh
python3 tools/cinder_quick_test.py all --build
```

The [build fingerprint](../../tools/cinder_build_stamp.py) records Unity Assets/Packages/ProjectSettings contents and the executable modification time. Exclude Editor folders and the CinderFourPlayerTest scene regenerated by the builder. Normalize only the build-generated `m_RuntimeSettings.m_List` in URP global settings; inspect all other authored settings. Include local EmployeeLocal assets. Documentation/Python test-only changes do not require a native rebuild. Restoring/editing source files can change the fingerprint; do not arbitrarily approve an old record. Store it in ignored `artifacts/cinder-four-player/build-source.json`.

## Fixtures and real checks

The [runner](../../tools/cinder_quick_test.py) launches **two** windowless real clients without a bot. `all` prepares three scenarios sequentially in the same two processes. Reject an existing session; wait up to 30 seconds only for a recently closed port. Stop the launched session on success/failure.

| Scenario | Seeded state | Validated through real inputs |
|---|---|---|
| Beacon | Field, purchased license, two charges, nearby device | E pickup, local/remote hands, placement/one charge/activation, baton return |
| Rescue | One nearby downed teammate | Held rescue/progress/hands, cancellation, 2.5-second revival/baton return |
| Baton | Ready weapon, target two metres ahead | Real hit/replicated stun, pose return, cooldown rejection |

Inject position/progression/down/enemy waiting state only during preparation. The enemy initially remains in a prepared state for 60 seconds, so this does not test natural encounters/pursuit difficulty. Purchasing/delivery/the cause of down are also skipped. **Never inject action results or replace hit/rescue/placement adjudication.** Subsequent actions use existing host logic and networking. Purchase price, full delivery, natural AI, four-player behavior, LAN/Windows and human quality remain covered by existing full checks/hands-on play.

[Fixture code](../../NoReturns/Assets/_NoReturns/Runtime/CarryLab/CarryRoom.QuickTest.cs) activates only under `CARRY_TEST_AUTOMATION` or `UNITY_EDITOR`. Require Cinder hazard mode, `--test-dir` and `--quick-test`, and accept requests only from the host. Read `fixture` only from the local test file; do not add it to network input. A participant cannot reset host state. Use Cinder test folders and create no personal progression save. Normal execution and on-demand human+companion play do not activate fixtures.
