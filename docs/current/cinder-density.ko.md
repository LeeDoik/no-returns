# CINDER 시설 밀도 확장

[English](cinder-density.en.md)

2026-09-21 · CINDER-DENSE-02 · 기본 도형 기반 플레이 배치

## 목적과 실행

사용자는 기존 데모가 너무 트이고 경로·적 위치가 잘 보여 긴박함이 없다고 평가했다. 맵 축소 제안은 취소하고 **108×86.4m 바닥과 우주선 크기를 유지한 채 시설 내부와 실외 연결 공간을 채웠다.** [Play_Cinder_Demo.cmd](../../Play_Cinder_Demo.cmd)가 새 Windows 데모를 실행한다. 원본 `CinderDepotBlockout.unity`와 선내 시험은 보존한다. 현재 배송 데모 장면만 개정했다.

## 공간 구성

| 시설 | 내부 역할과 연결 |
|---|---|
| A 분류 창고 | 입고실·분류 구역·기록실·출고 구역. 남북 출입과 동서 서비스 출입, 엇갈린 내부 문 |
| 서쪽 검문소 | 직원 진입·보관함·경비실. 착륙장과 서쪽 골목 연결 |
| 서쪽 반품 별동 | 처리실·기록 보관·분리 작업 공간. 북쪽 우회 동선과 동쪽 출구 |
| 북쪽 작업장 | 기계 작업·정비 구역. 북쪽 경계 통로와 옆길 연결 |
| 배차 사무동 | 중앙 횡단 복도와 양쪽 사무·기록 공간. 남북 및 동서 출입 |
| BAY 04 | 수령 로비·검사실·분리 보관실. 남북 출입 및 양쪽 서비스 출입. 바닥 수령·영수증 위치 유지 |
| C 설비동 | 펌프실·전력실·작업실. 엇갈린 내부 문과 동서 출구 |
| 남쪽 대형 보관동 | 3개 연결 보관 구획. 남북 및 동서 반출입 |
| 동쪽 냉각 시설 | 냉각 구획·제어 구획·설비 구획. 길게 연결된 실내 대체 경로 |

중앙 적재 마당의 화물 섬과 추가 가림 적재물, 하역 차양, 서비스 배관·외벽 기둥·옥상 환기구를 배치했다. 외곽에는 정비 차폐벽과 위치가 엇갈린 개구부를 두어 한 방향으로 끝까지 보며 달리는 구조를 끊는다. 이 시설은 수작업 좌표로 재현하며 무작위 소품 살포가 아니다. 출입문은 폭 3.2m·높이 3.3m의 열린 개구부이고 건물 천장 아래 높이는 4m다. 문 열기 상호작용·옥상 플레이·완성 아트는 이번 변경에 포함하지 않는다.

표지는 벽에 가려지는 전용 글자 셰이더를 사용한다. 반대편 글자가 벽을 통과하거나 뒤집혀 보이는 표시를 수정했다. 지붕을 숨긴 개략도는 검토용이며 실제 게임에는 지붕이 있다.

## 리스너와 기존 규칙

A 분류 창고, B 중앙 적재 마당, C 설비동 주변에 리스너를 각각 1체 배치했다. 세 개체는 각자의 이동·소음 목표·공격 예고를 가지며 공용 경로망만 공유한다. 근처 소리는 여러 개체가 동시에 들을 수 있다. 화물 소리·신호기·호출·발소리를 각 위치에서 판단하고 충격봉은 실제 사거리·방향·가림을 검사한다. 완벽한 소음 차폐나 구역간 균형을 확정한 것은 아니다.

다운 상태·2.5초 구조·구조 후 4초 보호·6초 충격봉 재사용·3초 전원 다운 회수는 공용으로 한 번만 갱신한다. 적이 3체가 되었다고 시간이 3배로 흐르지 않는다. 방장이 A/B/C 상태를 결정하고 참가자는 같은 결과를 표시한다. Cinder 프로토콜은 **12**, 이전 작은 시험은 10이다. 이전 Cinder 프로토콜 11 빌드와 혼합 접속할 수 없다.

경제·억제장치 시간·E/Q·영수증 회수·외곽 생물 규칙은 유지했다. 낮은 위험의 긴 길에서는 조용히 이동해 적을 피할 수 있으며, 짧은 중앙길은 순찰·소음과 교차한다. 이 배치가 실제로 원하는 긴장을 만드는지는 사람 플레이로 검증해야 한다.

## 제작과 검증

[CinderDenseBuild.cs](../../NoReturns/Assets/_NoReturns/Editor/CinderDenseBuild.cs)의 `Populate Dense Cinder Facility` 메뉴가 현재 데모의 시설 묶음을 다시 만든다. 직접 편집은 덮어쓰므로 다른 이름으로 저장하거나 생성 코드에 반영한다. 바닥·경계·우주선은 유지한다. `Create Cinder Delivery Demo`도 이제 이 밀집 배치를 적용한다. Build는 저장된 장면을 사용한다.

[CinderDenseValidation.cs](../../NoReturns/Assets/_NoReturns/Editor/CinderDenseValidation.cs)는 29개 실내 지점의 연결, 4개 긴 시야 차단, 1.14m 폭 검사체의 경로, 실제 CharacterController 배송 이동을 검사한다. 모든 방향의 상자 회전이나 사람 조작감을 보장하지 않는다. 검사에서 내보낸 `artifacts/cinder-dense/routes.json`을 [실제 배송 검사](../../tools/test_cinder_dense.py)가 사용한다. 원래 빈손 경로와 달리 운반 입력은 아래로 25도 바라보고 문 중앙을 따라가고 모퉁이에서 다음 통로를 바라본 뒤 옆걸음으로 진입한다.

[CinderThreatValidation.cs](../../NoReturns/Assets/_NoReturns/Editor/CinderThreatValidation.cs)는 공유 상태·시간·B 리스너 충격봉·기존 1체 회귀를 검사한다. `ValidatePatrols`는 실제 콜라이더 경로망에서 300초를 빠르게 시뮬레이션해 모든 순찰점 방문과 이동을 검사한다. 이는 실시간 네트워크 플레이가 아니다. [두 프로세스 위험 검사](../../tools/test_cinder_dense_hazards.py)는 B 리스너의 공격 예고·다운·구조를 별도로 검증한다.

현재 통과 근거와 실패·미확인 범위는 [테스트 체크리스트](05-validation.ko.md)를 따른다. 원본 근거·화면은 로컬 `artifacts/cinder-dense/`에 저장하며 빌드·로그는 Git에 넣지 않는다.

## 다음 사람 플레이

우선 두 사람이 한 명 운반·한 명 유인을 맡아 짧은 중앙길과 긴 실내 우회길을 각각 시도한다. 적을 피해 들어간 건물에 다른 출구가 있는지, 좁아진 동선 때문에 화물 조작이 답답해지는지, 표지를 보고 목적지를 찾을 수 있는지 기록한다. 시야 차단 때문에 불합리한 기습이 늘었는지도 확인한다. 위험도를 느끼지 못한다면 순찰 접점·소음 반경·계약 위치를 조정하며 맵 크기를 줄이는 것으로 대체하지 않는다.

운반 자동 검사는 빈손 경로의 문설주·기둥·코너 지점에 여유를 더한 별도 경유점을 사용한다. 원본 격자 경로가 모든 화물 자세에 안전하다는 의미는 아니다.
