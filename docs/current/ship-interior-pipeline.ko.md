# FLATBED 내부 제작 방식

[English](ship-interior-pipeline.en.md)

2026-09-14 · 제작 준비와 권고. 이번 작업은 기존 소스 조사·부품 분류·검증 순서 수립이며 신규 모델 제작이나 Unity 적용 완료가 아니다.

## 선택할 방식

**치수를 정한 Blender 구조 + 재사용 가능한 개별 부품 + Unity 기능 조립**을 사용한다. 사용자가 더 나은 방식을 선택해 진행하도록 요청했으므로 기존 디자인 04를 기준으로 이 방식을 제작 기준으로 제안한다. 내부 전체를 한 이미지에서 단일 메시로 생성하지 않는다. 모든 나사·패널을 별도 생성하는 방식도 피한다.

| 방식 | 이 프로젝트에서의 판단 |
|---|---|
| 내부 전체를 이미지에서 한 번에 3D 생성 | 분위기 탐색에는 쓸 수 있으나 숨은 면·출입구·치수·수정 가능성을 다시 확인해야 한다. 최종 플레이 공간 제작에는 채택하지 않는다. |
| 모든 요소를 별도 생성하고 Blender에서 조립 | 교체는 쉽지만 부품마다 두께·모서리·텍스처 크기가 달라질 수 있고 정리 비용이 커진다. |
| 구조 직접 제작 + 필요한 부품만 개별 제작 | 출입 치수를 통제하면서 대표 부품을 재사용한다. 최종 기능 조립을 Unity에 두어 모델 재수출로 상호작용이 사라지지 않게 설계한다. 권고 방식이다. |

## 현재 근거와 먼저 해결할 일

- 기준 이미지는 [디자인 04](../../art/ship-concepts-01/interior-design-04.png)와 [역방향](../../art/ship-concepts-01/interior-design-04-rear.png)이다. 두 이미지는 정밀한 정·역방향 도면이 아니다. 배치가 충돌하면 디자인 04의 전방을 바라본 배치를 기준으로 하나의 3D 배치에서 양방향을 렌더한다.
- [기존 제작 기록](ship-production.ko.md)과 [통합 스크립트](../../art/ship-flatbed-01/integrate.py)에 있는 내부 폭 4.352m는 출발점이다. 가구 설치 후 유효 통로 폭은 별도로 측정한다.
- 실제 모델에는 화물 바닥 0.6m, 조종 구역 1.2m와 계단이 있다. 평평한 바닥 시안과 다르다. 바닥만 제거하지 말고 창턱·눈높이·천장 높이를 함께 검토한다. 계단이나 실내 경사로를 임의로 복원하지 않는다.
- 후방 문과 외부 탑승 발판은 유지한다. 기존 문 설계 3m × 2.4m와 외장 절단 3.06m × 2.30m는 유효 통과 치수가 아니다. 중앙 엔진·문틀·열린 문·화물을 함께 놓고 검증한다. 엔진을 옮기거나 창 형상을 크게 바꿔야 한다면 변경 외형을 먼저 시각화해 검토한다.
- 기존 Angular/Integrated 모델은 보존한다. 새 내부 후보를 별도로 제작한다. 런타임 캐릭터와 화물의 실제 충돌 크기를 검사 기준으로 사용하며, 그림 속 인체 비율로 대신하지 않는다.

## 제작 단위

아래는 부품 종류다. 배치 개수·성능 예산·제작 완료 수를 뜻하지 않는다.

| 단위 | 제작과 재사용 방법 | 분리할 부분 |
|---|---|---|
| 객실 외피·바닥·천장 | Blender에서 선체 안에 맞춰 제작 | 외피, 충돌, 점검용 숨김 단위 |
| 직선 벽·모서리·천장 보강재 | 공통 단면의 모듈을 반복 배치 | 구역별 고정 구조 |
| 바닥 레일·고정 홈 | 대표 모듈 재사용, 작은 홈은 재질로 표현 | 실제 운반에 필요한 형상만 충돌 |
| 후방 문틀·문·외부 발판 | 기존 구조를 수정·재사용 | 문짝과 발판의 이동 축 |
| 중앙 대형 콘솔 | Blender로 정확한 화면 개구부와 외장 제작 | 외장, 화면 면, 조작 위치 |
| 좌우 보조 콘솔 | 중앙 콘솔과 재질·버튼 언어 공유 | 보조 화면 면 |
| 접이식 직원 좌석 | 대표 1개 제작 후 4개 배치 | 등받이·좌판, 번호 표시 |
| 화물 랙·결박 장치 | 기존 승인 랙을 우선 검토 | 선반, 화물 자리, 고정 표현 |
| 신호기 거치대 | 기존 신호기는 재사용, 거치대만 맞춤 | 장비 장착 위치와 상태등 |
| 충격봉 거치대 | 기존 충격봉은 재사용, 거치대만 맞춤 | 장비 장착 위치와 상태등 |
| 조명·배선·환기구 | 소수 대표 부품과 재질로 반복 구성 | 조명 발광 면, 배선 경로 |
| 표지·번호·사용 흔적 | 공통 텍스처와 별도 표시로 통일 | 위치별 의미 있는 마모·경고 |

Tripo는 기존 승인 이미지의 주요 부품에서 초안이 유용한 경우에 사용한다. 벽·바닥·문틀·화면 개구부처럼 치수가 중요한 형상은 Blender에서 만든다. Tripo 결과도 그대로 합치지 않고 크기·면·UV·재질을 정리한다. 승인된 외형에 없는 새 디자인이 필요하면 이미지 검토 원칙을 유지한다.

## Blender와 Unity의 경계

- Blender에 동일 좌표계의 조립 검토 장면을 두고 전방·후방·외부·단면을 같은 모델에서 출력한다. 반복 부품은 같은 원본을 재사용한다. 시각적으로 연결되지 않는 배관이나 장식은 넣지 않는다.
- 원본 `.blend`, 명시적으로 내보낸 `.fbx`, 텍스처, 제작 스크립트를 관리한다. 단일 메시로 합치지 않으며 움직이는 부분과 화면 면을 보존한다. 반복 부품은 부품별, 고정 외피는 구역별로 내보내는 것을 기본으로 한다.
- Unity에서 선체 아래 구조·가구·화면·장비·문을 하위 프리팹으로 구성한다. 모델은 외형을 공급하고 프리팹이 충돌·상호작용·조명·온라인 상태 연결을 소유한다. 재가져오기 때 이 연결이 유지되는지 검사한다.
- 중앙 화면은 독립된 화면 면에 동적 UI를 표시하는 방향이다. 글자를 외장 텍스처에 굳히지 않는다. 실제 구현은 기존 게임 디스플레이 방식을 확인해 재사용하며 한영 전환·가림·가독성을 검사한다.
- 회백색 도장·주황 강조·흑연색 바닥·청록 화면을 공통 재질로 묶는다. 나사까지 개별 고해상도 텍스처를 만들지 않는다. PSX 질감은 일관된 픽셀 밀도와 제한된 디테일로 만들고, 어두운 조명으로 모델 결함을 숨기지 않는다.

## 진행 순서와 통과 조건

1. **구조 시험:** 단색 외피·평평한 바닥·중앙 콘솔·후방 출구를 만든다. 창 시야와 머리 공간, 장비 조작 위치, 실제 화물 운반 부피를 검사한다. Unity에서 기본 출입을 먼저 확인한다.
2. **대표 구간:** 중앙 콘솔과 벽·바닥 일부만 최종 후보 수준으로 만든다. 실제 1인칭 거리에서 질감·문구 크기·모서리·조명을 비교한다. 이 구간의 품질 기준을 나머지 부품에 적용한다.
3. **전체 조립:** 좌석·랙·거치대·조명과 문을 적용하고 같은 모델의 양방향 및 후방 외관을 렌더한다. 장비와 화물 접근, 문·발판 동작 전체 구간을 검사한다.
4. **게임 검증:** 출입·화물 운반·화면·장비 회수·문 상태를 게임 기능에 연결한다. 실제 복수 프로세스에서 상태 일치를 확인하고 4인 출입·교행·성능을 검사한다.

- [ ] 실제 선체 안에서 평평한 바닥·창문·머리 공간이 함께 성립한다.
- [ ] 직원과 운반 화물이 후방 입구 및 열린 문·발판을 통과한다.
- [ ] 대표 구간을 실제 1인칭 카메라로 시각 검토한다.
- [ ] 모델 재가져오기 후 재질·화면·충돌·상호작용 연결을 유지한다.
- [ ] 복수 프로세스 상태 일치와 4인 출입·교행을 확인한다.

치수·UV·누락·파일 재가져오기 자동 검사는 구조 증거다. 조작감·가독성·공간의 답답함은 실제 조작 검토로 따로 기록한다. 이번에는 문서·소스 조사만 수행했으며 위 항목은 모두 미완료다.

## 2026-09-14 — 내부 브라우저 Tripo 확인

사용자 선호에 따라 Chrome 대신 Codex 내부 브라우저를 우선한다. 로그인된 작업 공간, 잔액 750, 기존 우주선 모델과 GLB·FBX 내보내기 메뉴에 실제로 접근했다. 기존 모델에서 두 형식의 내보내기를 시험했으나 다운로드 이벤트는 각각 20초 후 시간 초과였고 Downloads 폴더에서 새 파일을 확인하지 못했다. 제작 화면 조작은 확인했지만 신규 생성·업로드·다운로드 저장까지 완료 검증한 것은 아니다. 내부 브라우저의 영구적인 기능 미지원으로 단정하지 않는다. 생성 크레딧을 사용하지 않았고 기존 파일을 보존했다. 다운로드 완료 여부가 다음 검증 항목이다.

## 2026-09-14 — 파일시스템 판정으로 다운로드 성공

이 절은 앞선 로컬 저장 미확인 상태를 갱신한다. 내부 브라우저에서 기존 우주선 모델을 FBX로 내보내고 다운로드 폴더의 새 ZIP을 실제 확인했다. 브라우저 이벤트는 성공 기준으로 사용하지 않았다. 이전 실패의 정확한 원인은 확정하지 않으며, 이번 파일명·시점의 다운로드 성공을 근거로 기록한다.

- 파일: Windows Downloads의 NR_Flatbed_IAB_Check_20260914.zip, 4,856,994바이트.
- 2초 간격으로 검사해 크기·수정 시각이 2회 연속 같고 새 부분 다운로드 파일이 없음을 확인했다. 약 4.05초 후 완료 판정.
- ZIP CRC 검사 통과. FBX 바이너리와 JPEG 텍스처의 파일 시그니처도 확인했다. Blender 재가져오기나 신규 아트 품질 검토는 이번 범위가 아니다.
- SHA256: 25ce888b4483c25de862561a18b5b947148cac51f0d12265e9e261a1f0b32423.
- 새 생성과 크레딧 사용 없음. 다운로드 파일은 Downloads에 유지하고 기존 제작 원본을 덮어쓰지 않았다.

### 재사용 절차

[watch_download.py](../../tools/watch_download.py)는 Windows 터미널에서 실행한다. 먼저 이번 작업 전용 파일명을 Tripo에 지정하고, 다운로드 버튼을 누르기 전에 목록을 저장한다.

~~~powershell
python tools/watch_download.py --directory "$env:USERPROFILE/Downloads" --prefix NR_Asset_Check --state "$env:TEMP/nr-download-state.json" --prepare
~~~

내부 브라우저에서 Export를 누른 직후 다음을 실행한다.

~~~powershell
python tools/watch_download.py --directory "$env:USERPROFILE/Downloads" --prefix NR_Asset_Check --state "$env:TEMP/nr-download-state.json" --timeout 120 --interval 2
~~~

실제 저장 폴더가 다르면 directory를 바꾼다. 기존 파일은 제외하고 지정 접두사의 새 파일만 선택한다. 새 .crdownload 또는 .part가 남아 있으면 성공 처리하지 않는다. 안정된 ZIP은 CRC와 모델 포함 여부, GLB는 헤더 버전·전체 길이를 추가 검사한다. 현재 도구의 허용 출력은 ZIP 또는 GLB이며 단독 FBX는 지원하지 않는다. 120초 내 확인하지 못하면 TIMEOUT과 종료 코드 1을 반환하며 완료로 기록하지 않는다. 임시 스냅샷·다운로드 로그는 커밋하지 않는다.

자동 시험에서 기존 파일 배제, 부분 다운로드 보류, 새 안정 ZIP 승인 사례가 통과했다. 폴더 폴링은 이번 다운로드의 저장 확인 방법이며, 사이트 오류나 다른 저장 경로까지 자동 해결하는 기능은 아니다.
