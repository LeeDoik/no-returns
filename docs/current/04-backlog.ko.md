1. 이동·카메라·물리 운반과 2인 입력·소유권 기초 검증.

## 0.8.2 이후 권장 순서 — 제안

다음 목표는 CINDER DEPOT의 첫 배송을 데모 수준으로 다듬는 것이다. 현재 기능 구현과 자동 검사 통과를 사람의 협동 재미 검증으로 대체하지 않는다.

1. 현재 실행본으로 실제 사람 2명이 배송을 진행한다. 처음에는 추가 설명 없이 시도하고, 다음에는 운반·유인 역할을 바꿔 비교한다. 길을 잃은 구간, 억제 단계 인지, 신호기 사용 이유, 다운 원인, 귀환 가능 여부와 재도전 의향을 기록한다.
2. 관찰된 문제부터 동선·생물 압박·징후 전달을 조정한다. 대상 선택 진동과 의도적 이탈은 기존 미완료 항목으로 함께 검토한다. 보수·시간·속도를 출시값으로 확정하지 않는다.
3. 읽히는 동선이 확인된 구역부터 승인된 PSX 방향의 아트·조명·사운드를 적용한다. 이미지 승인 후 모델 제작 규칙을 유지한다. 우주선 출입구에서 첫 위험 구간까지 작은 구역으로 스타일을 먼저 확인한다.
4. 해당 배송 흐름이 안정되면 4인, 다른 PC와 지연 환경, Steam 연결 및 배포 준비로 넓힌다. 협동을 좌우하는 4인 문제는 콘텐츠 대량 제작 전에 검증한다.

첫 통과 판단: 팀이 경로와 역할을 선택하고, 위험 징후를 알아차리며, 실패 이유를 설명하고 다음 시도에서 다른 대응을 사용할 수 있는가. 이는 제안된 사람 평가 기준이며 현재 통과 상태가 아니다. 이번 우선순위 조사에는 코드·빌드·에셋 변경이 없다.

## 2026-09-13 — Steam 협동 서비스 요구

사용자 요구: Steam 친구·초대로 편하게 합류하고 판 정보를 저장하며, 클라이언트 조작을 통해 게임 상태를 임의 변경하지 못하게 한다. 요구는 확인됐으나 엔진 전환·서버 도입·비용 지출·구현은 확정하지 않았다.

권장 구조는 Steam 인증·로비·초대 + 운영자가 관리하는 권한형 게임 서버 + 서버 측 영구 저장소다. 방장을 포함한 플레이어 PC는 입력을 요청하고 서버가 이동·집기·공격·배송·보상을 검증한다. 저장소에는 신뢰하는 서버만 판 결과를 기록한다. 로비는 모임과 합류를 담당하며 게임 시뮬레이션 서버를 대신하지 않는다. 판마다 영구 실행 서버를 유지할 필요는 없으며, 비어 있는 판의 상태 저장 후 서버 자원을 회수하는 방식을 검토한다. 이는 미구현 제안이다.

대안: 방장 호스팅 + 로컬/Steam Cloud 저장은 운영 부담이 작지만 방장 조작을 신뢰 경계 밖으로 밀어낼 수 없다. 방장 호스팅 + 서버 저장만으로도 조작된 방장이 보내는 허위 결과를 신뢰하게 되면 부족하다. Steam Cloud는 파일 동기화이며 판 결과의 진위를 판정하지 않는다. 클라이언트 수정 자체를 완전히 차단할 수는 없으며, 서버 검증은 조작된 요청의 게임 상태 반영을 제한한다. 자동 조준 등 별도 부정행위까지 전부 해결하는 것은 아니다.

기존 [방장 저장](space-play-05.ko.md)은 로컬 진행 저장이며 근무 중 이어하기와 조작 방지는 미구현이다. 새 요구가 기존 기능의 완료를 뜻하지 않는다. 판 저장 범위(근무 중 정확한 복원 또는 우주선/근무 종료 체크포인트), 판 소유권·접근 권한, 방장 부재 시 재개 규칙, 운영 예산은 미정이다. Unity와 Unreal 모두 가능한 구조이며 엔진은 별도 판단한다.

검증 예정: 서로 다른 Steam 계정·네트워크의 초대/합류, 재접속과 저장 복구, 중복 보상 방지, 잘못된 이동·집기·보상 요청 거절, 권한 없는 판 접근 거절. 이번에는 문서·공식 자료 검토만 수행했다.
