권장 구조는 Steam 인증·로비·초대 + 운영자가 관리하는 권한형 게임 서버 + 서버 측 영구 저장소다. 방장을 포함한 플레이어 PC는 입력을 요청하고 서버가 이동·집기·공격·배송·보상을 검증한다. 저장소에는 신뢰하는 서버만 판 결과를 기록한다. 로비는 모임과 합류를 담당하며 게임 시뮬레이션 서버를 대신하지 않는다. 판마다 영구 실행 서버를 유지할 필요는 없으며, 비어 있는 판의 상태 저장 후 서버 자원을 회수하는 방식을 검토한다. 이는 미구현 제안이다.

대안: 방장 호스팅 + 로컬/Steam Cloud 저장은 운영 부담이 작지만 방장 조작을 신뢰 경계 밖으로 밀어낼 수 없다. 방장 호스팅 + 서버 저장만으로도 조작된 방장이 보내는 허위 결과를 신뢰하게 되면 부족하다. Steam Cloud는 파일 동기화이며 판 결과의 진위를 판정하지 않는다. 클라이언트 수정 자체를 완전히 차단할 수는 없으며, 서버 검증은 조작된 요청의 게임 상태 반영을 제한한다. 자동 조준 등 별도 부정행위까지 전부 해결하는 것은 아니다.

기존 [방장 저장](space-play-05.ko.md)은 로컬 진행 저장이며 근무 중 이어하기와 조작 방지는 미구현이다. 새 요구가 기존 기능의 완료를 뜻하지 않는다. 판 저장 범위(근무 중 정확한 복원 또는 우주선/근무 종료 체크포인트), 판 소유권·접근 권한, 방장 부재 시 재개 규칙, 운영 예산은 미정이다. Unity와 Unreal 모두 가능한 구조이며 엔진은 별도 판단한다.

검증 예정: 서로 다른 Steam 계정·네트워크의 초대/합류, 재접속과 저장 복구, 중복 보상 방지, 잘못된 이동·집기·보상 요청 거절, 권한 없는 판 접근 거절. 이번에는 문서·공식 자료 검토만 수행했다.

출처: [Steam 로비](https://partner.steamgames.com/doc/features/multiplayer/matchmaking), [인증](https://partner.steamgames.com/doc/features/auth), [Cloud](https://partner.steamgames.com/doc/features/cloud), [부정행위 대응](https://partner.steamgames.com/doc/features/anticheat).

### 2026-09-13 — 저장 범위 확정·권고

사용자가 우주선 귀환 시점의 돈·장비·진행도부터 이어하면 충분하다고 확인했다. 근무 중 화물 위치·전투 상태의 정확한 복원은 요구하지 않는다. 위 절의 저장 단위 미정 상태를 이 결정으로 대체한다. 세부 체크포인트 실패·재시도·귀환 전 연결 종료 시 처리 규칙은 후속 명세가 필요하다.

권고는 Unity 유지 + Steam 초대/로비 + 운영자 권한형 게임 서버 + 서버 체크포인트 저장이다. 현재 요구는 엔진 이식보다 직접 TCP 프로토타입의 네트워킹·판정·저장 구조를 서비스용으로 바꾸는 근거다. 기존 게임 로직 재사용 가능성과 전체 엔진 이식 범위를 고려한 판단이며 비교 성능 검증 결과가 아니다. 현행 네트워크 코드를 그대로 출시한다는 뜻은 아니다. 엔진 유지와 서버 도입은 권고이며 사용자 확정·구현 완료가 아니다. 비용은 동시 실행 판 수·지역·실측 서버 자원에 따라 산정해야 하며 아직 견적하지 않았다.

최소 검증 후보: 서로 다른 Steam 계정과 네트워크에서 초대 합류, 배송 후 귀환 체크포인트 저장, 전원 종료 후 재개, 중복 지급 거절, 잘못된 이동·보상 요청 거절. 판 소유권과 방장 부재 시 접근 권한은 여전히 미정이다. 코드 변경이나 실제 서버 배포는 없다.
