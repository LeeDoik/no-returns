# 배송 소품 제작

[English](psx-props-01.en.md)

0.8.5에서 높은 수령대는 제거했고 화면·표시등·소리·영수증 반응을 연결했다. 아래 0.8.4 상태는 제작 이력이다. [현재 수령 단말기](receipt-terminal.ko.md).

2026-09-13 · SPACE-ART-27 · 제작 중.

사용자는 cargo-receipt-clues-01 시트의 밀봉 상자와 수령 장치를 그대로 제작하도록 승인했다. 미스터리 소품·직원·장비·리스너는 이번 승인의 범위가 아니다. 기존 시설 6종은 재생성하지 않는다.

승인 시트에서 제작용 상자와 독립 수령 단말기를 분리 재구성했다. 원본 시안 파일은 보존했다. 단말기 화면의 문구는 Unity에서 별도로 표시하며 수령대는 기존 시설을 재사용한다. Tripo Smart Mesh P2.0 비공개로 각각 1개 먼저 제작한다. 모델 자체의 결함이 확인될 때만 재생성하고, 단위·피벗·재질·배치 오류는 로컬에서 수정한다.

완료 기준: 다운로드 압축·메시·UV 검사, 실제 모델 렌더 비교, 단위 변환을 보존하는 루트 구성, Unity 가져오기와 운반/수령 회귀 확인. 생성 완료만으로 게임 적용 또는 사용자 외형 승인 완료로 표시하지 않는다.

## 제작 결과와 적용 — 0.8.4

상자 3722삼각형, 단말기 9777삼각형. 각각 1개 생성, 재생성 0회. 1315에서 생성 65·텍스처 20을 각 모델에 사용해 총 170, 잔액 1145를 화면에서 확인했다. ZIP·UV·메시 검사와 Blender FBX 재가져오기 2종을 통과했다. 정면 렌더 이후 게임·후면 검사에서 상자 뒤의 불필요한 원형 장치를 발견해 해당 후면만 잘라내고 승인된 앞쪽 패널을 회전 복제해 질감과 모서리 보호대를 유지했다. Tripo 재생성은 하지 않았다. 단말기 받침의 세부 구조는 입력 이미지와 다르며 게임용 문구는 텍스처에 굽지 않았다.

512 텍스처, 바닥 중앙 피벗과 원본 FBX 변환을 보존하는 상위 루트로 Unity에 가져왔다. 상자 외형은 기존 0.8×0.65×0.65m 충돌 크기에 맞췄고 질량·소유·운반 규칙은 바꾸지 않았다. 수령 단말기는 기존 수령대 옆 (-8.1,0.8,9)에 0.75×1.6×0.65m 크기와 단순 충돌체로 배치했다. 기존 시설 6종과 수령 조건·보수는 유지한다. 화면·표시등의 동적 상태 연결과 영수증 배출 애니메이션은 미구현이며 현재 단말기는 외형이다. 기존 HUD가 배송 상태를 안내한다.

상자 후면의 단색 패널 시도는 취소했으며 최종 모델은 앞면의 텍스처·보호대를 재사용한다. 정면·후면 렌더를 모두 검사했다. 기존 소스와 실패 검토 렌더 이력은 보존한다.


최종 0.8.4 Windows 빌드 성공. 두 실제 Windows 프로세스에서 배송·수령·중복 보수 방지·귀환·잔액 유지·이탈 정산 등 자동 검사 14항목 통과. Blender 정면·후면과 Unity 소품 표시를 검토했다. 마지막 텍스처 후면 수정 뒤에는 빌드와 자동 배송 검사를 재실행했으며 기존 게임 캡처는 그 이전 후면을 포함하므로 최종 후면 외형 근거는 rear-review.png다. 사람의 조작감·재미·성능 측정은 미실시. 문서 검사 206개 통과.
