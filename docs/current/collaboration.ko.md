# Codex·Claude Code 공동 개발 제안

[English](collaboration.en.md)

2026-09-13 · 현재 0.8.1 기준의 작업 분담 제안. Claude 설치·연결·권한 설정, 작업 전달, Git 커밋·worktree 생성은 이번 조사에서 실행하지 않았다.

## 처음의 역할

현재 구현 맥락을 보유한 Codex가 핵심 게임 코드 통합·Unity MCP·빌드와 실행 검증을 맡고, Claude Code는 독립 검토부터 시작하는 것을 권한다. 모델의 우열을 주장하는 분담은 아니다. 기능마다 작성자와 검토자를 바꿔도 되지만 통합 책임자는 한 명으로 둔다. 사용자는 실제 조작감·공포·재미와 아트 승인 여부를 판단한다.

| 우선순위 | Claude에 맡길 일 | 결과물 |
|---|---|---|
| 1 | 외곽 생물·운반·다운·구조·정산의 독립 코드 검토 | 파일·줄, 발생 조건, 영향, 재현 여부, 최소 수정 제안 |
| 2 | 빠진 검사 설계와 별도 검증 도구 | 벽 뒤 추적, 대상 교체, 접속 해제, 중복 지급 등 경계 조건과 실행 근거 |
| 3 | 경제·압박 균형 분석 | 배송 소요 시간, 도주 여유, 장비 구매 효과, 악용 가능성에 대한 가설·비교표 |
| 4 | 범위를 분리한 제작 도구 또는 장비 실험 | 별도 파일·장면에서 제작한 도구/프로토타입과 통합 방법 |

경제 분석에서 현재 수치를 출시값으로 확정하지 않는다. 코드 검토만으로 오류 재현이나 재미 검증을 완료 처리하지 않는다. 승인 전 이미지로 모델을 제작하지 않는 기존 아트 규칙도 유지한다.

## 현재 프로젝트에서 겹치면 안 되는 작업

- 같은 파일을 두 세션이 동시에 수정하지 않는다. 작업마다 수정 가능한 파일, 바꾸지 않을 인터페이스, 결과물, 통과 기준을 명시한다.
- 처음의 검토는 게임 소스와 공용 문서를 읽기만 하고, 결과를 채팅에 보고한다. 검토 보고서를 저장할 때는 별도 한영 파일을 사용한다. 공용 현재 명세·변경 이력 반영은 통합 담당자가 정리한다.
- Unity 편집기/MCP, 빌드 출력과 실제 실행본 검사는 한 번에 한 작업만 사용한다. 현재 [CarryRoom](../../NoReturns/Assets/_NoReturns/Runtime/CarryLab/CarryRoom.cs)의 TCP 포트는 27841이다. 별도 코드 폴더만으로 같은 포트의 검사 충돌이 해결되지는 않는다.
- [MCP 래퍼](../../tools/unity_mcp.py)는 프로젝트 경로와 일치할 때 NoReturnsUnity 별칭을 사용한다. 다른 작업 폴더에서는 실제 연결 프로젝트와 출력 경로를 다시 확인한다. 현재 편집기에 무심코 연결해 원본을 수정하지 않는다.
- 코드 동시 제작을 시작하기 전에 현재 상태를 정리해 기준 커밋을 만들고, 해당 커밋에서 별도 worktree를 만든다. 조사 시 현재 게임 소스에 Git 미추적 파일이 있으므로 기존 HEAD만 복제하면 최신 구현이 빠질 수 있다. 이번에 커밋하거나 파일을 이동하지 않았다.

Claude Code는 별도 파일·브랜치를 가진 worktree 세션을 지원한다. 설치된 버전과 환경은 따로 확인해야 한다. [공식 worktree 문서](https://code.claude.com/docs/en/worktrees), 2026-09-13 확인.

## 첫 요청문

다음을 Claude Code에 전달할 수 있다. 이 문서 작성 자체로 작업이 전달되지는 않는다.

> NO RETURNS 0.8.1의 독립 코드 리뷰를 해줘. 먼저 AGENTS.md, docs/README.md, docs/current/02-spec.ko.md, docs/current/space-play-07.ko.md를 읽어줘. 게임 코드·장면·설정·공용 문서는 수정하지 말고, Unity MCP·빌드·게임 실행도 시작하지 마.
>
> 외곽 생물의 전역 탐색·벽 우회·표적 변경, 다운·구조·우주선 안전, 배송 보수·중복 지급, 접속 해제 시 상태 처리를 검토해줘. 정상 동작을 추측으로 버그라고 하지 말고, 각 발견에 파일·줄 번호, 발생 조건, 플레이 영향, 실제 재현 여부, 최소 수정 방향과 필요한 검사를 적어줘. 이미 통과한 자동 검사의 사각지대도 찾아줘. 현재 코드를 확인한 범위와 실행하지 않은 검사를 구분하고, 한국어로 우선순위가 높은 항목부터 보고해줘.

그 결과를 통합 담당자가 코드와 재현 조건으로 검토한 뒤 수정 → 검사 → 문서 갱신 순서로 반영한다. 독립 개발을 맡기는 다음 요청에는 파일 소유 범위와 Unity 사용 순서를 추가한다.
