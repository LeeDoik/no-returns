## 현재 규칙

폭 3m·깊이 2m, 중심 (-6,0,9)의 바닥 표시 안에 상자를 내려놓는다. 화물 중심 x=-7.05~-4.95, z=8.4~9.6, y=0.2~0.65m 내부에서 아무도 들지 않고 속도 0.2m/s 미만을 0.75초 유지하면 배송 확인된다. 이때 돈은 지급하지 않는다.

영수증 출력은 0.75초 뒤 완료된다. 단말기 2.4m 안에서 단말기를 바라보고 [E]로 회수한다. 팀원 누구나 회수할 수 있으며 팀 공용 소지품으로 기록된다. 별도 물리 운반이나 손 슬롯을 차지하지 않는다. 이미 회수한 영수증은 중복 회수할 수 없다. 팀이 모두 선내에 모여 [F] 귀환·정산할 때 일반 300+120=420, 위험 450+180=630을 한 번 지급한다. 성공 횟수도 이때 증가한다. 회수하지 않은 귀환·긴급 회수·근무 도중 연결 종료는 해당 근무 보수를 지급하지 않는다. 이전 근무에 받은 잔액은 유지된다. 다음 근무는 영수증 상태를 초기화한다.

## 외형과 제작 가이드

단말기 모델을 180도 돌려 배송 접근 방향으로 화면이 보이게 했다. 머리 위 추가 안내판을 제거하고 원본 CRT 안에 한국어·영어 상태 문구를 표시한다. 화면 중심 (-8.09,1.25,8.765), 슬롯 시작 (-7.96,0.84,8.691)은 실제 모델 표면 측정에 근거한다. 영수증은 슬롯에서 앞쪽으로 배출되고 회수하면 사라진다. 바닥 테두리·스캔·음향은 유지한다.

옆의 별도 Reception recorder와 가짜 영수증 외형을 제거했다. 해당 미스터리 단서는 기존 수령 단말기를 바라보고 [I]로 조사한다. 정비 단말기와 두 단서 원문은 보존한다. 새 3D 생성은 없다.

## 기술과 검증

[CarryMission.cs](../../NoReturns/Assets/_NoReturns/Runtime/CarryLab/CarryMission.cs)가 영수증 출력·회수·정산을 결정한다. [ReceiptFeedback.cs](../../NoReturns/Assets/_NoReturns/Runtime/CarryLab/ReceiptFeedback.cs)는 표시만 담당한다. 프로토콜 8로 회수·출력 상태를 공유하므로 양쪽 모두 0.8.6을 사용한다. 기존 0.8.5 즉시 지급 규칙과 별도 상태 패널은 폐기한다.

변경 전 검사에서 배송 즉시 돈이 지급되는 기존 동작을 재현했다. 검증 순서: 미회수·중복 회수·반환·중단 규칙 → 실제 2개 프로세스 → 화면·슬롯 확인 → Windows 빌드·문서 검사. 사람의 조작감·청감·재미와 인터넷 검증은 별도 미완료다.

## CRT 표면 텍스처 수정 — 0.8.7

별도 TextMesh와 글자 재질을 제거했다. 한국어·영어 상태 6종을 각각 256×256 텍스처로 만들고 원본 모델의 CRT 유리 표면에만 표시한다. 본체 텍스처는 유지한다. ReceiptCRT 셰이더는 불투명 깊이 쓰기·깊이 검사·뒷면 제거를 사용하므로 벽이나 단말기 자체에 가려진 글자는 보이지 않는다. UI 오브젝트를 화면 앞에 띄우지 않는다. 배송·영수증·보수와 프로토콜 8은 유지한다.

제작: tools/make_receipt_ui.py가 한/영 상태 텍스처를 생성한다. ReceiptUI/ReceiptCRT.shader의 유리 표면 마스크는 현재 단말기 배치에 맞춰 측정한 좌표를 사용하므로 위치·크기를 바꿀 때 함께 조정해야 한다. 검증은 동일 카메라에서 UI 두 상태를 렌더해 비교한다. 정면에는 변화가 있어야 하며 뒷면·차폐 벽 뒤는 변화가 없어야 한다.
