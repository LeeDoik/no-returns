# SPACE-PLAY-02 — 시야 운반과 첫 배송 루프

[English](space-play-02.en.md)

2026-09-12. 승인된 다음 단계의 내부 검증 계획. writing-plans 절차로 범위와 통과 조건을 정리한다.

1. 현재 상자가 수평 방향만 따르는 실패를 두 실행본 검사에 추가한다. 눈높이 기준 로컬 오프셋을 전체 시점으로 회전하고 벽·바닥 충돌을 유지한다. 방장과 참가자 모두 상하 시점·소유권·충돌을 검사한다.
2. CarryRoom 운반 모드를 보존하고 `--delivery` 실행 모드를 추가한다. 임시 실험실의 뒤쪽을 선내 구역, 기존 선반을 수령대로 사용한다. CINDER DEPOT 실제 맵이나 최종 아트 제작은 아니다.
3. 선내 F로 CINDER DEPOT 선택, 다시 F로 전원 탑승 확인 후 자동 도착. 이동 연출은 상태 전환으로만 표현한다. 수령대에 화물을 놓아 안정되면 수령 확정, 전원 선내에서 F로 귀환·정산, F로 새 근무를 준비한다. 선외 F·운반 중 수령·반복 지급은 거절한다.
4. 경제 초안의 정상 화물만 사용: 수령 300 CR, 전원 귀환 120 CR, 총 420 CR. 공용 지갑은 세션 메모리에만 있으며 손상·죽음·구매·저장은 아직 없다. 이 모드에서 근무 중 신규 입장을 막고, 연결 종료 시 해당 근무를 정산 없이 중단하여 누락 직원 보너스 지급을 막는다. 이미 받은 수령 보수는 유지한다. 이는 임시 제한이며 최종 재접속 규칙이 아니다.
5. 두 프로세스로 상태·수령·지갑 일치, 빈 귀환 무보수, 중복 지급 방지 및 다음 근무 초기화를 검사한다. 자동 검증과 사람 조작감·재미 평가를 구분한다. Windows 빌드와 한영 명세·가이드·검증·변경 이력을 함께 갱신한다.

구현 파일: CarryRoom은 입력·운반 통합, CarryMission은 근무 상태·정산, CarryWire는 상태 복제, CarryWorld는 임시 표식, CarryBuild는 빌드. 자동 입력은 일반 이동·상호작용을 사용하고 순간이동은 추가하지 않는다.

## 실행과 제작

[배송 모드 실행](../../04_Play_Delivery_Loop.cmd) → HOST, [같은 PC 참가](../../05_Join_Local_Delivery.cmd). 두 창 모두 같은 빌드를 사용한다. WASD·마우스·E 조작은 기존과 같으며 F가 선내 행동이다. 배송 모드에서 R 초기화는 막는다. 기존 [운반 모드](carry-test.ko.md)도 유지한다.

청록 바닥이 선내 구역이며, 황금색 선반이 수령대다. (x=1, z=5) 쪽으로 벽을 돌아 (x=-6, z=9) 선반에 접근한다. 상자를 바라보며 E로 든 뒤, 선반 위에서 E로 놓는다. 화물을 내려놓고 0.75초 안정되면 수령 처리한다. 시선에 따라 높이를 조절할 수 있다. 귀환은 선내에서 연결된 전원이 모인 뒤 F다. 배송하지 않고 귀환하면 0 CR이다.

[CarryMission.cs](../../NoReturns/Assets/_NoReturns/Runtime/CarryLab/CarryMission.cs)가 근무 상태와 중복 지급 방지를 담당한다. 선내 범위는 |x|<3, -10<z<-3.8, y<2다. 수령은 화물 중심 -7.05<x<-4.95, 8.6<z<9.4, 1.15<y<1.5와 속도 제곱<0.04로 판정한다. 정확한 범위는 현재 임시 지형 전용이다. 보수는 방장만 결정하고 프로토콜 3로 복제한다. 다른 버전끼리 접속하지 않는다.

상태: 준비 → 항로 선택 → 현장 → 수령 완료 → 정산. 현장에서 미배송 귀환도 가능하다. 정산의 F는 새 근무이며 지갑은 유지하고 화물·직원 위치를 초기화한다. 출항·착륙은 즉시 상태 전환이므로 비행·실제 우주선·현장 로딩을 구현한 것은 아니다. 저장하지 않으므로 프로그램 종료 시 잔액은 사라진다.
