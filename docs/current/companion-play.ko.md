## 실행과 조작

- 화면 왼쪽 사용자 창 1개(방장) + 오른쪽 자동 동료 창 1개(참가자)를 같은 너비로 연다. `나 + 자동 동료` 표시가 있는 사용자 창을 선택해 기존 키보드·마우스로 움직인다. 봇은 키보드/마우스를 읽거나 커서를 잠그지 않는다. 기존 조작 설정·Esc 메뉴를 사용한다.
- 현재 Cinder 맵에서 위험 없는 관찰 모드로 시작한다. 배송 진행·출발·구매·생물·억제 타이머·진행 저장은 동작시키지 않는다. 상자 운반과 진압봉 표시/6초 재사용 대기는 확인할 수 있다. 실제 배송/전투 검증은 기존 4인 모드와 별개다.
- 봇은 약 **32초** 주기로 대기(0–3초), 걷기·옆걸음(3–11초), 느린 이동(11–16초), 점프(16–19초), 진압봉(19–22초), 가까운 상자 접근·운반(22–30초), 내려놓기(30–32초)를 반복한다. 직원 모델은 현재 대기/걷기 두 동작을 재사용하며 새 전용 점프/공격 애니메이션을 제작한 것은 아니다.
- 사용자와 **6m** 넘게 멀어지면 따라오기를 우선한다. 보통 사용자 앞쪽 약 **2.7m**를 목표로 움직인다. 상자는 사용자에서 **7m** 안에 있고 아무도 들고 있지 않을 때만 시도한다. 사용자가 들고 있는 상자를 강제로 빼앗지 않는다.
- 바닥 확인과 짧은 충돌 검사로 가까운 장애물을 피한다. 복잡한 미로·다층 경로 전체 탐색은 하지 않으므로 막다른 곳에서는 가까운 열린 공간으로 이동해 확인한다. 멀어진 봇을 순간이동시키지 않는다.
- 종료는 [기존 종료 바로가기](../../08_Stop_Cinder_4P.command) 또는 아래 stop 명령을 사용한다. 다른 시험이 실행 중이면 새 실행을 거절하며 기존 창을 임의로 닫지 않는다.

```sh
python3 tools/cinder_four_player.py start --companion
python3 tools/cinder_four_player.py stop
# 코드 변경 후 준비: 게임 창을 열지 않는 빌드와 자동 검사
python3 tools/cinder_four_player.py build
python3 tools/test_cinder_companion.py
```

[실행기](../../tools/cinder_four_player.py)는 정확히 두 실행본만 시작한다. 방장은 실제 입력을 받고 참가자는 [동료 입력 코드](../../NoReturns/Assets/_NoReturns/Runtime/CarryLab/CarryRoom.Companion.cs)를 사용한다. 이동/점프/집기/놓기 요청은 기존 네트워크와 방장 판정을 거친다. 연습 진압봉은 피해 없는 표시 검사다. 봇 준비 응답이 없으면 두 프로세스를 정리하고 실패를 알린다. 오래된 빌드라면 먼저 재빌드한다.

테스트 전용 옵션은 `CARRY_TEST_AUTOMATION` 또는 Unity Editor에서만 활성화한다. 일반 실행은 기존 동작을 유지한다. 최초 구현 기록은 게임 **0.9.7**, 프로토콜 **13**, TCP **27842**이며 [버전 설정](../../NoReturns/ProjectSettings/ProjectSettings.asset)이 근거다. 직원 에셋의 [로컬 준비 조건](employee-animation.ko.md)은 그대로 적용한다.
