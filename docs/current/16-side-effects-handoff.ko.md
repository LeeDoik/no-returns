## 전달할 작업 요청

SIDE EFFECTS / 부작용 원정대의 첫 협동 프로토타입을 구현하라. 목표는 **동료를 밀어버린 회복 마법을 다음에는 의도적인 이동·구조 기술로 활용하는 경험**을 실제 플레이로 검증하는 것이다. 랜덤 보상이나 콘텐츠 양보다 안정적인 조작, 이해 가능한 부작용, 사고 후 재참여를 우선한다.

기획 원문은 [아트·Core Fun·Core Loop](14-side-effects.ko.md)다. 구현 시 executing-plans 스킬로 아래 단계를 순서대로 실행하고 체크박스를 갱신하라. 이 문서는 코드가 포함된 상세 작업 계획을 대신하는 인수인계서다. 최신 코드를 확인한 뒤 첫 단계에 필요한 파일·인터페이스·검사 명령을 구체화하고 구현으로 이어가라. 단순한 계획 제출로 종료하지 말고 승인된 범위의 실행 가능한 결과까지 진행하라.

## 현재 상태와 시작점

- 먼저 `AGENTS.md`, [문서 홈](../README.md), 기획 원문, [Unity 환경](14-unity-environment.ko.md), [Unity 조작 명세](15-unity-controls.ko.md)를 읽는다.
- 확인된 기반은 `unity/NoReturns`의 Unity 6000.6.0f1, URP 17.6.0, Input System 1.19.0이다. 실제 버전은 `ProjectSettings/ProjectVersion.txt`와 `Packages/manifest.json`을 재확인한다. 이번 인수인계는 기존 Unity 프로젝트 활용을 권장한다.
- `Assets/_Project/Scenes/CarryLab.unity`는 솔로 이동·운반 실험실이다. 인계 당시 네트워크 라이브러리가 없었으며, 이번 독립 장면에 공식 Unity Transport 6.6.0을 추가했다.
- `Assets/_Project/Runtime/WorkerController.cs`는 CarryMotor 의존성과 직접 입력 처리가 있다. 그대로 새 플레이어에 붙이지 말고 이동·카메라 패턴을 참고한다. 입력 속도와 별개로 외부 밀치기 속도를 유지해야 한다. 매 프레임 입력으로 반동을 지워서는 안 된다.
- 작업 전 변경 파일과 다른 작업의 담당 범위를 확인한다. Godot 게임, Development, CarryLab, 기존 실행 파일·저장 데이터를 보존한다. 기존 미커밋 변경을 일괄 되돌리거나 커밋하지 않는다.

## 첫 결과물과 제외 범위

첫 결과물은 별도 SideEffectsLab 장면과 Windows 실행본이다. 2–4인 연결, 연습 공간 1개, 전투 방 1개, 이동 방 1개, 도구 3종, 적 2종, 돌풍 변수 1종, 다운·끌기·구조·전멸·재시작을 포함한다. 원정의 20–30분 목표는 완성 게임 방향이며 이 짧은 실험실의 길이를 억지로 늘리지 않는다.

전투 방은 적 처치, 이동 방은 건너편 스위치 작동과 출구 도달로 완료한다. 모든 필수 목표는 기본 이동으로 접근할 우회로가 있어야 한다. 방 종료 보상은 기존 도구 유지 또는 제시된 도구 교체로 한정한다. 임시 결과 화면은 구조·합동 행동과 다시 시작을 제공한다.

보스, 영구 성장·저장, 안전실 보상 경제, 대규모 절차 생성, 매치메이킹, Steam, 내장 음성, 시청자 투표, 자동 영상 편집, 최종 아트 양산은 후속 범위다. 이 제외 항목을 구현 완료로 표시하지 않는다.

## 구현 구조와 기술 원칙

아래 경로는 `unity/NoReturns` 기준의 신규 제안이다. 기존 이름과 충돌하면 같은 책임을 유지하며 경로 변경을 기록한다.

| 경로 | 책임 |
|---|---|
| `Assets/_Project/SideEffects/Scenes/SideEffectsLab.unity` | 별도 실행 장면 |
| `Assets/_Project/SideEffects/Runtime/Player/` | 입력, 이동·외부 속도, 체력·다운·구조 |
| `Assets/_Project/SideEffects/Runtime/Tools/` | 도구 정의, 사용 요청, 범위 검사, 회복·밀치기·끌기 |
| `Assets/_Project/SideEffects/Runtime/Network/` | 연결, 권한, 상태 복제, 중복 요청 방지 |
| `Assets/_Project/SideEffects/Runtime/Rooms/` | 목표, 적, 방 전환, 시드와 환경 변수 |
| `Assets/_Project/SideEffects/Runtime/UI/` | HUD, 조준 예고, 도구 선택, 결과 화면 |
| `Assets/_Project/SideEffects/Data/` | 도구·전투·이동의 조정 가능한 설정 |
| `Assets/_Project/SideEffects/Tests/` | 규칙 검사와 실제 장면·네트워크 검사 |
| `artifacts/side-effects/` | 검사 로그, 양쪽 클라이언트 영상·스크린샷 |

입력 → 행동 요청 → 권한 있는 시뮬레이션 → 결과 상태 → 시각 효과로 분리한다. 요청에는 발신 플레이어, 도구 ID, 순번, 조준 방향을 포함한다. 서버/호스트는 소유권·쿨다운·다운 상태·거리·가림을 검사하고 실제 대상을 결정한다. 체력·밀치기·보상은 한 번만 적용한다. 클라이언트가 전달한 명중 결과를 그대로 믿지 않는다.

호스트 권한 방식을 기본 제안으로 삼는다. 기존 호환 패키지가 있는지 먼저 확인하고, 없으면 Unity 공식 네트워크 선택지의 현재 공식 문서·Editor 호환성을 확인한 뒤 선택 이유와 고정 버전을 기록한다. 온라인 서비스를 자동 결제하거나 계정을 추가하지 않는다. 첫 연결은 직접 주소 또는 로컬 접속으로 성립시킨다. 호스트 이탈은 안내 후 세션 종료로 처리하며 호스트 이전은 범위 밖이다.

CharacterController에는 별도 외부 속도 경로를 두고 충돌 이동과 함께 처리한다. Rigidbody 금속 소품에는 물리 힘을 사용한다. 조작 캐릭터를 완전한 래그돌로 만들 필요는 없다. 입력 반응과 권한 상태 보정을 분리하고 지연 환경에서 조작감과 위치 오차를 측정한다.

## 작업 순서와 통과 조건

- [x] **A. 독립 장면·기본 조작:** 새 장면에 이동·점프·회피·기본 공격·카메라를 만든다. WASD, 마우스, Space, Shift, 좌클릭, 우클릭 도구, E 상호작용을 초기 배치로 삼는다. 벽·경사로·가장자리에서 이동하고 커서 해제 시 공격이 나가지 않는지 확인한다. CarryLab 회귀 검사를 통과한다.
- [x] **B. 가장 작은 협동 검증:** 2개 실제 프로세스로 연결하고 회복 지팡이의 회복·밀치기와 다운·구조를 구현한다. 호스트→클라이언트와 클라이언트→호스트 양방향 사용, 중복 요청, 범위 밖 요청을 검사한다. 양쪽 체력·다운 결과가 일치하고 충격이 중복되지 않아야 한다. 로컬 대역 캐릭터만으로 협동 완료를 선언하지 않는다.
- [x] **C. 도구와 전투:** 자석 방패, 반동 망치, 금속 근접 기사와 공격 예고를 가진 원거리 적을 추가한다. 자석은 금속만 끌고 벽 너머 대상을 끌지 않는다. 망치 반동은 입력 중에도 유지되고 벽을 통과하지 않는다. 회복 범위 예고와 실제 적용 범위가 맞는지 확인한다. 아군 연속 부작용 보호는 밀치기를 막되 정상 회복까지 누락시키지 않는다.
- [x] **D. 짧은 루프·랜덤·복구:** 연습→전투→이동→결과→재시작을 연결한다. 호스트가 시드·방 구성·보상 후보를 결정한다. 돌풍 유무로 동일 공간을 비교하고, 도구 유지·교체 모두 진행 가능하게 한다. 낙하는 구조 발판 또는 마지막 안전 위치의 다운으로 처리한다. 전원 다운·클라이언트 이탈·재시작 시 이전 체력·도구 효과·오브젝트 소유권이 남지 않는지 검사한다.
- [ ] **E. 읽히는 아트·HUD와 확장 검증:** 큰 장갑·망토·모자 형태를 임시 모델로 구별하고 배경 남색·청록, 회복 민트색 고리, 위험 호박색 패턴을 적용한다. 색만으로 구분하지 않는다. HUD는 현재 목표, 동료 다운, 체력, 도구 이득·부작용, 쿨다운을 표시한다. 4개 프로세스와 Windows 빌드를 검사하고, 사람이 첫 사고 후 의도적인 활용에 도달하는지 관찰한다.

각 단계는 실패를 재현하는 규칙·통합 검사 → 최소 구현 → 같은 검사 통과 → 직접 장면 확인 → 문서·증거 갱신으로 진행한다. 단순히 구현을 복사한 테스트는 만들지 않는다. 네트워크 검증이 막히면 원인과 진행 가능한 로컬 범위를 기록하되 협동 완료로 넘기지 않는다.

## 수치 결정과 검증 시나리오

이동 속도, 도구 힘·범위·쿨다운, 외부 속도 감쇠, 연속 적용 보호, 구조 시간·부활 체력은 설정 자산에서 조정한다. 개발 에이전트가 최소 실험값을 선택하고 선택 근거·단위를 문서에 기록한다. 회복 발사로 지름길을 건너되 기본 점프 우회도 가능한 공간을 먼저 만들고 힘을 조정한다. 기존 운반 속도를 최종 액션 속도로 고정하지 않는다.

필수 검사: 만피 회복에도 의도한 밀치기 적용, 보호 중 회복 성공·중복 밀치기 차단, 다운 중 공격 차단·도움 요청 가능, 구조자의 거리 이탈 시 구조 취소, 벽 너머 회복·자석 차단, 방 전환·재시작 후 잔여 힘 제거, 고정 시드로 방·보상 선택 재현. 고정 시드가 물리 궤적까지 완전히 동일함을 보장한다고 주장하지 않는다.

네트워크는 정상 환경과 왕복 지연 100ms·패킷 손실 1%의 실험 조건을 비교한다. 이 값은 측정 조건이며 출시 품질 합격선이 아니다. 각 조건의 최종 체력·상태 불일치, 중복 효과, 위치 보정 크기를 기록한다. 별도 PC 검증 여부를 다중 프로세스와 구분한다.

사람 플레이에서는 첫 실수 후 두 번째 시도에 계획이 달라지는지, 사고 원인을 설명하는지, 구조가 반복 노동이 되는지 관찰한다. 자동 검사는 재미를 증명하지 않는다. 사람 참여가 없으면 플레이테스트용 빌드와 절차까지 제공하고 재미 검증은 미완료로 보고한다.
