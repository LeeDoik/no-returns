# CINDER 배송 데모 구현 계획

[English](cinder-demo-plan.en.md)

2026-09-18 · CINDER-DEMO-01 · 사용자 승인한 한 사이클 연결 작업

목표: 기존 블록아웃과 선내 시험을 보존하고 별도 CinderDeliveryDemo 장면에서 1~4인 계약·운반·배송·영수증·귀환·보급을 연결한다. 방장 권한과 E/Q, 한국어 기본·영어 전환을 유지한다. 10~15분은 사람 플레이 목표이며 실측 확정이 아니다.

- [x] CinderDemoLayout에 선내 스폰·적재·수령 구역을 정의하고 기존 CarryMission/ReceiptFeedback/CarryEquipment/CarryRoom 좌표 분기를 연결한다. 기존 수령 좌표 회귀와 Cinder 수령 판정을 각각 검사한다.
- [x] CinderDemoBuild로 기존 블록아웃을 새 장면에 복사하고 실험 조작기를 제거, CarryRoom을 배치한다. 생성 메뉴와 Windows 실행 메뉴를 추가한다.
- [x] CarryThreat의 탐색 영역과 순찰을 맵에 맞춘다. 첫 연결은 B구역 리스너 1체와 외곽 1체로 검증한다. A/C 추가 개체·균형은 다음 검증 대상으로 분리한다. 억제 제안값은 360초에 불안, 480초에 임계, 600초에 꺼짐, 608초에 침입이다.
- [x] 두 실제 프로세스에서 준비·운반·수령·영수증·귀환420CR·보급120CR·다음 근무 초기화를 검증한다. 솔로·4인과 위험 상태 동기화도 별도 검사한다.
- [x] 한영 현재 명세·가이드·미완료·검증·변경 이력을 갱신하고 변경 범위만 커밋·전용 브랜치 푸시한다.

기초 실패 확인: 기존 CarryMission은 (32.7,.4,15)에 안정된 화물을 둬도 배송되지 않음. Unity MCP의 실제 C# 평가에서 EXPECTED RED 예외 확인. 이 실패를 새 맵 수령 연결 후 통과시킨다. 자동 통로/네트워크 검사는 사람 조작감·재미·10~15분 길이 검증을 대신하지 않는다.
