# 구조 검증 우선 에셋 제작

[English](art-structure-first.en.md)

2026-09-14 · 사용자가 요청한 새 기본 파이프라인. 모든 신규·재제작 에셋에 적용한다. 이번에는 천장 수정 구조 시험까지만 진행하며 Tripo 생성·크레딧 사용은 하지 않는다.

## 순서와 승인

1. **Blender 구조 제작:** 실제 미터 단위로 외곽 크기, 통로, 문, 화면 면, 손잡이, 피벗과 결합 위치를 만든다. 캐릭터·화물의 실제 충돌 크기도 함께 배치한다. 내부 전체를 하나의 생성 메시로 합치지 않는다.
2. **Unity 배치:** 실제 1인칭 시점과 조작으로 시험한다. 구조 모델의 충돌·상호작용 기준은 시각 모델과 분리해 유지한다.
3. **사람의 플레이 확인:** 사용자가 크기·분위기·동선에 의견을 주고 수정한다. 자동 충돌 검사는 보조 근거이며 재미·답답함의 승인을 대신하지 않는다. 만족했다는 확인 전에는 해당 부품의 Tripo 제작으로 넘어가지 않는다.
4. **아트 기준 고정:** 승인된 구조에서 정면·후면·측면·윗면과 실제 시점 이미지를 출력한다. 치수, 개구부, 화면 면, 피벗, 재질 구역, 보존할 실루엣을 함께 기록한다. 기존 이미지 승인 원칙을 유지하고 새 외형은 생성 전에 확인받는다.
5. **Tripo 외형 후보:** 검증한 구조를 기준으로 부품별 외형 후보를 만든다. 현재 도구에서 지원되는 입력 방식은 실행 시 확인한다. 업로드한 구조를 손상 없이 자동 고급화하는 기능으로 단정하지 않는다. PSX의 각진 실루엣·제한된 질감과 공통 색채를 유지하며 고폴리 자체를 품질로 보지 않는다.
6. **Blender 맞춤·검수:** 결과를 승인 구조에 겹쳐 크기, 통로, 화면 개구부, 움직이는 부품, UV와 재질을 검사한다. 어긋난 곳은 직접 수정하고 치수가 중요한 벽·문틀·화면은 승인 구조를 유지한다. 단순 구조까지 반드시 Tripo로 재생성할 필요는 없다.
7. **Unity 외형 교체·재시험:** 외형만 교체하고 충돌·상호작용·온라인 연결을 보존한다. 출입, 점프, 화물 운반, 화면 가림, 문 동작과 재가져오기를 다시 검사한다. 실제 사람의 최종 시각·조작 검토 후 완료한다.

## 부품별 보관과 통과 조건

구조 원본, 승인 시점 이미지, 치수·피벗 표, Tripo 원본, Blender 정리본, 게임용 FBX·텍스처·Unity .meta, 자동 검사와 사용자 의견을 연결한다. 이전 승인본은 보존한다. 원본 모델·이미지는 Git LFS, 제작 코드와 한영 문서는 일반 Git으로 관리한다. 빌드·로그·인증정보는 제외한다.

- [ ] 구조와 실제 카메라·캐릭터·화물 크기가 일치한다.
- [ ] 사용자가 구조 플레이에 만족해 아트 제작으로 진행하도록 확인했다.
- [ ] 승인 이미지와 구조 기준으로 외형을 제작했다.
- [ ] 외형 교체 후 통로·점프·손잡이·화면·피벗이 유지된다.
- [ ] 자동 검사와 사람의 품질 검토를 각각 기록했다.

현재 우주선은 두 번째 항목 이전의 반복 검증 중이다. [구조 시험](ship-interior-trial.ko.md) · [선내 부품 제작 가이드](ship-interior-pipeline.ko.md).

## 2026-09-15 — 우주선은 내부부터 제작

우주선은 실내 업무·동선·실제 플레이를 먼저 만든다. 실내 배치를 사용자와 확인한 뒤 그 외곽에 구조 두께·설비 여유를 더해 외장 치수를 정하고, 외장 아트 시안을 승인받아 제작한다. 외장 시안에 실내를 억지로 압축하지 않는다. 실내 시험 때는 가림과 출입 검증을 위한 임시 덮개만 사용한다. 현재 제작 스크립트도 기존 외장 파일을 읽지 않고 빈 Blender 장면에서 실내부터 만든다.

새 내부 후보는 우주 배송선의 검사·밀폐 보관·송장 작업 구역을 비대칭으로 배치한다. 자동 검사와 사용자 만족은 별도이며, 검사 장치·보관함·송장기는 이번에는 구조 모형이다. 새 경제·화물 규칙을 승인한 것으로 보지 않는다.
