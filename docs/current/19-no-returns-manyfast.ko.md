## 한 줄 정의

NO RETURNS — 살아 있는 택배를 싣고 출근해, 친구들과 경로를 고르고 사고를 수습하며 배송을 마치는 1–4인 3D 3인칭 협동 배송 원정 게임. PC·Steam 출시를 지향하며 Unity를 메인으로 개발한다.

## 결정과 현재 상태

2026-09-12 개정 3. 사용자 결정: SIDE EFFECTS 폐기, NO RETURNS 구체화. 마법 도구·전투·보스 중심 기획과 이전 구현 지시서는 활성 요구사항이 아니다. 기존 NO RETURNS 배송 원정 방향과 D안 아트를 이어간다.
현재 Unity는 CarryLab의 이동·카메라·물리 운반·던지기 단계다. Godot의 캠페인과 EXP-01 배송·계약·저장·온라인은 참조 구현이며 Unity 이식 완료가 아니다. 아래 상세 설계는 제안이며 출시 사양·재미 검증 완료를 뜻하지 않는다.

## Core Fun

핵심 재미는 성격 있는 화물을 다루며 팀이 배송 방법을 만들어 가는 것이다.
운반 숙련: 잡는 방향·던지는 힘·받는 위치를 맞춘다.
협동 판단: 누가 길을 열고, 누가 운반하고, 누가 회수할지 상황에 따라 교대한다. 고정 운전자나 대기 전담 역할은 두지 않는다.
배송 순서: 재채기 상자를 바로 납품할지, 다른 배송의 지름길을 여는 데 먼저 쓸지 결정한다.
성취 보존: 완료한 배송은 남고, 사고는 회수·우회·재배치 문제로 이어진다. 시청자 없이도 친구끼리 재미가 성립해야 한다.

## 해결하려는 경험 문제

검증 가설: 목적지까지 반복해서 걷기만 하면 배송이 노동이 된다. 불명확한 잡기 판정과 카메라 가림은 물리 개그보다 짜증을 만든다. 사고 한 번으로 이미 끝낸 성과가 사라지면 재도전이 부담스럽다. 한 사람이 해결하고 나머지가 기다리면 협동의 의미가 줄어든다. 실제 빈도와 영향은 사람 플레이로 확인한다.

## 제품 설계

아트: 승인된 D안의 장난감 우편 마을, 작업복 직원, 표정 있는 골판지 화물, 바닥 매립 컨베이어를 유지한다. 팀 색에 이름·문양을 병용하고, 재채기 준비·접착 남은 상태·점프 예고는 동작과 소리로 읽히게 한다. 판타지 전투 아트로 전환하지 않는다.
트럭: 고정 주차된 공동 준비·장비 교환·귀환 거점. 직접 운전은 제외한다.
계약: 기존 확장안의 후보 5종 중 3종을 선택하는 구조를 제안한다. 목적지·화물·수령 조건·보상·알려진 통로 상태를 수락 전에 공개한다. 기본 계약은 시간 제한 없이 진행한다.
계약 내용: C01 Paper Please는 재채기 화물을 가게 받침에 배송하며 종이 장벽 지름길과 우회로를 비교한다. C02 Rooftop Greens는 점프 화물을 옥상 수령대에 배송하며 계단과 동료 받기를 비교한다. C03 Hold Tight는 접착 화물을 정비대에 배송하며 바닥 우회로와 지정 접착 면을 비교한다. C04 Quiet Delivery는 일반 화물을 창고에 배송하며 넓은 길과 좁은 선반 길을 비교한다. C05 Counter Service는 일반 화물을 셔터 안으로 배송하며 동료의 발판 조작과 솔로 옆문을 비교한다. 시설 접착·장벽 해제는 신규 설계이며 Unity 현재 기능이 아니다.
맵: 접수 광장과 상가 골목·옥상·설비 뒤뜰을 연결한다. 각 목적지는 안전 경로, 선택 경로, 낙하물 회수 경로를 가진다. 특정 화물을 먼저 배송해도 다른 계약을 막지 않는다.
랜덤: 검증된 공간의 연결·계약 조합·일부 장치 상태를 근무 시작에 선택하고 참가자에게 동일하게 전달한다. 운반 중 조작 규칙을 무작위로 바꾸지 않는다. 필수 경로 단절·회수 불가 배치는 제외한다. 첫 검증은 고정 배치에서 한다.
장비: 고정끈 60/1칸, 경사판 120/2칸, 수레 180/2칸, 공용 예산 4칸은 기존 실험 제안이다. 전부 해금해도 적재 선택은 남는다. 첫 근무는 구매 없이 완료 가능해야 한다. 가격과 물리 성능은 플레이 결과로 조정한다.
보상: 기본 배송당 30, 기본 3건은 90을 출발점으로 검증한다. 배송 확정 순간 한 번만 지급하고 이후 사고로 회수하지 않는다. 오배송은 화물을 현장에 남기고 이유를 알려준다. 품질·추가 시간 보너스는 기본 루프 이후 검증한다.
사고: 접근 가능한 화물은 직접 회수한다. 접근 불능이면 이미 지나온 안전 위치나 트럭으로 계약을 유지해 복구한다. 직원 구조로 화물을 순간 운반하지 않는다. 긴 관전·영구 부채를 핵심 벌칙으로 삼지 않는다.
UI: 중앙에 집기 대상·불가 이유, 화물에 목적지와 반응 예고, HUD에 선택 계약·완료 상태·확보 보상을 둔다. 계약 상세는 준비 화면에, 이동 중에는 현재 목표와 동료 핑에 집중한다. 귀환 전에 미배송 포기 목록을 보여준다.
온라인·저장: 방장이 계약·화물 소유·배송·지급을 확정한다. 중복 요청·재접속으로 화물이나 돈을 복제하지 않는다. 손님도 회사 공용 장비를 사용한다. 방장 이탈은 종료 안내와 확정 성과 보존으로 처리한다. Unity 네트워크 선택과 진행 중 근무 재개는 별도 결정한다.

## 차별화 가설

화물은 목적지로 옮길 대상이면서 배송 방법을 바꾸는 환경 도구다. 배송 순서가 맵 활용에 영향을 주고, 같은 화물도 안전하게 운반하거나 위험을 감수해 지름길에 쓸 수 있다. 반복 플레이의 차이는 무작위 사고 수보다 팀이 고른 순서·경로·적재 구성에서 만든다.

## 대상

친구와 대화하며 협동하고 가벼운 물리 사고를 즐기는 플레이어와 방송인. 1인도 안전 경로로 진행 가능하고 2–4인은 분업과 전달로 다른 해법을 만든다. 글로벌 게임 문구는 영어 원문과 한국어 대응본으로 관리한다. Steam은 목표이며 등록·초대 연동·출시 완료를 뜻하지 않는다.

## Core Loop와 첫 플레이

순간: 화물 예고 관찰 → 잡기·놓기·던지기·받기 → 반응 → 회수·연계.
배송: 목적지 확인 → 순서·경로 합의 → 운반·시설 활용 → 수령 확인 → 보상 확보.
근무: 계약·적재 선택 → 기본 배송 → 선택적 추가 의뢰 또는 귀환 → 정산 → 다음 장비 구성. 완성 게임의 30–40분은 목표이며 걷기로 시간을 채우지 않는다.
대표 상황: 재채기 화물을 먼저 써 종이 골목을 열고, 튕긴 다른 화물을 동료가 회수한다. 열린 길로 점프 화물을 운반한 뒤 옥상에서는 던져 받기 또는 계단을 고른다. 납품이 끝나면 추가 배송과 귀환을 논의한다.
다음 Unity 검증 순서: 일반 화물 집기→목적지 수령→1회 지급→트럭 귀환부터 연결한다. 이어 재채기 화물과 안전/선택 경로를 추가하고 2인 협동에서 전달·사고 수습을 확인한다. 이후 나머지 계약·장비·랜덤 구역을 확장한다. 첫 샘플에 전체 성장 시스템을 넣지 않는다.

## 검증 기준

자동 검사: 오배송·중복 수령·재접속·저장 재실행의 중복 지급 없음, 화물 복구 후 계약 유지, 필수 경로 통과, 선택적 추가 의뢰 거절 후 정상 귀환.
사람 플레이: 설명 없이 목적지와 집기 실패 이유를 이해하는지, 같은 화물을 다른 방법으로 쓰는지, 누가 왜 경로·장비를 골랐는지 기록한다. 의미 없는 이동·대기 20초 초과 구간은 원인을 분석한다. 사고의 원인을 설명하고 계속 배송할 수 있어야 한다.
먼저 솔로와 2인, 이후 3–4인으로 검사한다. 로컬 다중 프로세스·별도 PC·외부 네트워크·사람 재미를 구분해 보고한다. 수치는 실험 관찰 기준이며 출시 합격선이 아니다.

## 위험과 범위 경계

주요 위험은 운반의 반복 노동화, 카메라·벽 충돌 스트레스, 한 명에게 일이 몰림, 화물 특성이 필수 열쇠가 되어 진행 불능, 조기 경제 소진, 물리 온라인 비용이다. 짧은 고정 배송 루프에서 먼저 관찰한다.
미확정: 충격 손상 임계값, 최종 이동·수레 속도, 보너스 가격 균형, 실제 근무 시간, Unity 네트워크 기술, 최종 아트 성능. 이전 Godot 수치·검사 결과를 Unity 완료 근거로 쓰지 않는다. 이 문서 작업은 코드 변경이나 개발 에이전트 실행 지시를 전송하지 않는다.
